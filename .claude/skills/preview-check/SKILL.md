# 画面を見て確かめる

このリポジトリで見た目の絡む変更をしたら、**出す前に必ず1回は自分の目で見る。**

見ずに出して間違えた実例がある。図の番号を「左から8文字ぶん」のように手で位置指定していて、
番号が罫の真ん中から外れていた。ユーザーに指摘されるまで気づかなかった。

## 先に考える: そもそも見なくてよい形にできないか

**見ないと正しいか分からない書き方を避けるのが第一。** 見るのはその次である。

- 手で座標や字数を計算して書いた → 必ず見る必要が出る。**やめる**
- 要素の中に入れて中央寄せ・`gap`・グリッドで並べた → ずれる余地が無い
- 部品がビルド時に落ちるようにした（`<Keys>` `<Figure>`）→ 間違いは検査で止まる

## 手順

### 1. 開発サーバを確かめる

```
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:4410/api/health
```

動いていなければ入れ直す。**`npm run dev` は使えない**（Astro v7 が30秒で見切りをつけるが、
このリポジトリは初回起動に40秒以上かかる）。

```
ASTRO_DEV_BACKGROUND=1 npx astro dev --port 4410
```

バックグラウンドで起動し、ログに `localhost:` が出るまで待つ。
すでに動いていると `Another astro dev server is already running.` で落ちるが、
**その場合はもう動いているので、そのまま使ってよい。**

### 2. 新しいタブで開く

`tabs_create` してから `navigate` する。

**ローカルのファイル（`file://`）を開いたタブは固定され、スクリーンショットを撮れない。**
静的な HTML を見たいときは `public/` に置いて開発サーバ経由で配る。見終わったら消す。

### 3. 撮る

```
computer { action: "screenshot", scale: 1, tabId: "tab-N" }
```

見たい場所は先に `javascript_tool` で `scrollIntoView({block:'center'})` してから撮る。

### 4. 片付ける

`resize_window` で幅を変えたら `preset: "desktop"` で戻す。`public/` に置いた見本は消す。

## 詰まったときの見分け方

| 症状 | 原因と手 |
|---|---|
| スクリーンショットが「描画が終わらない」で失敗する | ウィンドウが他の窓の後ろにある。**ユーザーに前に出してもらう。** それまでは `read_page` と `javascript_tool` で確かめる |
| `window.innerHeight` が 0、スクロールも `IntersectionObserver` も動かない | 同じ原因。描画が止まっている。**この状態で「動かないから実装が悪い」と判断しない** |
| `Tab ... is pinned to a local file preview` | `file://` のタブ。新しいタブを作るか、開発サーバ経由で配る |
| ページが縦に細長く潰れて読めない | `resize_window` で幅を指定していない。`{ preset: "desktop" }` か `{ width: 900, height: 1100 }` |
| 教材の画面に小窓が出て中身が隠れる | 前の検証のログインが残っている。`localStorage.removeItem('kit-lesson-progress-v1')` と `POST /api/logout` をしてから再読み込み |

## 見るときに確かめること

- **文字と罫がそろっているか。** 等幅の図は `ch` 単位で引いているので、書体が落ちるとずれる
- **狭い幅で崩れないか。** `resize_window` の `preset: "mobile"` で1回見る
- **前の検証の状態が残っていないか。** ログイン・進度・小窓
