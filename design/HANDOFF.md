## 4. 何度も起きたこと

### 下限は、足りない節を厚くしない。埋めやすい節を厚くする

**6回起きた。** 下限を置くたびに起きると思ってよい。

| 置いた下限 | 生まれたもの |
|---|---|
| 本文の字数 | 内容として要らない一文 |
| 節ごとの課題4問 | 用語を選ばせるだけの問いが3つ（第0.5節） |
| 「説明」の字数（表を数えないまま） | 表と同じことを地の文でも言う段落 |
| 例題を必ず置く | すぐ上の `<Run>` を書き写すだけの課題が16節ぶん |
| 「変える」課題を置く | 答えが問題文に書いてある課題が18問 |
| 章の合計の「組む」の数 | 置けない節のぶんを別の節が2問持ち、2問目が1問目に含まれていた |
| 「説明」250字（第8章・練習編・第9章で3回続けて足された） | 2026-09-24 に100字へ下げた |

いまの下限は**節ごとに「組む」が1問**だけ。置けない節は frontmatter の `nobuild` に理由を書く。
**関係のない課題を足すより、理由を残すほうがよい。**

### 枠を外すと、一段下が同じ形で埋まる

1. 例題を廃した → **「変える」課題**が「値を1つ変えて実行」になっていた（10問）
2. それを直した → 第4章で**地の文に数を書く**形になっていた（4問）。検査19 はバッククォートの中しか見ない
3. 「組む」課題にも出ていた → 第5.3節の課題がすぐ上の `<Run>` と関数名・引数・既定値まで同じで、
   **書き写せば通った**（2026-09-23 に差し替え）。`build:tests` は模範解答と `<Run>` の**文字**しか比べて
   いなかった。いまは `<Run>` を実際に課題のテストに当てて落とす（118問で誤報0件を確かめてから入れた）

**外した枠のすぐ下を、毎回見にいくこと。**

### 機械検査は形しか見ない。判断は人が持つ

壊れやすい検査を足しかけて、2回やめた。**やめた判断も残す。**

- **地の文の数まで検査19 で見る案**: 実データで測ると7件中3件が誤報。
  「`平均71.7点 基準80点` と表示されるように」の 80 は**出力の指定**で、正しい書き方だった。
  出力を言っているのか、書き換える中身を言っているのかは、日本語の動詞を見ないと分からない。**やめた**
- **カタカナ語を用語集と突き合わせる検査案**: 28節で本物は2件。
  「字下げ（インデント）」は正しい併記、「フォルダー」は Windows の画面の文字の引用。
  許可リスト＋例外2種が要るので**やめた**。一度きりの調べとして `spec/10` 第8章に手順だけ残した

**検査を足すかどうかは、実データで誤報を数えてから決める。**

## 7. 環境の罠

### 開発サーバ

`npm run dev` は使えない（Astro v7 が30秒で見切るが、このリポジトリは初回起動に40秒以上かかる）。

```
ASTRO_DEV_BACKGROUND=1 npx astro dev --port 4410
```

`Another astro dev server is already running.` で落ちたら、**もう動いているのでそのまま使ってよい。**

### シェルがバックスラッシュとバッククォートを食う

**これに5回はまった。** `node -e "..."` の中や heredoc に、正規表現やコード片を直接書くと壊れる。

- 症状: 正規表現のバックスラッシュが1つぶん減る。バッククォートで囲んだ部分は丸ごと消える
- 手1: 置き換える文章は `cat > file <<'XEOF'` で**別のファイルに書き**、node で読んで差し込む
- 手2: 正規表現は `String.fromCharCode(92)` でバックスラッシュを組み立てる
- **書いたあと必ず読み返して確かめる。** 黙って壊れる

### CRLF

Windows の git が作業ファイルを CRLF で書き出す。**読む側で必ず改行を LF にそろえる。**
これで3回事故った。いちばんひどいのは検査16・18 が**黙って何も見ない状態**になっていたもの。

### Browser ペイン

- `viewport 0x0` / `window.innerHeight === 0` は**ウィンドウが他の窓の後ろにある**という意味。
  **この状態で「動かないから実装が悪い」と判断しない。** 利用者に前に出してもらう
- `file://` を開いたタブは固定されスクリーンショットを撮れない。`public/` に置いて開発サーバ経由で配る
- 詳しくは `.claude/skills/preview-check/SKILL.md`

### 画面の写真を教材に入れる

- 元の写真は利用者の `機械学習研究会/教材の写真/`。**個人のフォルダ名などが写っている。リポジトリに入れない**
- 加工は、開発サーバの `public/_shots/` に一時的に置き、Browser ペインの canvas で切り抜き・塗りつぶし・朱の枠を描き、手元だけで動かす小さな受け取り口（node の http、127.0.0.1）に POST して `public/images/<章>/` に保存した。**終わったら `public/_shots/` を消す**
- 塗りつぶしの色は写真の中から拾う（エクスプローラーの暗い地は `rgb(25,25,25)`）

### 出すとき

- `npm run build` は `check:lessons` から始まる。**落ちている状態で push しない**（本番のビルドが落ちる）
- 根の `wrangler.jsonc` に `main` と `assets` を書かない。配るのは `wrangler deploy -c dist/server/wrangler.json`
- **`SESSION_SECRET` の中身を出力しない。** `/api/health` は有無だけを返す

## 8. もう決まっていること（蒸し返さない）

`DECISIONS.md` に全部あるが、教材を書くときに効くものだけ。

- **例題（`kind="trace"`）は廃止。** 例は `<Run>` である。課題の型は「変える」と「組む」の2つだけ
- **「よくある間違い」は任意。** 既定で閉じておく。躓く先が見えているときだけ置く

- **意図から設計する。** 「練習問題の欄があるから書く」ではなく「理解を確かめたいから置く」

  ゲストには質問の欄を出さない
- 表示名は**学籍番号**を薦める。集めるのは表示名だけ（メールも本名も集めない）
- 招待コードは `MLAB-2026`（内部）と `MLAB-OPEN`（外部）。外部は登録数に上限がある
- パスワードを外し続けると待ち時間が伸びる。模範解答は入っている人だけに出す
