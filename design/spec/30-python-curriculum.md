## 3. 第0部 第0章 パソコンの操作

レベル0で必修、レベル1で任意、レベル2は確認テストで飛ばせる。
**説明より練習を主にする。** Python は使わない。入力された文字列を直接判定する。

### 3.1 本文から Python を締め出す（2026-09-12 決定）

**この章の本文に、Python・コード・プログラムという語を出さない。**`print` のようなコードの断片も出さない。

当初の4節は、4節すべての「困る例」が「あとで Python をやるから」という理由で成立していた。
第0.1節の最初の1文が「第1章では `print("A")` のような1行を打ちます」だった。**教材全体の最初の
文である。**読者はまだ Python も第1章も知らない。困る根拠を、読者がまだ経験していない未来の
出来事に置いている。第2.1節の「困る例」の書き方（読者がいま持っている困りごとから書く）に反する。

困る例は、**パソコンを使っていて実際に起きること**から書く。全角の数字で検索しても見つからない、
ファイル名に打った記号が思ったものと違う、長い文を打ち直すのが大変、保存したものが見つからない。

Python への接続は、各節の最後の「つながり」だけで軽く触れる。それが「つながり」の役目である。

### 3.2 節

| 節 | 内容 | いちばん上の課題 |
|---|---|---|
| 0.1 | **この教材の使い方**。採点する・1問ずつ出ること・右レール | 画面の部品の役割を選ぶ |
| 0.2 | 半角と全角、日本語入力の切り替え | 指定された記号を全部半角で打つ |

| 0.4 | コピー・貼り付け・選択・取り消し（`Ctrl+C` `V` `A` `Z`） | 貼り付けを使って文を組み替える |

**0.1 を足した理由。**`00-overview.md` 第2.2節は第0部の内容を「パソコンの操作、**この教材の使い方**」と

教える場所がないまま第0.2節が始まっていた。**画面の使い方は、パソコンの操作より前に要る。**

**0.4 は操作を本当に使わせる。**当初の節は、課題がどれも最終的な文字列の一致だけを見ていたため、
`Ctrl+C` を一度も使わずベタ打ちしても全問通った。**節の題が約束した技能を何も検証していない。**
貼り付けが起きたかどうかを記録して判定する（`20-platform.md` 第11.7節）。取り消しは記録が
難しいので、選ぶ練習で確かめる。

**0.5 はエクスプローラーの定義と開き方から始める。**当初の節は「自分のパソコンでエクスプローラーを
開き」といきなり書いていた。この語はそこまで一度も出てこない。開き方も書いていない。
**想定読者はこの語を聞いたことがない人なので、ここが唯一、完全に手が止まる場所だった。**

0.1 と 0.5 と 0.6 は画面の操作なので、判定は自己申告＋選ぶ練習にする。

**0.5 と 0.6 に分けた理由**（2026-09-13）。1節にまとめていたとき、ファイルとフォルダの違いを
知っている前提で拡張子の話に入っていた。**聞いたことはあるが違いを言えない人**が、いきなり

ファイルとは何か・フォルダとは何か・フォルダの中にフォルダが入ること・ディレクトリはフォルダの

### 第4章 繰り返す

| 節 | 困る例 | 新しい概念 | 組む課題 |
|---|---|---|---|
| 4.1 | 1から10まで出すのに10行書くことになる | for文と `range()` | 1から n までの合計を出す（`sum` を使わない） |
| 4.2 | 値が10個あると変数を10個作ることになる | リスト | リストの中で最大の値を出す（`max` を使わない） |
| 4.3 | リストの何番目かを指定して取り出したい | 添字と `len()` | リストを逆順に出す（`reversed` とスライスを使わない） |
| 4.4 | 後から値を足したり取り除いたりできない | `append()` と `remove()` | 条件に合う要素だけを集めて出す |
| 4.5 | 終わりが決まっていない繰り返しを書けない | while文 | 入力が `終わり` になるまで受け取り続けて合計を出す |

**「返す」をやめて「出す」にした**（2026-09-21）。4.2〜4.4 は当初「◯◯を返す」と書いていたが、**「返す」は関数の語である。** 関数を書けるのは第5章からなので、この書き方のままでは書き手が `def` と `return` に手を伸ばす。第1.1節が `print` しか教えていないのに `input()` を使う課題を置いてしまったのと同じ形である。

**4.1 と 4.3 に禁じ手を足した。** 「1から n までの合計」は `sum(range(1, n + 1))` で1行で通り、for文を一度も書かずに済む。「逆順」も `[::-1]` で通る（スライスは第7.4節）。どちらも第3.6節（組む課題はその節の道具を要求する）に反するので、`forbid` で塞ぐ。

### 第5章 まとめて名前を付ける

| 節 | 困る例 | 新しい概念 | 組む課題 |
|---|---|---|---|
| 5.1 | 同じ計算を3か所に書くと、直すとき3か所直すことになる | 関数の定義と呼び出し | 2つの数の平均を**表示する**関数 |
| 5.2 | 関数の中で計算した値を外で使えない | `return` | 3つの数のうち最大を返す関数（`max` を使わない） |
| 5.3 | ほとんど10%の税率を、呼び出すたびに書くことになる | 既定値 | 税率を変えられる税込価格の関数 |
| 5.4 | 渡す値が増えると順番を間違える。入れ替えてもエラーにならない | 名前を書いて渡す引数 | 引数の多い関数を、名前を書いて呼ぶ |
| 5.5 | 関数の中で付けた名前が外から見えない | 有効範囲（scope） | 置かない。出力を当てて直す「変える」で確かめる |
| 5.6 | **通し課題**: 合計と平均を出す部分を関数にする | （新概念なし） | 章末課題 |

**5.1 を「返す」から「表示する」に変えた**（2026-09-21）。`return` を教えるのは 5.2 である。「平均を返す関数」は `return` を使わないと書けないので、5.1 の道具だけでは成立しない。5.1 は「まとまりに名前を付けて、何度でも呼べる」ことだけを教え、中で `print` する。5.2 で「値を持ち帰る」を足す。**この2段はこの章の骨なので、混ぜない。**
**5.3 と 5.4 に分けた**（2026-09-22 決定、2026-09-23 反映）。もともと 5.3 は「引数と既定値」1節で、困る例は「渡す値の順番を間違える」だった。**既定値はその困る例の答えにならない。** 順番の問題を解くのは、呼び出す側で名前を書くほうである。

分けた理由はもう1つある。第7.2節が軸を扱い、`np.mean(scores, axis=0)` と書く。**これは名前を書いて渡す引数である。** どこでも教えないまま第7章で使うことになっていた。台帳の検査16 は `def` の行だけを見るので、呼び出し側の `axis=0` は先取りとして引っかからない。**機械では見つからない抜けだった。**

置き方は「ついでに触れる」ではなく1節を立てる。定義側の `=`（既定値）と呼び出し側の `=`（名前を書いて渡す）は同じ記法の裏表だが、**使う場面も解く問題も別**なので、節を分けて、それぞれの困る例から入る。

**5.5 の課題を差し替えた**（2026-09-21）。当初は「与えられたリストの標準偏差を返す関数」だったが、2つ問題がある。

- **有効範囲を使わなくても通る。** ループと `math.sqrt()` で書けてしまい、第3.6節（その節の道具を要求する）に反する
- 「標準偏差」はここまでに出てこない統計の語である（第11.1節 前提の抜け）

有効範囲は「使う道具」ではなく「知らないと間違える決まり」なので、**組む課題ではなく、出力を当てて直す形**にする（frontmatter に `nobuild` を書く）。同じ名前の変数が関数の中と外にあるコードを読ませ、何が出るかを答えさせてから直させる。

### 第6章 エラーを読む

**既存の Colab 教材の第6回を土台にする。** ただし「壊れたコードを直す」練習は第1〜5章の各節にも分散して置いてあり、この章はその**総まとめと、エラーメッセージの読み方の体系化**を担う。

| 節 | 困る例 | 新しい概念 | 組む課題 |
|---|---|---|---|
| 6.1 | 赤い文字がたくさん出て、どこを見ればいいか分からない | エラーメッセージの読み方（最終行と行番号） | **置かない**（下の理由） |
| 6.2 | 打ち間違いなのに動かない理由が分からない | SyntaxError と NameError | 綴り・全角・かっこ・コロンの4つが壊れたコードを直す |
| 6.3 | 型が違うと言われるが意味が分からない | TypeError と ValueError | `input()` の値を数として使うところが壊れたコードを直す |
| 6.4 | エラーは出ないが答えが違う | 思いどおりに動かないとき（論理の誤り） | 条件の向き・添字の固定・`return` の忘れを直す |
| 6.5 | **通し課題**: 壊れた点数表を直す（8か所） | （新概念なし） | 章末課題。壊れた点数表を直す |

**6.1 に組む課題を置かない**（2026-09-21）。当初は「5つのエラーから原因の行を答える」としていたが、**それを出す仕組みが無い。** 課題の型は「変える」と「組む」の2つで、「行番号を答える」はどちらにも当たらない（「打つ」「選ぶ」は第0章だけ。第11.5節）。

型を増やす手もあるが、増やさない。6.1 が教えるのは**読み方**であって、書く道具ではない。読み方の確かめは「変える」で足りる。壊れたコードとエラーメッセージを見せ、最終行と行番号だけを手がかりに直させれば、読めたかどうかは直せたかどうかで分かる。

**6.1 は frontmatter の `nobuild` に理由を書く**（検査15）。「組む」の下限は章の合計ではなく節ごとに見る（第3.8節）。

ここは当初「6.5 に2問置いて章として5問にする」と書いていた。**合計で足りるなら埋め合わせてよい、という書き方だった。** 第5章で実際にそれが起き、第5.5節の2問目が1問目を含むものになった。下限を節ごとに変えたので、6.5 は1問でよい。

第6章はこの教材で唯一、**新しい道具を1つも増やさない章**である。第1〜5章で使った道具のまま、壊れたものを直すことだけをする。だから「組む」より「変える」が主になるのは、この章の性質どおりである。
