# 教材仕様 00: 全体像

この文書は、何を作るかの最上位の定義。ここに書かれた数字と構造は、下位の仕様書と実装が従う前提とする。

## この仕様書の育て方

作りながら直す。直すたびに、**その指摘がどちらなのかを必ず判定する。**

| 判定 | 例 | 扱い |
|---|---|---|
| **その箇所だけの話** | この節の例が分かりにくい、この図が小さい | 直して終わり。仕様書には書かない |
| **全体の作り方の基準になる話** | 例は必ず失敗する場合を含める、図の中の数字は本文と同じ大きさにする | **仕様書に足す。** 以降の全ての節・実装がこれに従う |

判定に迷ったら「同じ指摘が他の章でも起こりうるか」を考える。起こりうるなら基準である。

基準を足したときは、**すでに書いた分が新しい基準を満たしているかを確認する**。満たしていない箇所は、まとめて直す回を設ける。

### 実装の分担

| 種類 | 担当 |
|---|---|
| 仕様を決める、全体の構成、検証、指摘の判定 | Claude（本体） |
| 重い実装（土台、実行環境、採点、データベース、画面の構造） | Opus のサブエージェント |
| 本文・課題の執筆、既存内容の規約への適合、量の多い単純作業 | Sonnet のサブエージェント |

## 1. 誰のための教材か

### 1.1 想定する学習者

京都工芸繊維大学の学生で、次のすべてに当てはまる人を**基準の読者**とする。

- 情報系の学科ではない（例: 生物系、化学系、建築系）
- 大学1年。高校数学（数I・数II・数B程度）は履修しているが、大学の微分積分・線形代数はまだ
- 機械学習について知っているのは、ニュースで見た程度
- プログラミングの経験がない。パソコンは日常的に使うが、ファイルの拡張子やフォルダ階層は意識したことがない

本文はこの読者に向けて書く。これより詳しい人には飛ばす手段を用意するが、**本文の水準をこの読者より上げない**。

### 1.2 到達目標

一年を終えた時点で、次ができる状態を目標とする。

1. Python で、数十行規模のプログラムを仕様から書ける
2. numpy で配列の計算ができ、行列積が何を計算しているか説明できる
3. 与えられたデータに対して、回帰と分類のどちらの問題かを判断し、適切な損失関数を選べる
4. 全結合ニューラルネットワークを PyTorch で定義し、学習させ、学習曲線を読んで次の手を決められる
5. 連鎖律から逆伝播の式を導ける
6. なぜ ReLU が使われるのか、シグモイドを深く重ねると何が起きるのかを、式と数値の両方で説明できる
7. 過学習を検出し、正則化・データ分割・早期終了で対処できる
8. CNN と Attention が何を計算しているかを、具体的な数値例で追える

「大学3年の情報学生程度」の具体化がこの8項目。**この8項目に寄与しない内容は書かない。**

### 1.3 レベル別の入り口

学習開始時に3段階から選ぶ。**本文は共通。変わるのは入り口と補助の量だけ。**

| レベル | 名前 | 該当する人 | 変わること |
|---|---|---|---|
| 0 | はじめて | プログラミング未経験。ファイル・フォルダ・拡張子を意識したことがない | 第0章（パソコンの操作）が必修になる。本文中の**操作の補足**が開いた状態で表示される |
| 1 | 標準 | パソコンの一般的な操作はできる。プログラミングは未経験 | 第0章は任意。操作の補足は閉じた状態で表示される |
| 2 | 経験あり | 何らかの言語を少しでも書いたことがある | 第0章と第1〜2章に「確認テスト」が出る。合格すれば飛ばせる。操作の補足は表示されない |

レベルはいつでも変更できる。飛ばした章は「未読」として記録され、あとから読める。

**操作の補足に書いてよいのは操作だけ**（どのキーを押すか、どこをクリックするか、画面のどこに何が出るか）。概念の説明を補足に逃がしてはいけない。概念は全員が読む本文に書く。

## 2. 全体の構成

### 2.1 単位

- **1章 = 勉強会1回分。** 対面90分＋自宅での宿題60〜90分を想定する
- 1章は**4〜7節**からなる
- 1節は**8〜15分**。節の中身の規定は `10-lesson-and-writing.md`
- 全**31章**。週1回で約8か月、余裕を見て一年

### 2.2 部と章

| 部 | 章数 | 内容 | 周 |
|---|---|---|---|
| 第0部 準備 | 1 | パソコンの操作、この教材の使い方 | — |
| 第1部 Python | 7 | 変数から関数、エラーの読み方まで。サイト内で実行 | — |
| 第2部 道具 | 4 | numpy、ベクトルと行列、変化率と傾き、確率の初歩 | — |
| 第3部 機械学習 1周目 | 4 | 予測とは何か、回帰、分類、評価 | 1周目 |
| 第4部 深層学習 1周目 | 4 | ニューロン、多層、学習が回るまで、うまくいかない例 | 1周目 |
| 第5部 自分の環境 | 2 | uv での環境構築、PyTorch の導入と書き換え | — |
| 第6部 深層学習 2周目 | 5 | 連鎖律と逆伝播、活性化の選択、初期化、最適化、勾配消失と正則化 | 2周目 |
| 第7部 応用 | 3 | CNN、系列、Attention と Transformer | — |
| 第8部 総合 | 1 | 通しで1つ作る | — |

### 2.3 2周構造の約束

第3・4部（1周目）と第6部（2周目）は、**同じ話題を扱う**。1周目では「何が起きているか」を数値と図で見せ、式は結果だけ示す。2周目で同じ話題を式から導く。

1周目で許される書き方の例:

> 誤差を出力側から入力側へ順に伝えていくと、各重みをどちらに動かせばよいかが分かります。これを誤差逆伝播といいます。ここでは数字が逆向きに流れることだけ押さえてください。式は第6部で導きます。

2周目では同じ話題を、連鎖律から `∂L/∂w` を導いて書く。

**1周目で「あとで詳しくやる」と書いた項目は、2周目のどの章で回収するかを必ず明記する。** 回収先のない先送りは書いてはいけない。

### 2.4 Python と機械学習の並べ方

第1部でまとめて扱うのは、**機械学習と無関係に必要な基礎**だけ。

| 第1部で扱う | 必要になったところで差し込む |
|---|---|
| 変数、型、演算子、if、for、while、リスト、関数、エラーの読み方 | スライス（numpy の章）、二次元リスト（行列の章）、内包表記（データ整形の章）、クラス（PyTorch の `nn.Module` の章）、`with` 文（ファイル読み込みの章） |

差し込む側は、**その節で使う直前に、その用途に必要な分だけ**を教える。文法の網羅は目的にしない。

## 3. 第1期に作る範囲

一年分を一度には作れない。第1期の完成条件を次のとおり定める。

### 3.1 土台（全部作る）

1. レベル選択と、レベルに応じた本文の出し分け
2. ログインと進度の保存（`20-platform.md`）
3. サイト内での Python 実行（Pyodide）
4. 演習の自動採点と、よくある間違いへの応答
5. 運営の画面（誰がどこまで／どこで詰まっているか／正答率／提出コード／コメント）

### 3.2 中身

- 第0章（パソコンの操作）
- 第1部の第1〜3章

**第1期は分量より作り込みを優先する。** 最初に触るメンバーがここで脱落すると、以降の内容が何章あっても届かない。

### 3.3 第1期の受け入れ条件

- レベル0を選んだ未経験者が、第0章から第3章までを補助なしで完走できる
- 演習の「組む」問題で、模範解答と違う書き方をしても正しければ通る
- 誤答時に、何が違うかが分かる応答が返る（単なる不正解表示では不合格）
- 運営の画面から、誰がどの節で止まっているかが分かる

## 5. 旧サンドボックスの扱い

`src/sandbox/` のうち、

- **残す**: `engine/`（順伝播・逆伝播・SGD/Momentum/Adam・初期化・種付き乱数）。数値微分との照合で検証済み。第4部・第6部の実験がこれを使う

- **捨てる**: `stages.ts` のゲーム進行（ステージ・クリア・締め付け・出題ティッカー）

codex が作った `src/course/` は未監修のため、仕様確定後に作り直す。`.openai/hosting.json` は OpenAI 側のホスティング設定で、本番（Cloudflare）とは無関係。
