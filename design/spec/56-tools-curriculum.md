### C. Titanic のデータをサイトにどう置くか

**いまどうしているか**: タイタニック演習は datasciencedojo の公開 CSV（Kaggle の train.csv と同じ891人）から、**選んだ20〜40人の値を節のコードに直接書いている**。規則の正解率ランキングのテストデータ20人も `src/lesson/rule-board-data.ts`（ブラウザに配る）に書いている。CSV のファイルそのものはリポジトリに無い。リポジトリは公開なので、書いた行は GitHub から誰でも読める。**再配布してよいかを調べた記録は、仕様書・DECISIONS に見当たらない。** Kaggle の Titanic のデータの利用条件は、このセッションでは確かめていない。

**ファイルを読ませる仕組みは、いまは無い。** 実行は毎回 `<Run>`・`<Exercise>` のコードだけを Pyodide に渡し、ファイルは渡さない（`runner.ts`・`pyodide.worker.ts`）。`pd.read_csv("train.csv")` を動かすには、次のどれかが要る:

1. **ファイルを添える仕組みを作る**: 置き場所のファイルを、実行の前に Pyodide の中のファイルとして書く。ブラウザ（worker）とビルド時の期待値づくり（`scripts/pyodide-node.mjs`）の両方に要る。Node の Pyodide で、`py.FS.writeFile` で書いたファイルを `pd.read_csv` が読めることを確かめた（このセッションでは仕組みは作っていない）。メンバーだけにするなら、`public/` ではなくスライドと同じようにサーバから渡す
2. 仕組みを作らず、コードの中に CSV の文字を書いて `io.StringIO` で読ませる（Node で動くことを確かめた）。行が少なければ動くが、891人ぶんはコード欄に入れられない。`io.StringIO` と3重の引用符が新しい書き方になり、「ファイルを読む」の練習にならない
3. `pd.read_csv("https://…")` で外から読む。Pyodide のブラウザで動くかは確かめていない。ビルド時の期待値づくりが外のサイトに頼ることになる

データの形の案:

- 案3: サイトには置かず、メンバーが Kaggle から各自で落とす。サイトのブラウザ実行では読めないので、P から Colab か Kaggle Notebook でやることになる（自動の採点が使えなくなる）

### F. 1回の後半に何節を当てるか

- **案1（おすすめ）: P・S は1回2節（各10〜15分）、T は1回1節。** 1節の新しい書き方が3つまでに収まる。2節目は1節目のコードの続きなので、段差が小さい。進め方は1節目の `<Facilitate>` に書く
- 案2: どの回も1回1節（タイタニック演習と同じ）。1節の新しい書き方が P1 で4〜5個、S1 で4個になる。節の数が半分になり、プロジェクトの教材の並びが短くなる

### G. 1行で複数の変数に入れる `a, b = …` を教えるか

`train_test_split` の普通の書き方 `X_train, X_test, y_train, y_test = train_test_split(...)` はこれを使う。Kaggle の解説・Notebook はほぼこの形。

- **案1（おすすめ）: S3 で教える。** 台帳の `python-99-unpack` の `in` を S3 に移す。理由: 1月の本番で見るコードがこの形。教えずに避けると、外のコードが読めない
- 案2: 教えない。`parts = train_test_split(...)` として `parts[0]`〜`parts[3]` で取り出す。新しい書き方は増えないが、どれが何番目かを覚えることになり、外のコードとも違う
