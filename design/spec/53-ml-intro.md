# 機械学習の入口（2026-09-26 決定）

## 1. なぜ作るか

今週の演習（第19章）は前期にやった Python の復習で、メンバーは「また？」となる。利用者の判断: **復習と、先へ進める分の二本立て**にする。進める分は**機械学習の入口**（利用者の選択、案A）。復習した書き方をその週のうちに機械学習に使い、「何のための復習か」を見せる。題材は Titanic の乗客の記録（12月の Titanic・1月と3月の Kaggle 月例コンペへの下準備）。9/29 から始める（利用者の選択）。

## 2. 置き場所と呼び方

- 新しい部「**機械学習の入口**」を第1部 Python のすぐあと（練習編2のあと）に置く（利用者の選択）
- 節は「**入口1**」〜「**入口4**」と呼ぶ（練習編の「練習1-2」と同じ呼び方の仕組み）。章の番号（第N章）は付けない
- 教材の公開（第20章）の対象。最初は準備中

## 3. 節ごとの中身

**各節で使ってよい書き方は、その週に復習した範囲まで**（台帳の検査16より厳しい、書き手の決まり）。データは Titanic の乗客の記録（891人。datasciencedojo の公開 CSV と同じ数）。

| 節 | 集まり | 使う書き方 | 分かってほしいこと |

## 4. 集まりの進め方メモ（運営だけ）

利用者の相談「集まったときに私ができることはあるのか。これ読んでくださいでいいのか」。答え: 運営の役目は教えることではなく、**問いかけて・予想させて・比べさせる**こと。進める分の30分は「最初の3分で問いかけて予想を並べる → 20分各自で読んで解く → 最後の7分で予想と答えを比べ、次の週につなぐ問いを1つ投げる」。

各節の先頭に、**運営にだけ見える「集まりの進め方」**を置く（利用者の選択）。中身:

1. 最初の問いかけ（1〜2問。数字で答えられるもの。例:「生き残ったのは何割だと思う？」）
2. 答え合わせで言うこと（予想と実際の数、ひとことの要点）
3. 次につなげる問い（答えは言わず、次の節で確かめる。例:「正解率が90%なら良い予測と言える？」）
4. よく詰まるところ

メンバーには中身を1文字も送らない（第13.2節と同じ。節のページはサーバで組み立てているので、運営でなければ出さない）。

## 5. 実装で決めたこと（2026-09-26）

- **章のフォルダは `src/content/lessons/08q-mlintro/`**（`chapter: 08q-mlintro`）。名前の並びで練習編2のあと・第9章の前に来る（`08p-practice2` < `08q-mlintro` < `09-matrix`）。道具の台帳（検査16）と語の初出（検査18）もこの並びで見る。章の名前は `scripts/parts.mjs` の `INTRO_CHAPTER` に1つだけ置く
- **部**: `scripts/parts.mjs` の `PARTS` で第1部のすぐあとに「機械学習の入口」。学習の一覧の部の段は章の数ではなく「4節」と添える
- **呼び方**: `src/lesson/chapters.ts` の `practiceSectionLabel`（練習編の「練習1-2」と同じ関数）と `scripts/section-refs.mjs` の `sectionLabel` が「入口N」を返す。左の欄・学習の一覧・節の上（「入口1 ・ この部の 1 / 4 節」）・「続きから」・用語の検索の札・運営の画面・マイページの進み具合がこれを使う
- **節への参照**: 章の番号が無いので「第N章M節」では書けない。本文・ヒントなどに「入口2」と書くとその節へのリンクになる（`remark-section-links.mjs`・`Inline`。行き先は `section-refs.json` のキー `入口2`）。検査20 は行き先の無い「入口N」も落とす
- **集まりの進め方**: `<Facilitate>…</Facilitate>` を frontmatter のすぐあとに置く。節のページが運営・管理者にだけ `Facilitate.astro`（琥珀の枠。「運営だけに見えています」の帯と同じ色）を渡し、それ以外の人には中身を描かない `FacilitateHidden.astro` を渡す。運営でない人の HTML には中身が1文字も入らない（curl で確かめた）。検査と検索の索引からは `scripts/parse-lesson.mjs` の `withoutFacilitate` で外す
- **用語**: 「正解率」「訓練データ」「テストデータ」「過学習」の初出を `08q-mlintro` に移し、「ベースライン」を足した。「予測」「基準」は用語集に足していない（第7章1節と第2章が地の文で普通の言葉として使っており、初出を入口に置くと検査18 が落ちるため）
- **データ**: datasciencedojo の公開 CSV（891人）。入口1 は性別・等級ごとの人数だけ。入口2・3 は年齢が整数で分かっている乗客の並び（PassengerId 213〜262 の40人。入口2 はその先頭20人）、入口4 は別の40人（PassengerId 819〜871）。数はすべて Python で計算してから書いた

## 7. 実装で決めたこと（2026-09-27。第6節のメンバーだけ・予想ボード）

規則の正解率ランキング（案C の2）はまだ作っていない。

**メンバーだけにする**

- **どの章か**: `scripts/parts.mjs` の `MEMBERS_ONLY_CHAPTERS`（いまは `08q-mlintro` だけ）。判定は `src/lesson/chapters.ts` の `isMembersOnlyChapter`。メンバーは `src/server/member.ts` の `isMember`（第13.1節）
- **節のページ**: 公開済みでも、メンバーでない人には「このページはプロジェクトのメンバー向けです。学習の一覧へ」の1段落だけを返し、本文・判定データ・用語の欄を1文字も送らない（curl で確かめた）。準備中の章のメンバーには、これまでどおり「この章は準備中です。」。運営・管理者は準備中でも見られる。メンバーだけの章は `cache-control: no-store`。練習編2の最後の節の「次の章へ 機械学習の入口 →」も、メンバーでない人には「学習の一覧へ →」にした
- **学習の一覧（事前生成）**: 部の段を `hidden` で置き、節の行は**1つも書かない**（題が静的な HTML に入らない）。`/api/lessons/status` が、メンバーにだけ `membersSections`（行を組むのに要る分: 呼び方・題・目安・課題の id）を返し、`src/lesson/learn-list.ts` が行を作って段を出す。行のスコープ付きスタイル（`data-astro-cid-*`）は `<ol>` から写す。右上からログイン・ログアウトしてメンバーかどうかが変わったら、`src/lesson/publish-status.ts` が覚えた答えを捨てて読み直す。メンバーでない人の「続きから」にはこの章の節が入らない
- **用語の検索の索引**（`search-index.json`。誰でも読むファイル）: この章の節の札を入れない。この章で初めて出る語の札は、誰でも開ける節（第15章）を行き先にし、そちらが無い語（ベースライン）だけ「入口1」を指す（題と「やってみる」のコードは入れない）。メンバーでない人には、この章への行き先に「メンバー向け」と添えてリンクにしない
- **本文の「入口2」**: 誰でも見られるページ（ほかの章の節・練習問題集）では、メンバーでない人にはリンクにせず文字だけにする（MDX の `a` を `src/components/lesson/PlainMembersLink.astro` に差し替える。メンバーには今までどおりリンク）。採点の欄のヒント（`Inline`）はだれが見ているかを知らないので、メンバーでない人が開けないページ（この章の節・今週の演習）でだけリンクにする。いまは、この章の外に「入口N」と書いたところは無い
- **構文の一覧**（`src/lesson/weekly-syntax.ts`）: この章の節を行き先にしない（入口は復習した書き方だけを使う決まりなので、ここで初めて教える書き方は無い）
- **今週のページ・練習問題集**: 今週のページはメンバーだけのページなので手を入れていない。練習問題集はこの章へのリンクを持たない

**みんなの予想ボード**

- **書き方**: `<Guess id="intro1-survived" question="…何%だと思う？" unit="%" answer={38.4} answerNote="342人 / 891人" />` を `</Facilitate>` のすぐあとに置く。問いに `"…"` を含むときは `question={'…'}` と書く。検査23（`check:lessons`）が、メンバーだけの章にしか置けないこと・id の形（英小文字・数字・ハイフン）と重なり・`question` が空でない・`unit` が `%`・`answer` が 0〜100 で小数第1位まで・`answerNote` が空でない文字列（任意）・中身を持たないことを見る。部品なので字数・文の長さの検査からは外れる
- **答えの置き場所**: `build:tests` が `lesson-data.json` の最上位の `guesses` に書き出し、サーバ（`src/server/guess.ts`）だけが読む。**節の HTML には答えを書かない**（答え合わせのあとに API が返す）。この表に無い id は API が断る（勝手な id で行を作れない）
- **データベース**: `migrations/0010_guess.sql`。`guesses`（所属・ボード・人で1行。答え合わせまで上書きできる）と `guess_reveals`（所属・ボードで1行。行が有れば答え合わせ済み。「やり直す」は行を消すだけで、予想は残す）
- **所属**: 見ている人の所属のボード。運営の「答え合わせ」は押した人の所属だけに効く（今週の演習の公開で運営が自分の所属に公開するのと同じ）。管理者も、節のページのボードが見せている自分の所属に効く（今週の演習の画面のように所属を選ぶ欄は作っていない）
- **API**: `GET /api/guess?ids=a,b`（メンバーだけ。1回で最大10ボード）、`POST /api/guess`（`{ id, value }`。メンバーだけ。答え合わせのあとは 409）、`POST /api/guess/reveal`（`{ id, revealed }`。運営・管理者だけ）。どれも、章が準備中なら運営・管理者だけ
- **予想の値**: ％で 0〜100。小数は第1位までにそろえて受ける（38.38 → 38.4）。入力欄はブラウザの検査を切り（`novalidate`）、範囲外は「0から100までの数を入れてください。」
- **答え合わせの前**: 数だけを**小さい順に**並べる（出した順に並べると、出した時刻から誰の数か見当がつくため）。名前は API の答えにも入れない。「◯人が予想しました（答え合わせまで名前は出ません）」
- **答え合わせのあと**: 札に「名前 値%」、いちばん近い人（同じ近さなら全員）を緑。下に「本当は **38.4%**（342人 / 891人）。いちばん近かったのは ◯◯（39%）」。自分の予想の入力欄は隠す
- **運営のボタン**: API の `staff` を見て出す。「答え合わせ（運営）」→ 画面の中の確かめ「本当の数と、全員の名前を見せます。このあとは予想を変えられなくなります。」［答え合わせをする］［やめる］。答え合わせのあとは「やり直す（運営）」→「答えと名前を隠して、予想を受け付ける状態に戻します。出した予想は消えません。」。`confirm()` は使わない
- **読み直し**: ページの中のボードを1回の GET でまとめて、画面が見えている間だけ5秒ごとに読む。裏に回ったら止め、見えたらすぐ1回読んでから再開する。ログアウトなどで 401/403/404 が返ったら止める
- **見た目**: 試作「案C の1」のとおり（琥珀の細い枠・明るい地・明朝の太字の問い・丸い札・近い人は緑）。色は `lesson-tokens.css` のものだけ、ボタンは既存の `.kit-btn`（運営のボタンは琥珀の字と枠）
