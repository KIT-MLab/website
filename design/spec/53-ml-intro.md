## 4. 集まりの進め方メモ（運営だけ）

利用者の相談「集まったときに私ができることはあるのか。これ読んでくださいでいいのか」。答え: 運営の役目は教えることではなく、**問いかけて・予想させて・比べさせる**こと。進める分の30分は「最初の3分で問いかけて予想を並べる → 20分各自で読んで解く → 最後の7分で予想と答えを比べ、次の週につなぐ問いを1つ投げる」。

各節の先頭に、**運営にだけ見える「集まりの進め方」**を置く（利用者の選択）。中身:

1. 最初の問いかけ（1〜2問。数字で答えられるもの。例:「生き残ったのは何割だと思う？」）
2. 答え合わせで言うこと（予想と実際の数、ひとことの要点）
3. 次につなげる問い（答えは言わず、次の節で確かめる。例:「正解率が90%なら良い予測と言える？」）
4. よく詰まるところ

メンバーには中身を1文字も送らない（第13.2節と同じ。節のページはサーバで組み立てているので、運営でなければ出さない）。

**みんなの予想ボード**

- **書き方**: `<Guess id="intro1-survived" question="…何%だと思う？" unit="%" answer={38.4} answerNote="342人 / 891人" />` を `</Facilitate>` のすぐあとに置く。問いに `"…"` を含むときは `question={'…'}` と書く。検査23（`check:lessons`）が、メンバーだけの章にしか置けないこと・id の形（英小文字・数字・ハイフン）と重なり・`question` が空でない・`unit` が `%`・`answer` が 0〜100 で小数第1位まで・`answerNote` が空でない文字列（任意）・中身を持たないことを見る。部品なので字数・文の長さの検査からは外れる
- **答えの置き場所**: `build:tests` が `lesson-data.json` の最上位の `guesses` に書き出し、サーバ（`src/server/guess.ts`）だけが読む。**節の HTML には答えを書かない**（答え合わせのあとに API が返す）。この表に無い id は API が断る（勝手な id で行を作れない）
- **データベース**: `migrations/0010_guess.sql`。`guesses`（所属・ボード・人で1行。答え合わせまで上書きできる）と `guess_reveals`（所属・ボードで1行。行が有れば答え合わせ済み。「やり直す」は行を消すだけで、予想は残す）
- **所属**: 見ている人の所属のボード。運営の「答え合わせ」は押した人の所属だけに効く（今週の演習の公開で運営が自分の所属に公開するのと同じ）。管理者も、節のページのボードが見せている自分の所属に効く（今週の演習の画面のように所属を選ぶ欄は作っていない）
- **API**: `GET /api/guess?ids=a,b`（メンバーだけ。1回で最大10ボード）、`POST /api/guess`（`{ id, value }`。メンバーだけ。答え合わせのあとは 409）、`POST /api/guess/reveal`（`{ id, revealed }`。運営・管理者だけ）。どれも、章が準備中なら運営・管理者だけ
- **予想の値**: ％で 0〜100。小数は第1位までにそろえて受ける（38.38 → 38.4）。入力欄はブラウザの検査を切り（`novalidate`）、範囲外は「0から100までの数を入れてください。」
- **答え合わせの前**: 数だけを**小さい順に**並べる（出した順に並べると、出した時刻から誰の数か見当がつくため）。名前は API の答えにも入れない。「◯人が予想しました（答え合わせまで名前は出ません）」
- **答え合わせのあと**: 札に「名前 値%」、いちばん近い人（同じ近さなら全員）を緑。下に「本当は **38.4%**（342人 / 891人）。いちばん近かったのは ◯◯（39%）」。自分の予想の入力欄は隠す
- **運営のボタン**: API の `staff` を見て出す。「答え合わせ（運営）」→ 画面の中の確かめ「本当の数と、全員の名前を見せます。このあとは予想を変えられなくなります。」［答え合わせをする］［やめる］。答え合わせのあとは「やり直す（運営）」→「答えと名前を隠して、予想を受け付ける状態に戻します。出した予想は消えません。」。`confirm()` は使わない
- **予想を消す（2026-09-29 利用者の依頼）**: 集まりのたびにボードを使い直すため、運営・管理者（運営として見ているとき）にいつでも「予想を消す（運営）」を出す（答え合わせの前でもあとでも）。確かめ「全員の予想を消します。元に戻せません。」［予想を消す］［やめる］。`POST /api/guess/reveal` に `{ id, reset: true }`。押した人の所属の `guesses` と `guess_reveals` の行を消す。5秒以内に全員のボードが空になり、また予想を出せる（メンバーの欄に残っていた数も消す）。メンバー・学習者として見ている人は 403
- **読み直し**: ページの中のボードを1回の GET でまとめて、画面が見えている間だけ5秒ごとに読む。裏に回ったら止め、見えたらすぐ1回読んでから再開する。ログアウトなどで 401/403/404 が返ったら止める
- **見た目**: 試作「案C の1」のとおり（琥珀の細い枠・明るい地・明朝の太字の問い・丸い札・近い人は緑）。色は `lesson-tokens.css` のものだけ、ボタンは既存の `.kit-btn`（運営のボタンは琥珀の字と枠）

## 9. 規則の正解率ランキング（2026-09-27 決定。タイタニック2）

利用者（プロジェクトの代表）と決めた形。10/6 の集まりの後半に、タイタニック2 で使う。小さな Kaggle の順位表として、各自の規則を出すと訓練データの正解率で並び、テストデータの正解率は運営が「公開」を押すまで伏せる（試作 c-proto.html の「案C の2」）。

**何をするか**

- **書くもの**: 1人ぶんの予測 `pred` を決める if文だけ（タイタニック2 の「やってみる」のコードの7〜10行目と同じ形。最初はその4行が入っている）。使える記録は `sex[i]`（"女" か "男"）・`pclass[i]`（1〜3）・`age[i]`（年齢）と `i`。答え（`survived`）は使えない（テストデータに答えが無いため。書くと `NameError`）。for文・関数は書かない（10/6 は第3〜4章の復習の週）
- **出す**: 規則のひとことの説明（1〜40字。例「女性か12歳未満」）を添えて「出す」を押す。ブラウザ（Pyodide）が規則を for文に包んで訓練データとテストデータの両方に当て、**1 か 0 の予測の並びと説明だけ**を送る。規則のコードは送らない。`pred` が 1 か 0 に決まらない人がいれば送らずに「pred が決まらない人がいました（訓練データの i が 0 の人）」と出す。Python のエラーは、書いた規則の中の行番号とエラーの型ごとの説明（`<Run>` と同じ `adviceFor`）を出す。書きかけの規則と説明はこの端末に残す（演習の書きかけと同じ）
- **正解率はサーバが出す**: 送られた予測を、サーバだけが持つ答えと比べる。出した本人への返事も訓練データの正解率だけ
- **表**: 順位・名前（表示名）・規則（説明）・訓練データ・テストデータ。1人1行（いちばん新しく出したもの）。訓練データの正解率の高い順で、同じ正解率は同じ順位（1, 2, 2, 4）、先に出した人が上。自分の行は明るい地と左の朱の線。公開前はテストデータの列が全員「公開前」。公開後は数が出て、訓練データより 0.1（20人で2人ぶん）以上低い行に朱の ▼。公開後も並びは訓練データの順のまま（1位の規則が下がったのを見せるため）
- **公開・やり直す**: 運営・管理者にだけ「公開（運営）」が出る。画面の中で確かめてから公開（`confirm()` は使わない）。公開すると全員の画面に5秒以内にテストデータの正解率が出て、規則は出せなくなる（409）。「やり直す（運営）」で伏せた状態に戻る（出した規則は残る）。「出した規則を消す（運営）」はいつでも出る（2026-09-29。予想ボードの「予想を消す」と同じ。確かめ「全員の出した規則を消します。元に戻せません。」、`POST /api/rule-board/reveal` に `{ id, reset: true }`。所属の `rule_submissions` と `rule_reveals` の行を消す）
- **読み直し**: 画面が見えている間だけ5秒ごと（予想ボードと同じ。裏に回ったら止め、401/403/404 で止める）

**データの分け方**（datasciencedojo の公開 CSV 891人のうち年齢が整数の人。数は Python で計算して確かめた）

- 訓練データ: タイタニック2 の20人（PassengerId 213〜237 のうち年齢が整数の20人。性別・等級・生き残りは節の `<Run>` と同じ。年齢はタイタニック3 の `ages` の先頭20人）

## 11. みんなの進み具合（運営だけ。2026-09-29 決定）
