# 第6章（06-error）学習者の目で読んだ報告

読んだ順: 01-read, 02-syntax, 03-type, 04-logic, 05-scores。`node scripts/taught.mjs python-06-read` を最初に実行し、2節目以降は前の節までに読んだことを足して考えた。
指摘番号は章を通して L1〜。

## 章全体で目立つこと（先に）

この章は「エラーを読む」章なのに、**エラーの実物が画面に出る場面が、第1節の1回しかない**。第2〜4節の `<Run>` は、どれも正しく動くコードで、`out` に正常な結果が出るだけである（L1）。学習者は SyntaxError / TypeError / ValueError の実際の文面を、課題で初めて見る。

## 第2節 python-06-syntax「SyntaxErrorとNameError」

### 止まる
- L1 【02-syntax】 場所: 「やってみる」の `<Run>`（apple + orange の計算）と、「困る例」の「動かしてはじめてエラーになって出ます」
  なぜ: 「困る例」はエラーが出ると言うのに、Run は正常に `くだものは8個です` と出るだけで、SyntaxError も NameError も1つも見えない。学習者は説明文の「SyntaxError は…」を、実物なしの言葉だけで読むことになる。全角の記号や `: ` の不足が実際にどんなメッセージ（`invalid character` / `expected ':'` / `was never closed` など）になるかを、課題で初めて見る
  案: 壊れたコードを `error` つきの `<Run>` で見せる（SyntaxError と NameError を1つずつ）。正常に動く Run は要らない
- L6 【02-syntax】 場所: 課題 python-06-syntax-m1（starter に 5 か所の壊れ）
  なぜ: 全角コロン、`print(...` の閉じかっこ忘れ、`else` のコロン忘れ（SyntaxError 3つ）と、`itn`（NameError）がある。節で教えているのは種類の名前と原因の一覧だけで、**メッセージの文面と、それと原因の対応は1つも見せていない**。さらに SyntaxError は1つ直すと次が出るので、4回以上エラーを読み直す。最後の `itn` は SyntaxError を全部直したあとにやっと NameError として出るので、説明の「NameError は実行の途中で…」を読んでいれば追えるが、文面の読み方を知らない状態で4周は段差が大きい。ヒント1が「次のエラーが出ることがあります」と先に言っていて助かるが、ヒント2の全角は答えに近い
  案: L1 のとおり、節の中で SyntaxError の文面を1回見せる。または課題を壊れ2〜3か所に減らす

### 引っかかる
- L7 【02-syntax】 場所: 「この行より先へは、1行も実行されません。」
  なぜ: 「この行」がどの行か分からない（エラーの行か、文全体か）。SyntaxError ではファイル全体が1行も実行されない、という意味なら「この行」は誤解を招く
  案: 「ファイルのどこかに SyntaxError があると、1行も実行されません」のように言う
- L8 【02-syntax】 場所: 「インデントの誤り」「どれもSyntaxErrorの仲間です」
  なぜ: インデントの誤りが画面では IndentationError という別の名前で出ることはここに無い。第5節の課題でそれが出て、名前が初見になる。「仲間です」という言い方も、名前が変わることを伝えていない
  案: 「インデントの誤りは IndentationError という名前で出る」と1文足す
- L9 【02-syntax】 場所: 「どちらの種類でも、いちばん下の行の名前と行番号を読めば、場所が分かります。」
  なぜ: 第1節で「止まった行と間違えた行は違うことがある」と学んだが、SyntaxError の閉じかっこ忘れは次の行（`else`）で止まるように見える。この節ではそれに触れておらず、行番号を信じて `else` 行を探して迷う
  案: 閉じ忘れは次の行で報告されることがある、と一言足す

### 要らない
- 「次の節では、型が合わないときに出るエラーを見ます。」は節の題の繰り返し
- 「やってみる」の `<Run>`（正常に動くコード）。L1 のとおり、何も示していないので消しても失うものが無い

### 課題ごとの表
| 課題 | 何を確かめるか | 未習の行 | 自分で考える数 | 抜け道 | 消したら失うもの |
|---|---|---|---|---|---|
| python-06-syntax-m1 | 全角記号・コロン・かっこ・綴りを、エラーを1つずつ読んで直す | `int(...)` は第1章で見た。`itn` は綴りだけ。未習の行は無いが、**SyntaxError の文面を読んで直す**ことは節内に例が無い | 3〜4（エラーが4回出て、それぞれ原因を文面から推測） | `print("はじめさん 合格")` だけでも通る（stdin 75 の1本しかテストが無い） | SyntaxError を読んで直す練習。他に無いので失う |

### この節は何のためにあるか
エラーには「文の形が読めない」(SyntaxError)と「名前が見つからない」(NameError)があり、どちらも最終行で見分けられると知るため。ただし実物のメッセージを見ないので、学習者の言葉では「そういう種類がある」までしか言えない。

## 第5節 python-06-scores「壊れた点数表を直す」

### 止まる
- L20 【05-scores】 場所: 課題 python-06-scores-m1 の starter（`    total = total + value` の字下げが無い）

  案: 第2節に IndentationError の名前と文面の実物を足す

### 引っかかる

  なぜ: starter の壊れは、`def` の `:` 忘れ、for の中の字下げ忘れ、`totla`、全角の `，`、`range(1)`（人数で回さない）、`input()` を int にしていない最初の点数、`<=` の向きの逆、の7か所だと数えた。8か所と数が合わない（学習者には見えない front matter の話）。学習者側の問題は、**1回の課題で、エラー読み直しが5回以上続く**こと。うち `[input(), …]` の int 忘れは `unsupported operand type(s) for +: 'int' and 'str'` と出て、第3節の「str と int の `+`」と並びが逆で気づきにくい。しかも止まる行は4行目（`total_score` の中）で、直す行は `scores = [...]` の行。第1節で習った「止まった行と間違えた行は違う」の実戦になっており、これは良い
