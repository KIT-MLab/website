# 第1章（01-python）学習者の目で読んだ報告

読んだ節（番号順）: 1 print / 2 variable / 3 input-basic / 4 input / 5 fstring / 6 scores
指摘の番号は章を通した L 番号。節の見出しの数字は上の番号。

## 止まる（ここで学習者が進めなくなる）

無し。

## 引っかかる（進めるが、迷うか、分からないまま通る）

- L1（節3 input-basic）場所: 「入力欄に読む行が残っていないのに `input()` を呼ぶと、…画面には「入力欄が空です。…」と出ます。」の次の段落「上の例で入力欄の2行目を消して ▶ を押すと、何も表示されないまま止まります。」
  なぜ: 同じ現象を「メッセージが出る」と「何も表示されない」と2通りに書いている。学習者はどちらが正しいか分からず、試して食い違うと混乱する。
  案: 「出力は何も出ず、代わりにこのメッセージが出る」と1つに言い直す。

- L2（節3 input-basic）場所: 「入力欄に `佐藤` と `京都` の2行が書いてある状態で、▶ を押してください。」
  なぜ: 「入力欄」がどこにある何なのかは、折りたたみの「入力欄の場所」（Level0）にしか書いていない。開かなければ、初めて見る学習者は入力欄を探す。節2までに入力欄は出ていない。
  案: 説明の最初の段落で、入力欄がコード欄の下にあることを1文で言う。

- L3（節3 input-basic）場所: `input("あなたの年齢は？")` の段落と Run、および「課題では、問題文に書いていない質問の文を `input()` に入れないでください」
  なぜ: この章の課題はどれも質問付きの input を使わない。節4〜6にも出てこない。学習者は「使う場面が来ない書き方」を覚えさせられ、警告文だけが残る。出力が「あなたの年齢は？19 歳です」と1行に混ざる理由も、「薄い色で出す」の説明だけでは読み取りにくい。
  案: 使う節まで送る。残すなら課題で1問使う。

- L4（節4 input）課題 python-01-input-b1 のヒント1: 「1つの式に2つ書いたときは、左の `input()` が1行目を読みます。」
  なぜ: 「1つの式に2つ書く」（`int(input()) - int(input())` のような形）は、この節のどこにも出ていない。ヒントを読んだ学習者は、そんな書き方があるのかと戸惑う。解答は変数2つで足りる。
  案: 「`input()` を呼んだ順に1行目、2行目が読まれる」だけにする。

- L5（節5 fstring）場所: 困る例「文字列と数値は値の種類（型）が違うので、そのままでは `+` でつなげません。`"点数は" + 80` と書くと…」
  なぜ: 「数値」「型」はこの章で初めて出る語で、説明が無い（`terms` に型はあるが本文は括弧書きだけ）。また、`+` で文字列がつなげることは、この節の説明の後半（「文字列どうしは `+` で1つにつなげられます」）でやっと出る。困る例の時点では、`+` でつなげるものだと学習者は知らない。
  案: 困る例を「数と文字を1行にまとめたいのに、`print` のコンマでは空白が入ってしまう」といった、既習の道具で言える形にする。「型」は使うなら1文で定義する。

- L6（節5 fstring）場所: 「`{name}` のように `{}` の中に変数を書くと、その値が文字列の中に展開されます。」
  なぜ: 「展開」が分からない。例の出力を見れば推測できるが、言葉としては説明が無い。
  案: 「その値に置き換わります」にする。

- L7（節5 fstring）課題 python-01-fstring-b1 の Output: 「形は出力例のとおりです。」
  なぜ: 問題文だけでは `名前:田中 点数:80点 残り20点` の「残り」「点」の位置が決まらない。出力例が画面に出る前提で読んだが、出なければ書式を推測するしかない。節5の例の形（`名前:` `点数:`）に合わせるのか、「残り」と書くのかも、出力例が頼り。
  案: 問題文に期待する出力の1行を書く（画面に出ていることを確かめる）。

- L8（節5 fstring）課題 python-01-fstring-b2 の入力・出力: `【` `】` を打つ
  なぜ: 節1のやさしい解説と第0章（半角/全角）で「全角は Python のコードとして読み取れない」と教わっている。ここでは全角の `【】` を `"` の中に書く。引用符の中なら全角でよい、という説明が無い。迷ったまま通るか、半角に直そうとする。
  案: 「文字列の中は全角でもよい」と1文足す。

- L9（節2 variable）場所: 変数の名前の表の `if`「Python が決まった意味で使う語」、および「`print` のような関数の名前は、変数に使うとその関数が使えなくなるので避けます。」
  なぜ: `if` は学習者が知らない語で、どんな意味で使われるのかは分からない（この節では「そういう語がある」としか分からない）。関数名の件は例が無く、「使えなくなる」様子を確かめられない。どちらも覚えるだけになる。
  案: `if` の行は「今は使わない語」と言い切る。関数名の件は、例を1つ見せるか、消す。

- L10（節2 variable）課題 python-01-variable-m3: 「エラーで止まります」
  なぜ: 学習者はこの章でエラー画面をまだ見ていない（節3の空の入力欄が初出）。starter を動かして出るエラーの文が読めるかで、何を直すか決まる。模範解答は `price1` `price2` だが、「名前を直す」のどこを直すかの手がかりはヒントの表への案内だけ。
  案: エラー文の読み方を1文教えるか、ヒントに「エラーの行番号を見る」を足す。

- L11（節6 scores）場所: 節全体（「困る例」「説明」）
  なぜ: 新しい書き方が無い（`terms: []`）。例も合計だけで、課題 b1 が初めて「合計を教科の数で割って f 文字列に入れる」を要求する。平均の求め方は説明に1文あるだけで、ヒントが2回それを指す。例に平均が無いので、「説明に書いた、平均の求め方」を何度見ても、書き方の見本は無い（`total / 3` は自分で組み立てる）。
  案: 「やってみる」の Run に平均の行を足す。

- L12（節6 scores）課題 b1 と m2: 表示の順が逆
  なぜ: m2 は「平均、合計」の順、b1 は「合計、平均」の順。どちらも問題文に例が書いてあるので読めば分かるが、続けて解く学習者は取り違えやすい。
  案: 順をそろえる。

## 要らない（消しても何も失わない文・問題）

  なぜ: 節の題と、直前の説明の言い直し。次の節の予告の文だけで足りる。

- 場所: 節6 説明の最後の段落「教科の数がもっと増えると…リストを使うと、教科の数が変わっても同じ書き方で処理できます。」
  なぜ: 学習者の知らない「リスト」を先に出すだけで、この節の課題には使わない。消しても何も失わない。

- 場所: 節6 困る例「点数を受け取り、名前で覚えておき、結果を文章で示せないと、確認するたびにコードを書き換えることになります。」
  なぜ: 何ができないと困るのかが、この節の道具（変数・input・f文字列）の並べ直しで、具体的な困りごとが無い。

- 場所: 節3 `input("質問")` の段落・Run（L3 を参照）
  なぜ: この章で使う課題が無い。

## 章全体の所見

- 課題に出てくる書き方で、教えていない行は無かった。止まる箇所は無い。
- 節2・4・5・6 の modify 課題（m1・m2）は、テストが1通りの stdout だけなので、固定の文字を print するだけで通る。節3・4・5・6 の build 課題はテストが複数あり、この抜け道が無い。
- 節6 の平均は、テストの入力がすべて割り切れるので、`/` が長い小数を出す場面が一度も試されない。説明が「割り切れるときも 70.0」とだけ言っていて、割り切れないときは何が出るかは第2章に回している。章内では問題にならない。
