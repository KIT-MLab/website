# 第5章（05-function）日本語の読み 2回目

読んだ節: 01-def / 02-return / 03-args / 04-keyword / 05-scope / 06-scores
意味が取れない文は無い。直すのは下の6か所。

## 意味が取れない・取り違える

- J1（05-scope）
  元: 「まず、いまのコードをそのまま実行して、1行目と2行目に何が表示されるか確かめてください。」（ヒント python-05-scope-m1 の1つ目）
  種類: 指示があいまい。この節では「N行目」は一貫してコードの行を指す。そのため、読み手はコードの1行目と2行目を見に行き、`total = 100` と `def ...` を見て戸惑う。表示の行のつもり
  直し: 「まず、いまのコードをそのまま実行して、表示の1行目と2行目に何が出るか確かめてください。」

## 不自然（意味は取れる）

- J2（05-scope）
  元: 「関数の外には、計算も数も書き足さないでください。`80` `80` の順に表示されれば直っています。」（課題 python-05-scope-m1）
  種類: 指示があいまい / 不自然。「数も書き足さない」は何を禁じているのか分かりにくい。「`80` `80` の順に」も、同じ値を並べて「順に」と言っていて読みにくい
  直し: 「関数の外に、計算や `80` などの数を書き足さないでください。`80` と `80` が1行ずつ表示されれば直っています。」

- J3（05-return）
  元: 「第4章2節で最大の値を求めたときと同じく、いまのところの最大を変数に入れ、`b` と `c` を順に比べて大きければ入れ替えます。」（ヒント python-05-return-b1 の1つ目）
  種類: 主語や目的語が分からない。「大きければ」は何より大きいのか、「入れ替えます」は何を入れ替えるのかが書かれていない
  直し: 「第4章2節で最大の値を求めたときと同じく、いまのところの最大を変数に入れ、`b` と `c` を順にそれと比べて、大きいほうを新しい最大にします。」

- J4（06-scores）
  元: 「7〜8行目の `average_score` は `total_score(scores)` を呼び出しています。その結果を `len(scores)` で割ることで、平均を求めています。`round(..., 1)` で、小数第1位に丸めています。関数の中から、別の関数を呼び出せます。」（説明）
  種類: ぶつ切り。同じ調子の短い文が4つ続き、つながりが読み手任せ。最後の1文だけ唐突に一般論になる
  直し: 「7〜8行目の `average_score` は、関数の中で `total_score(scores)` を呼び出し、その結果を `len(scores)` で割って平均を求めます。さらに `round(..., 1)` で小数第1位に丸めています。このように、関数の中から別の関数を呼び出せます。」

- J5（06-scores）
  元: 「10〜12行目で `scores` を作り、2つの関数をそれぞれ呼び出して表示しています。合計と平均を求める部分が、名前を呼ぶだけで使えるようになりました。」（説明）
  種類: 中身が無い。「〜できるようになりました」で終わるまとめ。「名前を呼ぶ」も、ほかの所の「関数を呼び出す」と言い方が違う
  直し: 「10〜12行目で `scores` を作り、2つの関数をそれぞれ呼び出して表示しています。合計と平均を求める式は、関数の名前を書いて呼び出すだけで使えます。」

- J6（04-keyword）
  元: 「`price_with_tax(0.2, 500)` のように、引数の順番を取り違える間違いが起きません。」（説明、4行目の段落）
  種類: 主語や条件が分からない。名前を付けずに書いた例を挙げているので、名前を書いても取り違えが起きるように読める
  直し: 「名前を書いて渡せば、`price_with_tax(0.2, 500)` のように順番を取り違える間違いは起きません。」

## 節全体について

- 01-def の課題 m1・b1 は「平均85.0」「平均を表示する」など「平均」が近くに重なるが、意味は取れるので直しは挙げない。
- 05-scope の説明末尾「別の場所に置かれた」「別の場所に置かれます」は同じ言い方が2回出る。意味は取れるので直しは挙げない。
