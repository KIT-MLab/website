# 第6章（06-error）日本語の読み

読んだ節: 01-read, 02-syntax, 03-type, 04-logic, 05-scores（examples.md も先に読んだ）

## 意味が取れない・取り違える

- J1【01-read】元: 「いちばん下の1行と、そこに書かれた行番号です。」（説明）
  種類: 主語や目的語が分からない（直後の文では行番号は「その少し上」にあり、下の1行には書かれていない。食い違う）
  直し: 「読む場所は2つだけです。**いちばん下の1行**と、**その少し上にある行番号**です。」

- J2【02-syntax】元: 「この行より先へは、1行も実行されません。」（説明）
  種類: 主語や目的語が分からない（「この行」がどの行か分からない。直前の「実行を始める前に」とも合わず、エラーの行より前は動くのかが取れない）
  直し: 「SyntaxErrorが出るプログラムは、1行も実行されません。」

- J3【03-type】元: 「どちらも、いちばん下の行に型の名前と詳しい値が書かれています。」（説明）
  種類: 言葉の選び（書いてあるのはエラーの名前と詳しい内容。「型の名前」は `int` などと取り違える。第1節では「エラーの種類の名前」「詳しい内容」と言っている）
  直し: 「どちらも、いちばん下の行に、エラーの種類の名前と詳しい内容が書かれています。」

- J4【05-scores】元: 「人数ぶんの結果と、合否の言葉が直す前と同じように出るかを、目で確かめてください。」（説明）
  種類: 言葉の選び（学習者が直すのは壊れたコードなので、「直す前」は壊れている状態を指してしまう。言いたいのは壊れる前、第5章の完成形）
  直し: 「人数ぶんの結果と、合否の言葉が、壊れる前と同じように出るかを、目で確かめてください。」

- J5【05-scores】元: 「合否の言葉が正しい向きか」（ヒント2つ目）
  種類: 言葉の選び（言葉に「向き」は無い。向きがあるのは条件）
  直し: 「合格と不合格が逆になっていないか」

- J6【03-type・build b1】元: 「1つ目を2つ目で割った結果を表示するプログラムを書いてください。」（課題）
  種類: 指示があいまい（`10` と `2` のとき `5` と `5.0` のどちらを出せば正解か、問題文から決まらない。入力が整数か小数かも書かれていない）
  直し: 説明が足りない。出す形（`5.0` のような小数か）と、入力が整数か小数かが問題文に無い

## 不自然（意味は取れる）

- J7【02-syntax】元: 「どちらの種類でも、いちばん下の行の名前と行番号を読めば、場所が分かります。」（説明）
  種類: 言葉の選び・係り受け（行番号は第1節で「その少し上」とされている。名前を読んでも場所は分からない）
  直し: 「どちらの種類でも、いちばん下の行でエラーの名前を、その少し上の行で行番号を読めば、直す場所の見当がつきます。」

- J8【02-syntax】元: 「目で追うだけでは気づけず、動かしてはじめてエラーになって出ます。」（困る例）
  種類: 硬い・翻訳調（「エラーになって出ます」）
  直し: 「目で追うだけでは気づけず、動かしてはじめてエラーとして表示されます。」

- J9【02-syntax】元: 「組み込みの `print` を `pirnt` と書いても、同じNameErrorになります。」（説明）
  種類: 言葉の選び（「組み込み」は教えていない語）
  直し: 「`print` を `pirnt` と書き間違えても、同じNameErrorになります。」

- J10【02-syntax】元: 「コロンの不足、かっこの閉じ忘れ、全角の記号、インデントの誤りは、どれもSyntaxErrorの仲間です。直すたびに、次のSyntaxErrorが出ることもあります。」（説明、3段落目）
  種類: 同じ語の繰り返し（1段落目の列挙の言い直し。SyntaxErrorが3文に出る）
  直し: 「インデントの誤りもSyntaxErrorの仲間です。1つ直すと、そのあとの行の別のSyntaxErrorが出ることもあります。」（1段落目で挙げた原因をもう一度並べない）

- J11【02-syntax】元: 「全角の記号は日本語入力がオンのまま打つと出ます。」（ヒント2つ目）
  種類: 主語が分からない（何が「出る」のか）
  直し: 「全角の記号は、日本語入力がオンのまま打つと入ってしまいます。」

- J12【03-type】元: 「文字だけを見ても、何がいけないのか分かりません。」（困る例）
  種類: 主語や目的語が分からない（何の文字か）
  直し: 「エラーの文を見ただけでは、何がいけないのか分かりません。」

- J13【03-type】元: 「型は文字列のままで正しいのに、中身が数字でない文字だと変換できません。」（説明）
  種類: 硬い・翻訳調（「型は文字列のままで正しい」が引っかかる。何が正しいのか一度で取れない）
  直し: 「`int()` には文字列を渡すので型は合っています。ただ、中身が数字でない文字だと数に変換できません。」

- J14【03-type】元: 「文字列のまま計算すればTypeError、数字でない文字列をint()に渡せばValueErrorです。」（説明）
  種類: 表記のゆれ（同じ節のほかの所では `int()` をコードの書式にしているが、ここだけ地の文）
  直し: 「…数字でない文字列を `int()` に渡せばValueErrorです。」

- J15【04-logic】元: 「エラーが出ないときは、値を目で追うしかありません。確かめたい行の近くに `print(値)` をもう1行足すと、…」（説明）
  種類: 硬い・ぶつ切り（「目で追うしかない」と言った直後に、別の方法を出している）
  直し: 「エラーが出ないときは、途中の値を自分で確かめます。確かめたい行の近くに `print(値)` をもう1行足すと、…」

- J16【04-logic】元: 「条件の向きが逆、繰り返しの中でインデックスを固定したまま、`return` を書き忘れて `None` が返る、はよくある形です。」（説明）
  種類: 語順・係り受け（3つを読点でつないだあとに「はよくある形です」が来て、一度で読み切れない）
  直し: 「よくある間違いは、条件の向きが逆になっている、繰り返しの中でインデックスが固定されている、`return` を書き忘れて `None` が返る、の3つです。」

- J17【04-logic】元: 「出力を1つずつ期待する値と見比べてください。」と「実行結果と自分が期待する値を並べて見比べてください。」（説明、2段落目と3段落目）
  種類: 同じ語の繰り返し（「期待する値」「見比べてください」が隣り合う段落で2度出る）
  直し: 3段落目を「たとえば `value >= 60` を `value <= 60` と書いても、動きはします。ただ、数え方だけが変わるので、エラーにならず気づきにくくなります。」（2段落目の指示をもう一度言わない）

- J18【04-logic・m2】元: 「`40` `65` `82` がこの順で表示されるように、直してください。」（課題）
  種類: 指示があいまい（1行ずつか、1行にまとめてか決まらない）
  直し: 「`40`、`65`、`82` が1行ずつこの順に表示されるように、直してください。」

- J19【05-scores】元: 「直った形でも、`total_score` と `average_score` の2つの関数が、人数ぶん呼び出される形のままです。」（説明）
  種類: 語順・係り受け（「直った形でも…形のままです」と「形」が2度出て、何が「のまま」なのか取りにくい）
  直し: 「直し終えたあとも、`total_score` と `average_score` は人数ぶん呼び出されます。」

## 節全体について

- 02-syntax: 「やってみる」のコードはエラーにならず、説明もそのコードに触れない。「次のコードの ▶ を押してください」のあとに何を見るのかが、読み手に渡っていない。
- 画面に出ない見出しを指す文、作り手の言葉、節の終わりの中身の無い文は、この章には見つからなかった（各節の最後は「次の節では…」で、次に何をするかが書かれている）。
