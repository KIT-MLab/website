## 意味が取れない・取り違える

- **J1**（02-rate／課題 python-13-rate-b1）
  元: 「発散したときは、学習率のあとに `発散` と表示します。」
  種類: 指示があいまい。直前の文で「続けて最後の `x` と `f(x)` を…表示します」と書いてあるので、発散したときも `x` と `f(x)` を出すのか、出さないのかが決まらない（模範解答は出さない）。学習率と `発散` のあいだを空けるのかも書いていない（模範解答は半角空白1つ）。
  直し: 「発散したときは、最後の `x` と `f(x)` の代わりに `発散` を表示します。学習率と、`x`・`f(x)`・`発散` のあいだは半角空白1つで区切ります。」

- **J2**（03-linear／課題 python-13-linear-b1）
  元: 「くり返しの途中で、100回動かし終えるたびに（100回目、200回目、…）、その回数と損失を1行に表示します。」
  種類: 指示があいまい。「その回数と損失」を何で区切るかが書いていない（模範解答は半角空白1つ）。
  直し: 「…100回動かし終えるたびに（100回目、200回目、…）、その回数と損失を、半角空白1つで区切って1行に表示します。」

- **J3**（03-linear／課題 python-13-linear-b1／ヒント1つ目）
  元: 「勉強時間と点数の配列、`loss`・`grad` の式は、上のコードと同じものを使います。」
  種類: 指示があいまい（「上のコード」が何か）。この課題のすぐ上には、課題 `python-13-linear-m1` の starter があり、そこには `grad` はあるが `loss` は無い。節の最初のコードを指すのか、すぐ上の starter を指すのか、読み手が決められない。
  直し: 「勉強時間と点数の配列、`loss`・`grad` の式は、この節の最初のコードと同じものを使います。」

- **J4**（04-multi／課題 python-13-multi-b1／ヒント1つ目）
  元: 「データと `predict`、1回動かす2行は、上のコードと同じです。」
  種類: 指示があいまい（「上のコード」が何か）。すぐ上の `python-13-multi-m1` の starter は、5人ぶんだけの別のデータで、`w` と `b` を動かす行も無い。「上のコード」を starter と取ると食い違う。「1回動かす2行」もどの2行か分からない（最初のコードの17〜18行目の `w = …` と `b = …`）。
  直し: 「データと `predict` は、この節の最初のコードと同じです。1回動かす `w = …` と `b = …` の2行も、最初のコードの17〜18行目と同じです。」

## 不自然（意味は取れる）

- **J5**（01-descent／課題 python-13-descent-b1／ヒント1つ目と2つ目）
  元: 「傾きを求める式は、上のコードと同じ (f(x+h) - f(x)) / h です。」「くり返しの中で x を書き換える式は、上のコードの8行目と同じです。」
  種類: 指示があいまい（「上のコード」が何か）。節の最初のコードを指すのか、すぐ上の `python-13-descent-m1` の starter を指すのか決まらない。幸い、どちらの8行目も `x = x - 0.3 * slope` で結果は同じだが、読み手には分からない。
  直し: 「傾きを求める式は、この節の最初のコードと同じ (f(x+h) - f(x)) / h です。」「くり返しの中で x を書き換える式は、最初のコードの8行目と同じです。」

- **J6**（02-rate／課題 python-13-rate-c1／問題文）
  元: 「学習率を大きくして動かしたところ、`x` の値が行ったり来たりしながらどんどん大きくなりました（発散しました）。」
  種類: 言葉の選び。この節の説明では、発散は「`f(x)` の値が大きくなっていく状態」と定めてある。ここでは `x` の値が大きくなることを発散と呼んでいて、定義とずれる。
  直し: 「学習率を大きくして動かしたところ、`x` の値が行ったり来たりしながら、`f(x)` の値がどんどん大きくなりました（発散しました）。」

- **J7**（03-linear／説明）
  元: 「第12章5節の総当たり（`6.1`、`33.1`、損失 `19.03`）より損失が少し小さいのは、候補の刻みに縛られないためです。」
  種類: 硬い・翻訳調。「候補の刻みに縛られない」は口で言わない。
  直し: 「第12章5節の総当たり（`6.1`、`33.1`、損失 `19.03`）より損失が少し小さいのは、総当たりでは決まった刻みの値しか試せないのに対し、勾配降下法は刻みに関係なく `a` と `b` を動かせるからです。」

- **J8**（05-standardize／説明）
  元: 「`hours.std()` は `np.std(hours)` と同じで、`.mean()` と同じ形で書けます。」
  種類: 語順・係り受け。「`.mean()` と同じ形」が、`hours.mean()` を指すことが一度読んだだけでは分からない。
  直し: 「`hours.std()` は `np.std(hours)` と同じ意味で、`hours.mean()` と同じ形で書けます。」

- **J9**（05-standardize／課題 python-13-standardize-c1／問題文）
  元: 「標準化した勉強時間で学習したモデルで、新しい人の点数を予測します。」
  種類: 同じ語の繰り返し（「で」が続く）。
  直し: 「勉強時間を標準化して学習したモデルを使って、新しい人の点数を予測します。」

- **J10**（06-study／説明）
  元: 「学習前の損失（`4334.2`）と学習後の損失（`16.88`）を比べると、200回のくり返しで大きく下がったと分かります。」
  種類: 中身が無い（数字を並べて「大きく下がった」と言うだけ）。出力の3〜5行目（`w`、`b`、予測）についての説明も、この節には無い。
  直し: 説明が足りない（出力の `[15.51  1.47]`・`63.8`・`64.0` が何かを書く必要がある）。なお、この文は「損失が `4334.2` から `16.88` に下がります。」と短くしてよい。

## 節全体について

- **J11**（03-linear／困る例）: 「`a = 7`、`b = 30` のとき、`a` と `b` を…」で、`a` と `b` が何か（直線の傾きと切片か）が、この節のどこにも書いていない。第10章5節を読み返さないと主語が分からない。内容は足さず、「説明が足りない」とだけ報告する。
- **J12**（04-multi／説明）: 「`w` は入力ごとの重みをまとめた配列です」で、重みという語がここで初めて出る（03節では `a` と `b` だった）。重みとは何か、説明が足りない。
- **J13**（全体）: 「上のコード」を使うヒントは、直前に別の starter がある節（01、03、04）で取り違えやすい。05・06 は直前に紛らわしいコードが無いので問題ない。書き手は「この節の最初のコード」と書き分けると、問題文（`この節の最初のコードの…`）と調子もそろう。
