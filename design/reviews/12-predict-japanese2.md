# 第12章（12-predict）日本語の読み 報告

対象: 01-model / 02-loss / 03-search / 04-count / 05-study の5節。`design/authoring/examples.md` を先に読んだ。

## 意味が取れない・取り違える

### J1（02-loss）
- 元: 「この値を損失と呼びます。」「損失のうち、このように差を2乗して平均したものを、平均二乗誤差と呼びます。」（説明）
  種類: 言葉の選び（1つの値に2つの名前が付き、どちらが何を指すのか取り違える）。直前の文で `mse` の値が「損失」と呼ばれ、次の段落で同じ値が「損失のうち…平均二乗誤差」と呼ばれる。節の題が「損失（平均二乗誤差）」なので、2つが同じものか、損失の一種が平均二乗誤差なのかが決まらない。
  直し: 「この値を損失と呼びます。損失にはいくつかの測り方があり、`mse` のように差を2乗して平均したものを、平均二乗誤差と呼びます。」
  （「いくつかの測り方」は足す内容になるので、採るか迷うなら「損失のうち」を「ここで求めた損失は」に変えて、2文を「ここで求めた損失は、差を2乗して平均したものなので、平均二乗誤差と呼びます。」の1文にまとめてもよい）

## 不自然（意味は取れる）

### J2（01-model、困る例）
- 元: 「2本の直線で予測を出して比べたくても、式が `loss` の中にあるままでは、`a` と `b` を変えて何度も呼べません。」
  種類: 主語や目的語が分からない。`loss(a, b)` は `a` と `b` を変えて何度も呼べるので、読み手は「呼べない」が何を指すのか取り違える。困っているのは、予測の値そのものを取り出せないこと。
  直し: 「2本の直線で予測を出して比べたくても、式が `loss` の中にあるままでは、予測の値だけを取り出せません。」

### J3（01-model、説明）
- 元: 「この式の形をモデル（model）と呼び、ここでは直線です。」
  種類: 主語や目的語が分からない・硬い。「この式の形」が `a * hours + b` を指すのか `predict` 全体なのかが読み取りにくく、「ここでは直線です」の主語も抜けている。
  直し: 「`a * hours + b` のような、入力から予測を出す式をモデル（model）と呼びます。ここでのモデルは直線です。」

### J4（01-model、説明）
- 元: 「6行目の `hours` は、呼び出すときに1つ目の引数として渡した配列です。」
  種類: 語順・係り受け。6行目の `hours` は `predict` の中で受け取る側の名前で、「渡した」と書くと8行目の `hours` と混ざる。
  直し: 「6行目の `hours` は、呼び出すときに1つ目の引数として渡された配列を受け取る名前です。」

### J5（02-loss、困る例）
- 元: 「AさんとBさんの直線のどちらが良いかは、見た目では決められません。差の2乗の和（第7章2節）は人数が増えるほど大きくなるので、人数の違う集まりどうしでは比べられません。」
  種類: ぶつ切り。1文目の「見た目では決められない」と2文目の「人数が違うと比べられない」のつながりが読み手任せ。2文目は、Aさん・Bさんの比べ方ではなく別の話に見える。
  直し: 「AさんとBさんの直線のどちらが良いかは、見た目では決められません。数で比べようと、差の2乗の和（第7章2節）を使っても、人数が増えるほど大きくなるので、人数の違う集まりどうしでは比べられません。」

### J6（02-loss、説明）
- 元: 「差の2乗の和は `66.0` から `82.0` に増えますが、平均は `16.5` と `16.4` で、同じ1人あたりの大きさとして比べられます。」
  種類: 硬い・翻訳調。「同じ1人あたりの大きさとして比べられます」は口で言わない。
  直し: 「差の2乗の和は `66.0` から `82.0` に増えますが、平均は `16.5` と `16.4` で、ほとんど変わりません。」
  （「同じ」ではなく「ほとんど変わらない」とした。元の意図が「1人あたりなので比べられる」なら、そのまま残す）

### J7（03-search、説明）
- 元: 「`a` が `1` のあいだに、`b` が `10` と `20` を回ります。」
  種類: 言葉の選び。「b が 10 と 20 を回る」は、変数が値を「回る」という言い方で、入門書では「b が 10、20 と順に変わる」と書く。
  直し: 「`a` が `1` のあいだに、`b` は `10`、`20` の順に変わります。」

### J8（04-count、困る例）
- 元: 「前の節は `a` と `b` の2つを探しました。」
  種類: 語順・係り受け。「前の節は」では、節が探したことになる。
  直し: 「前の節では、`a` と `b` の2つを探しました。」

### J9（05-study、課題 python-12-study-b1 の問題文）
- 元: 「先頭から決めた人数だけを使って、損失が最小の `a` と `b` を選んでください。」
  種類: 指示があいまい。「決めた人数」を誰がどう決めるのか、問題文だけでは分からない（入力の1行目だとは、下の「入力」を読まないと分からない）。
  直し: 「読み取った人数だけ、30人分のデータの先頭から使って、損失が最小の `a` と `b` を選んでください。」

## 節全体について

- 01〜05の「説明」は、どの節も「N行目は…」「N〜M行目は…」で始まる文が続く。行番号は実際のコードと合っている。行番号の指す先は、「最初のコード」「上のコード」と書き分けられているので直さなくてよい。
- 02-loss以外の「つながり」は、次の節で何をするかを具体的に書いていて、中身が無い文は見つからなかった。
- 05-study の説明は2段落で、「第12章3節と同じ」（同じ章の中での参照）の書き方は、他の節の「第4章2節」などと形が合っている。直さなくてよい。
