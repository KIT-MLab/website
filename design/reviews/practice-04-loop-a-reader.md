# 練習問題集 第4章（for / list / index）初見の学習者として読んだ報告

読んだもの: `for.mdx` `list.mdx` `index.mdx`（各5問）、模範解答15本、第4章1〜3節。`design/spec/` と `practice-writer.md` は読んでいない。
確かめ方: 15問すべての `tests` の入力で、模範解答と「学習者が自然に書きそうな別の書き方」の出力を比べた（`py` で実行。スクリプトは scratchpad のみ）。

結果の要約: 問題文だけで正解の形が決まらない問題は無し。模範解答に「未習」の行は無し。止まる所は index-1 のヒントの指す先、1か所。

## 重い順の指摘

### R1. index-1 のヒントが指す先が違う（止まりうる）
- 場所: `practice-04-index-1` のヒント「最後の値の位置は、`len()` で調べた個数から決まります。第4章3節の最初のコードを見てください。」
- 何で止まるか: 3節の最初のコードにあるのは `numbers[0]` `numbers[2]` `len(numbers)` だけで、「len から引いた位置を取り出す」書き方（`numbers[len(numbers) - 2]`）は **2つ目のコードの4行目** にある。最初のコードを見ると、`len(numbers)` は5、最後のインデックスは4、と自分で気づくしかない。そこから `len(counts) - 1` と書ける人は少ない。
- 案: 「第4章3節の2つ目のコードの、最後の行を見てください。後ろから2番目を取り出す式です。」に直す（答えの `- 1` は言わない）。

### R2. index-3 は list-4 と同じ手順で、前の値を覚える書き方で通る（インデックスを使わずに通る）
- 場所: `practice-04-index-3`「区間ごとの距離」と `practice-04-list-4`「貯金の増減」
- 何で止まるか／何が問題か: どちらも「となり合う2つの値の、後ろ引く前を、前から順に表示」で、手順が同じ。list-4 の `previous = ...` の書き方（`previous = int(input())`、残りをリスト、`print(balance - previous)`、`previous = balance`）がそのまま index-3 にも通る。実際、list-4 の答えを写すだけで index-3 の全テストが通る。インデックスの練習にならない。
- あわせて、index-3 のヒント「値の位置を表す式は、`i` と、それより1小さい位置の2つです」は、答え（`points[i]` と `points[i - 1]`）の形をほぼ言っている。
- 案: index-3 の手順を、前の値を覚える書き方で通らないものに替える。たとえば「各チェックポイントについて、3つ前のチェックポイントからの距離」（`points[i] - points[i - 3]`、4つ目から）。あるいは list-4 のほうを別の題材（増減ではなく、たとえば「前の月より増えた月の数」）に替える。

### R3. index-1 は `counts[4]` と書いても通る（`len()` を使わなくても通る）／3節の課題 index-m2 とほぼ同じ
- 場所: `practice-04-index-1`「最初と最後の記録」
- 問題文は「最後の値は `len()` を使って取り出してください」と手段を指定している（手段の指定そのものは自然）が、判定は出力しか見ない。節の課題 index-m2 は `forbid={['numbers[4]']}` で止めているのに、こちらには無い。`counts[4]` で全テストが通る。また、index-m2「最後の値だけを表示。`len()` を使う」と、やることが同じ（こちらは先頭も出すだけ）。
- 案: `forbid` に `'[4]'` を足す。題材も節の課題と離すため、最後の値ではなく「最後の日の回数は、最初の日の回数より何回増えたか」のように一手足す形も考えられる。

### R4. index-4 のヒントの言い回しが分かりにくい
- 場所: `practice-04-index-4` のヒント「`i` が何番目の日かを表すとき、1日目、1+k日目、のように進む日の `i` は、どんな割り算の余りになるかを考えます。」
- 何で止まるか: 「`i` が何番目の日かを表すとき」は、日の番号とインデックス（0から数える）のどちらを指すのか決まらない。日の番号で考えると `i % k == 1` と書き（k=1 のとき何も出ず落ちる。テストの k=1 で気づく）、「1+k日目」も `i` の値と取り違える。
- 案: 「1日目はインデックス `0`、4日目はインデックス `3` です。3日ごとのとき、取り出すインデックス `0`、`3`、`6`、… は、3で割った余りがどうなりますか。」
- 札の名前「k日ごとの降水量」の `k` は、問題文のどこにも定義が無い。「何日かごとの降水量」などにするか、問題文に「その日数を `k` とします」と書く。

### R5. index-3 で `range(len(points))` と書くと、画面は5行を出して「1行目が合わない」だけが見える
- 場所: `practice-04-index-3`
- 何で止まるか: `for i in range(len(points)):` の `points[i] - points[i - 1]` は、`i = 0` のときに `points[-1]`（最後の値）を引いて、1行余分に出る。エラーにならないので、学習者は原因が分からない。ヒントにも「`i` が 0 のとき」には触れていない。
- 案: ヒントに「`i` が `0` のとき、1小さい位置はありません。繰り返す範囲の始まりをどうするか」を足す。R2 で題を替えるなら、そちらで同時に直す。

### R6. for-4 のテストは、小数の掛け算で書いた答えも通す
- 場所: `practice-04-for-4`「預金の利息」のテスト5組
- 何が起きるか: `a + int(a * (r / 100))` も `int(a * (1 + r / 100))` も、5組すべてで模範解答と同じになる。ところが `100円・29%・1年` は `a*(r/100)` で 28（正しくは 29）、`100円・13%・1年` は `a*(1+r/100)` で 112（正しくは 113）になる。通った答えが、別の入力では間違う。
- 案: テストに `100\n29\n1\n` と `100\n13\n1\n` を足す（落ちた学習者は、問題文の「1円未満は切り捨て」と2章の `//` に戻れる）。
- 重さ（★2に対して）: 考えること = (1) パーセントを整数の計算に直す（`amount * rate // 100`。`amount * (rate // 100)` と書くと利息が0になり、エラーも出ない）、(2) 残高を入れ直しながら進む、(3) 年の数を1から数える。3つで、★3 の for-5（`range` と `%` と `elif` の順番。どれも教えた形そのまま）より重い。進めないほどではない。★2のままなら、ヒントに「利率はパーセントなので、100で割ります。割り算は、1円未満を切り捨てる形で」と1文足すか、for-5 と★を入れ替える。

### R7. 題材・手順の重なり
- 節の課題とそっくり: for-1 ≈ for-b1（`range(1, n + 1)` で、足すか表示するかの違いだけ。ヒントも同じ「終わりの数は n より1大きい」）。list-1 ≈ list-m2（各値を計算して1行ずつ表示。入力を読むかどうかだけ違う）。index-1 ≈ index-m2（R3）。index-5 ≈ list-b1（最小を探す。違いは位置も覚えること）。
- 練習の中で同じ手順: index-3 と list-4（R2）。list-1 と list-3（どちらも「値段から引いて表示」、list-3 は if が足されるだけ）。for-2 と for-3（繰り返しの変数を式に入れて表示する形が同じ。for-3 は `//` と入力が2つ増える）。
- 題材: お金の問題が15問中7問（for-3, for-4, list-1, list-2, list-3, list-4, index-5）。list-1 と list-3 は同じ「クーポン／値引き」。スポーツ・天気・時間などに分けられる。list-1 を「入場者数から、受付で配った数を引く」のように替えると重なりが減る。

### R8. リストを使わずに、変数で通る道（list-1, list-4）
- list-1: `a = int(input())` を3つ並べて `print(a - 50)` を3つ。リストの5行より1行長いだけで、自然に出てくる。list-4: `a b c d` の4変数と `print(b - a)` 3つで通る。学習者が節の説明を使わずに、課題が通る。これは判定の限界に近いので、直すなら題材の数を増やす（list-1 は入力の行数を5行〜7行にする、など）程度。優先度は低い。

## 学習者が引っかかる言い回し（小さいもの）

- index-1「リストの個数が変わっても動くように」: 節の本文は「リストに入っている値の数」。「個数」は通じるが、「値の数が変わっても」に揃えると迷いが減る。
- index-3 入力欄「同じか、大きくなる順に並んでいます」: 「前の行と同じか、それより大きい値が並んでいます」のほうが一度で読める。
- for-1 のヒントは、3節の課題と同じ答えのヒント（n+1）を、ほぼそのまま言っている（節の for-b1 のヒントと同じ内容）。続けて解く学習者には2度目の答えの提示になる。「終わりの数は含まれません。n まで出すには、終わりの数に何を渡すか考えます」程度に弱める。
- list-4 のヒント「次の月の残高と比べたあとに入れ直します」は、`previous = balance` を書く位置を言っている。ここが最後に考えるべき所なので、言い過ぎ。「いまの値を、次の繰り返しで使えるように残しておきます」程度に。ただし、この問題は最初の1行を別に読むことに気づけるかが山で、ヒントはそこに触れていない。1文足す案: 「節の2つ目のコードのように、最初の1行は、リストに入れずに別に読みます。」

## 本体の決定（2026-10-02）
