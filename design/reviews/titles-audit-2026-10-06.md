## 4. 方針の案

### 案A「言葉＋何をするか」（章も節も）

- 章: 「第3章 if 文で場合を分ける」「第4章 for 文と while 文で繰り返す」「第5章 関数で処理に名前を付ける」「第7章 numpy の配列で数をまとめて扱う」「第8章 numpy で表の形を扱う」「第13章 勾配降下法で回帰する」
- 節: 第1〜6章のいまの題の型（「if文で条件によって処理を変える」）を全部に広げる
- 良い点: 名前でも、何をしたいかでも探せる。AI やプログラミングを知らない人にも題だけで何をするか分かる。いまの題の言葉を多く残せる
- 悪い点: 章の題が長い（「第」から数えて15〜19字）。左の欄（232px、1行およそ15字）で2行に折れる章が多い。運営の画面（`staff/index.astro`）は章の題を空白で2行に割っているので、長いと3行になる
- 過去の決定: 第25.5節（代表が「値を表示する」型を退けた）とは、章の題の言い回しが半分ぶつかる

### 案B「目次型の名詞」（章も節も。公式チュートリアル・東大の入門と同じ）

- 章: 「第3章 if 文による条件分岐」「第4章 for 文・while 文とリスト」「第5章 関数」「第7章 numpy の配列」「第8章 numpy の2次元配列と形」
- 節: 「if 文と比較演算子」「else」「elif」「and・or・not」「スライス」「ブロードキャスト」
- 良い点: 短い。探しやすい。練習問題集の見出し（第25.5節、代表の選択）と同じ型になり、教材と練習問題集の名前がそろう
- 悪い点: **節の題が「elif」「ブロードキャスト」だけになると、名前を知らない初めての人には何の節か分からない。** 「何をするか」の手がかりが消える。目次が文法の一覧に見える（`spec/30` 第1節の弱点と見た目がぶつかる）

### 案C「いまの題＋括弧で名前」

- 章: 「第3章 場合で分ける（if 文）」「第4章 繰り返す（for 文・while 文・リスト）」「第5章 まとめて名前を付ける（関数）」「第7章 数をまとめて扱う（numpy）」
- 節: 「条件で取り出す（ブールインデックス）」「並びを一度に作る（arange・linspace）」
- 良い点: 変える量が最小。Ctrl+F では見つかる。`spec/30` の見出しはもともとこの形（第7・8章）。本文やヒントの「第N章M節（題）」の引用もほぼそのまま読める
- 悪い点: **頭の言葉はいまのまま**なので、一覧を目で追うと、いまと同じく何の章か分からない（代表の「見返したときに何の章か分からない」が直らない）。章の題が長くなり（第4章は「第4章 繰り返す（for 文・while 文・リスト）」で20字）、括弧が並ぶ

### 推す案: 章は案B、節は案A（「章は目次、節は言葉＋何をするか」）

- **章の題**: その章で覚える Python の言葉か分野の名前を、**名詞で1〜3個**。「第N章 」を除いて**14字ほどまで**（左の欄で1行〜2行に収まる長さ）
- **節の題**: その節ではじめて出る **Python の言葉（構文・関数・メソッドの名前）か用語集の語を1つ以上入れ**、何をするかを短く添える。いまの第1〜6章の良い題（「if文で条件によって処理を変える」「スライスで範囲を取り出す」）の型。22字ほどまで
- 決まりの細部
  - 記号（`//` `%` `**` `@`）は題に入れず、名前で書く（第25.5節）。名前を添えるときは括弧で（「条件で取り出す（ブールインデックス）」）
  - 同じ題を2つ作らない。通し課題の節は「点数表を〈その章の道具〉で〜」の形にし、何を使って書き直す節かを入れる
  - いまの題に言葉が入っていて中身とずれていない節は**変えない**（108節のうち、変える案は49節。ホームの書き直しのあとにさらに2節）
  - 半角の語の前後の空白は、いまの置き場所の書き方に合わせる（章の題は「Python を」のように空ける、節の題は「numpyの」のように空けない）
- 推す理由
  1. 代表の指摘の中心は**章の題**で、章の題は畳んだ一覧・左の欄・公開の画面で、節より先に、しかも単独で目に入る。そこには短く、名前で探せる札が要る。公式チュートリアル・東大の入門・NumPy の入門は、どれも章に道具の名前を置いている
  2. 代表自身が、練習問題集の見出しで「何をするかの文」から「目次型」に直した（第25.5節）。章の題を同じ型にすると、教材と練習問題集の章の見出しがそろう
  3. 節は章の題の下で読まれるので、少し長くてもよい。名前だけ（案B）だと初めての人に分からないので、「何をするか」を残す。第1〜6章の多くはもうこの型で、変える量が少ない
  4. 案C は変える量が最小だが、頭の言葉が「場合で分ける」「数をまとめて扱う」のままで、代表が言う「見返したときに何の章か分からない」が残る
