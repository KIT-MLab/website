# 第6章 エラーを読む・直す　学習者読み（06-error）

読んだ節: 01-read / 02-syntax / 03-type / 04-logic / 05-scores（番号の順）。
`taught.mjs` は python-06-read で1回実行し、以降は読んだ節を足して考えた。

## 止まる（ここで学習者が進めなくなる）

無し。

## 引っかかる（進めるが、迷うか、分からないまま通る）

### L1（01-read）本文が「画面に出ないもの」を前提にしている可能性
- 場所: 「何行もの英語が出ましたが…」「そのあとに続く英語は、`avarage` のことではないかと聞いています」「その少し上に `line 3` とあります」
  なぜ: `<Run>` の `error` には `NameError: name 'average' is not defined` の1行しか書かれていない。画面が全文（Did you mean の行や `line 3` を含む）を出すなら一致するが、「N 行目で止まりました」という表示だけなら、「`line 3` とあります」「英語が聞いています」と画面が食い違い、学習者は「どこに書いてあるのか」と探す。
  案: 画面の実際の表示に合わせて、「`line 3`」を「3 行目で止まりました」に、「聞いています」の文を画面に出る形に揃える（出ないなら消す）。

### L2（01-read）「その名前が見つからないと言われています」までの理由が1段飛ぶ
- 場所: 「3行目は `average` を使っていて、その名前が見つからないと言われています。」
  なぜ: 学習者は「`average` は2行目で作った（はず）」と読むので、2行目の綴りが `avarage` だと気づく手順は最後の段落で初めて出る。「名前が見つからない＝それを作った行が別の綴りかもしれない」という筋は、あとの文を読めば分かるが、直前の文だけだと「作っていない」と言われた意味が一瞬取れない。進めはする。
  案: 「見つからない」の直後に「名前を作った行（2行目）の綴りを見てください」と足す。

### L3（01-read）課題の抜け道
- 場所: python-06-read-m1
  なぜ: 2行目の `mesage` を直す代わりに、3行目を `print(mesage)` に変えても通る（表示は同じ）。学習者が「止まった行を直す」と読んでしまうと、この抜け道のほうに行く。「止まった行と間違えた行は違うことがある」を確かめる問題としては弱い。
  案: 問題文に「3行目の `print(message)` は変えないでください」と足す（またはテストで確かめる）。

### L4（02-syntax）SyntaxError が先、とは書いてあるが、課題の最初の1つ目が何かは自分で当てる
- 場所: python-06-syntax-m1 のヒント1「直してからもう一度実行すると、次のエラーが出ることがあります」
  なぜ: starter には全角の `：`（3行目）、閉じていない `(`（4行目）、`itn`（2行目）の3か所がある。最初に出るのは全角 `：` の `invalid character`（本文の例と同じ形で分かる）。次の「`(` was never closed」のような文は、本文には「かっこの閉じ忘れ」と一言あるだけで、画面の実際の文面は見ていない。学習者は「どこが閉じていないのか」を4行目のあたりで探すことになり、迷う。最後の `itn` は NameError なので、2節目の `pirnt` の例で気づける。
  案: かっこの閉じ忘れの例の文面を本文に1つ出すか、ヒント2に「かっこの数を数える」を足す。

### L5（02-syntax）IndentationError は名前だけで、例が無い
- 場所: 「インデントの誤りもSyntaxErrorの仲間で、画面には `IndentationError` という名前で出ます。」
  なぜ: 名前だけで、どんな文面が出て何を直すのかを見ていない。第3章・第4章のインデントは習っているので意味は取れるが、05-scores の最初のエラー（`for` の中身がインデントされていない）は、この名前の説明だけで直すことになる。
  案: 05 の最初のエラー文面を02の説明に1行だけ出すか、05 のヒント1に「インデントの誤りもある」を足す。

### L6（03-type）ZeroDivisionError が1度も出ないまま、課題が割り算の0を扱う
- 場所: python-06-type-b1「2つ目が `0` のときは `計算できません` と表示してください」
  なぜ: 節の題と本文は TypeError / ValueError だけ。0で割ると止まる、という話はどこにも無い（第2章の `/` にも出ていない）。学習者は問題文の指示どおりに `if b == 0` を書けば通るが、「なぜ0のときを分けるのか」「分けないとどうなるのか」が分からないまま通る。
  案: 本文に「0で割ると `ZeroDivisionError` で止まる」と1文足す（または課題を TypeError/ValueError に合う題材に変える）。

### L7（03-type）ヒントがあいまい
- 場所: python-06-type-m1 のヒント「第1章でint()を使ったときの説明を見てください。」
  なぜ: どの節か分からない。ただ本文に `int()` で数に変える話があるので、進めはする。
  案: 「`score` を `int()` で数にする」と直接言う代わりに、「本文の1つ目の例と比べる」と書く。

### L8（04-logic）本文の「よくある間違い3つ」のうち2つは、画面にも例にも出ない
- 場所: 「条件の `>` と `>=` や向きの取り違え、`scores[0]` のように…、`return` の書き忘れです。」
  なぜ: 「向きの取り違え」が何のことか分からない（`<` と `>` のことだと読めるが、例は無い）。`return` の書き忘れは、書き忘れるとどう出るかを見ていない（`None` は未習。画面に `None` と出ても意味が取れない）。課題に使われるのは1つ目と2つ目だけで、`return` は課題にも例にも出ない。
  案: 「向き」を「`<` と `>` の取り違え」と書き、`return` の書き忘れは消す。

### L9（04-logic）m1 は、何を直すべきかが問題文だけでは決まらない
- 場所: python-06-logic-m1「`2` と表示されるように、直してください。」
  なぜ: starter は `value < 60` で 1 と出る。「60点以上を数える」という意図は問題文に無いので、`value < 60` を `value >= 60` にするか、`value < 80` にするか、`60` を `70` にするかなど、`2` になる直し方がいくつもある。どれもテストは通る。本文の例（25度以上）を見ている学習者は `>=` に気づくが、それは「推測」。
  案: 問題文に「60点以上の人数を数えるプログラムです」と足す。

### L10（04-logic）m2 のヒントは第4章の見直しを前提にしている
- 場所: python-06-logic-m2 のヒント「第4章のrange(len(...))の書き方を見てください。」
  なぜ: 第4章 03-index に `range(len(numbers))` の例があるので前提は合っている。ただ、starter が既に `range(len(scores))` を書いているため、直すのは `scores[0]` → `scores[i]` の1文字で、本文の「`scores[0]` のように同じ位置を取り出し続ける」にほぼ書いてある。考えることはほぼ0。
  案: 問題としては軽い。残すなら、starter を `for` なしの形にしてインデックスを自分で考えさせる。

### L11（05-scores）2つ目の壊れ（`input()` に `int` が無い）は、エラーが出る行と直す行が離れている
- 場所: python-06-scores-m1 の `scores = [input(), int(input()), int(input())]`
  なぜ: 出るのは `total = total + value` の行の TypeError（`'int' and 'str'`）。直すのは62行目。01節の「止まった行と、間違えた行は違う」は読んでいるが、「関数に渡った値が str だった」とたどるのは、課題の中で最も段差が大きい。ヒントは「いちばん下の行を読む」だけで、ここの助けにならない。
  案: ヒント1と2のあいだに「止まった行の値が、どこから渡されたかをさかのぼる」を足す。

## 要らない（消しても何も失わない文・問題）

- 場所: 01-read 冒頭「エラーが出ると、画面に英語の文が何行も並びます。すべて読もうとすると、どこが自分のミスなのか探すだけで時間がかかります。」
  なぜ: 次の「やってみる」と説明で「読む場所は2つだけ」と言うので、この文は無くても同じ。（ただし節の動機として弱く残してもよい。）
- 場所: 05-scores の `<Run>`（動く点数表）
  なぜ: エラーも壊れも無い完成形を見せているだけで、課題の「問題文の2行」と目で比べる材料にもなっていない（課題の出力は別の入力）。「第5章の完成形」を思い出す以外に使い道が無い。
- 場所: 05-scores 説明「この課題には、これまでの節で見た壊れ方が3つ入っています。」
  なぜ: 数を教えること自体は害が無いが、実際には「インデント」は見ていない（L5）ので、「見た」は少し言い過ぎ。残すなら「3つ」の数だけにする。

## その他の気づき

- `taught.mjs` の出力では 01-read の「この節で教える書き方」に `IndexError`（インデックスが範囲の外）が入っているが、01-read の本文にも課題にも IndexError は出てこない。台帳と本文がずれている可能性がある（学習者の側からは影響なし）。
- 02-syntax と 03-type のメタ情報の `terms: [SyntaxError, NameError]` などは、本文では語として使われている（問題なし）。
- 第4章・第5章の中身（`range(len(...))`、関数の `return`、`round`）は、教えた節のファイルの中身で確かめた。05-scores の `round`／`len`／関数呼び出しの入れ子は、第5章のとおりで学習者が見ている形。
