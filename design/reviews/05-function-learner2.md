## 引っかかる（進めるが、迷うか、分からないまま通る）

- L1（06-scores）: 場所: 困る例「第4章の点数表は、平均を `(scores[0] + scores[1] + scores[2]) / 3` と書いていました。」
  なぜ: 第4章の点数表（04-loop/06-scores）は `points[i * 3] + points[i * 3 + 1] + points[i * 3 + 2]` と書いている。`scores[0] + ...` という式はどこにも出てこない。学習者は「そんな式を書いたか」と戻って探す。
  案: 第4章の実際の式（`points[i * 3] ...`）の言い方に合わせる。

- L2（06-scores, python-05-scores-b1）: 場所: 課題「人数ぶんの3教科の点数を1人ずつ読み取り」
  なぜ: 1人ぶんの3つの点数をリスト `scores` にして関数に渡すところは、問題文に書かれていない。第4章のリストは、値を直接書く、または append で足す形だった。`[int(input()), int(input()), int(input())]` のように、リストの中で `input()` を呼ぶ書き方は初めての組み合わせ。append を3回書けば進めるが、「関数にはリストを渡す」ことは、例の `scores = [40, 55, 50]` から気づくしかない。
  案: 問題文かヒントに「3つの点数を1つのリストにして関数に渡す」と一言足す。

- L3（03-args, python-05-args-b1）: 場所: 課題の問題文「`score` が `border` 以上なら `"合格"`、そうでなければ `"不合格"` を返します。」
  なぜ: 入力欄も出力例も無い問題は、この章で初めて。それまでの組む問題は全部 `print` で表示していた。「返す」と書いてあるが、`print` するのか `return` するのか、`judge` を呼び出す側を自分で書くのかが、学習者には確信が持てない。ヒント2に `return` とあるので、読めば分かる。
  案: 「表示はせず、`return` だけ書けば足ります（呼び出す側は画面が行います）」を一言足す。

- L4（03-args）: 場所: 課題の解き方（if と else のそれぞれで `return` する）
  なぜ: `return` は2節で「ここで関数の実行は終わる」と言っただけで、if の中の `return` を見せた例が無い。`return "合格"` のように文字列を返す例も初めて（2節は数だけ）。ヒント2で気づけるが、書き方は自分で組み合わせる。
  案: 03 の例の `price_with_tax` とは別に、if の中で `return` する短い例を1つ足す。

- L5（02-return）: 場所: 「ここで関数の実行は終わり、それより後の行には進みません。」
  なぜ: 例も課題もこの性質を使わない（課題の模範は最後に1回 `return` するだけ）。言われても、確かめる場面が無く、分かったかどうか分からないまま通る。L4 の例を足すなら、ここがその役になる。
  案: L4 と合わせて、`return` の後ろの行が実行されない例を入れるか、この一文を消す。

- L6（02-return, python-05-return-b1）: 場所: 「`max` は使わないでください。」
  なぜ: 学習者は `max` を習っていない。「使わないで」と言われて初めて、そういう物があることを知る。第4章2節にも同じ文があるので、そこで見かけていれば問題ない。
  案: 第4章2節で `max` を見ているなら、そのままでよい。

- L7（01-def, python-05-def-b1）: 場所: 「`a` と `b` の2つです」「引数の名前」
  なぜ: 第1章では「引数」は関数に渡す値だった。この節で `()` の中の名前（a, b）も「引数」と呼ぶ。同じ語が、関数を作る側では名前、呼ぶ側では値を指す。課題の模範では、呼び出す側の変数も `a` `b` で、関数の引数と同じ名前になるため、「同じ a なのか別なのか」と迷う（スコープは5節まで出ない）。
  案: 「定義のかっこの中の名前」と「呼ぶときに渡す値」を、1文で書き分ける。

- L8（01-def）: 場所: 説明全体
  なぜ: 「定義しただけでは何も実行されない。呼び出して初めて2行目が動く」ことは、「呼び出すたびに実行されます」と間接的に書かれているだけ。定義の前に呼び出すと動かない、という順序も書かれていない。課題 b1 で関数の前に呼び出しを書いてしまう人が出る。
  案: 「定義の行では何も表示されません。呼び出した行で初めて動きます」を足す。

## この節は何のためにあるか（学習者の言葉で一文）

- 01-def: 同じ計算を何度も書かずに、名前を付けて呼ぶ方法。
- 02-return: 関数の結果を画面に出すだけでなく、変数に取って次の計算に使う方法。
- 03-args: よく使う値を引数に初めから決めておき、必要なときだけ変える方法。
- 04-keyword: 引数に名前を付けて渡すと、順番を間違えず、途中を飛ばせる。
- 05-scope: 関数の中で作った変数は外に出ない。外に出したいときは `return` で持ち出す。
- 06-scores: これまでの点数表を、合計と平均の2つの関数に分けて書き直す。

## 補足（節をまたいだ所見）

- 04-keyword と 05-scope は、組む課題が無く（nobuild）、どちらも「modify」1問だけ。学習者の側からは、どちらも starter を少し直すだけで通り、自力で組む負荷は 01〜03・06 より小さい。段差は無い。
- 数値例（1100.0、1200.0、1600.0、100.2、48.3）は、読んで追った限り矛盾が無い。
