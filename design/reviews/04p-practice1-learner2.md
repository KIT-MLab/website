## 節1: 01-combine「組み合わせる」（python-04p-combine）

### 止まる（ここで学習者が進めなくなる）
無し。どの問題も、教えた書き方だけで最後まで書ける。

### 引っかかる（進めるが、迷うか、分からないまま通る）

- L1（節1）場所: `python-04p-combine-b2` のヒント2「第3章2節（elseで当てはまらない場合を書く）を参考にしてください。」
  なぜ: この問題の解き方に else は要らない（`if i % 3 == 0 or i % 7 == 0:` だけで数えられる）。学習者は else を探して「else のときに何をするのか」で迷う。実際に要るのは「or で2つの条件をつなぐ」（第3章4節）と「range の終わりを n+1 にする」（第4章1節）。
  案: ヒント2を、第3章4節（and・or・not）と第4章1節（for文）に差し替える。

- L2（節1）場所: `python-04p-combine-b2` の `for i in range(1, n + 1):`
  なぜ: 例では `range(1, 4)` のように数が書いてあるだけで、`n + 1` のように式を渡す例は第4章に無い（`range(len(numbers))` は式を渡しているが、「1つ大きくする」は 04-for の課題 b1 のヒントにしか無い。ヒントを開かなかった学習者は見ていない）。問題文も「1 から n まで」としか言わないので、`range(1, n)` と書いて、n が数えられずに落ちる。ヒント1は「余りで確かめる」だけで終わっている。
  案: ヒントに「range の終わりの数は含まれない」と一言足す。または節の「はじめに」で触れる。

- L3（節1）場所: `python-04p-combine-b1`（while の中の `int(line)`）
  なぜ: 04-while の例は `line` を文字のまま扱うだけで、整数に直す行が無い。この問題では `終わり` を比べたあとで `int(line)` にしなければならないが、ヒントも問題文もそれを言わない。`price = int(input())` と書く学習者が多く、`終わり` で整数に直せずエラーになる。エラーの意味は第6章まで習っていないので、原因にたどり着けない。
  案: ヒント1に「終わりかどうかを比べるのは、整数に直す前」と足す。

- L4（節1）場所: `python-04p-combine-b3` のヒント2「第4章3節（インデックスとlen()）」
  なぜ: 前の値を変数に残していく書き方（`prev = x` を繰り返しの最後で入れ直す、第1章の「入れ直す」だけで書ける）でも通るので、インデックスを使わずに解ける。ヒント1が「1つ前のインデックス」と方法を決めてしまっているが、問題文は方法を指定していない。迷うほどではない。
  案: 変えなくてよい。直すなら、ヒントを「リストに集めてから比べる」と「前の値を覚えておく」の2通りにする。

- L5（節1）場所: `python-04p-combine-b4` のヒント1「受け付けた値だけをリストに集めておくと」
  なぜ: リストに集めるより、合計と個数の2つの変数で数えるほうが書き方が短い（どちらも教えた書き方）。ヒントがリストのほうを選ばせるので、学習者は `for value in accepted` で合計を出すもう1回の繰り返しと、`total / len(accepted)` まで書く。段差が大きくなる。通れるが、自分の選んだ書き方ではなく、ヒントに引っ張られる。
  案: ヒントを「リストに集める」か「合計と個数を持つ」かの2つにするか、リストの方法を残すなら理由を書く。

### 要らない（消しても何も失わない文・問題）
- 場所: 「ここまでに習ったことだけで解けます。どれを使うかは自分で決めてください。」の前半
  なぜ: 節の位置づけを繰り返すだけ。後半の「困ったら、下のヒントを開いてください」だけ残れば足りる。小さい。

## 節2: 02-choose「手を選ぶ」（python-04p-choose）

読む前に、節1までを読み終えたものとして考えた。節1で出た書き方は、そのまま持っている。

### 止まる（ここで学習者が進めなくなる）
無し。ただし L6 は止まる寸前。

### 引っかかる（進めるが、迷うか、分からないまま通る）

- L6（節2）場所: `python-04p-choose-b1`（全体）
  なぜ: この節の中でいちばん段差が大きい。学習者が1問の中で自分で組み立てるのは、
  (1) 最初の予想を while の前に先に読む（04-while の例と同じ）、
  (2) 回数を数える変数を、最初の予想を読んだときにも増やす（while の中だけでは、最初の1回が数えられない。模範解答は while の前後に `count = count + 1` を2か所置いている）、
  (3) `正解と同じ` を while の条件にする（`line != "終わり"` は文字と文字列の比べ、ここは変数どうしの比べ。形は同じだが、「終わり」の判定という見慣れた形から離れる）、
  (4) 4通りの表示を、elif で並べる、
  (5) 「差が10以内」を、大きい側と小さい側で別に書く（差の絶対値は教えていないので、`guess - answer <= 10` と `answer - guess <= 10` の2つに分けるしかない）。
  特に (5) は、`guess - answer <= 10` だけで「大きい側も小さい側も」判定しようとして、小さい予想がすべて「少し小さい」になる間違いが起きやすい。ヒント1の「予想と正解の差で決まります」は、この点を助けない。
  案: この問題を2問に分ける（先に「大きい／小さい／当たり」だけ、次に「少し」を足す）。または「少し」の判定を「大きい側と小さい側で別々に考える」とヒントで言う。

- L7（節2）場所: 節の冒頭「解き方は1つではないので、自分で選んだ書き方で書いてください。」と節の題「手を選ぶ」
  なぜ: 学習者は、どの問題で何を選べるのかが分からない。b1 と b2 は、ほぼ1通りの解き方しか見えない（b2 は `//` と `%` で、ヒント2がそれを指している）。選べるのは b3 くらいで、しかもその b3 は `reversed` と `[::` を禁止している（学習者は `reversed` も `[::` も習っていないので、禁止されても何のことか分からない。禁止の理由を画面で説明していないなら、エラーの意味が分からないまま止まる）。
  案: 「選ぶ」の中身を、どの問題でどれとどれから選ぶのか、一言で書く。または、題と冒頭を、問題の中身に合わせて「少し難しい組み合わせ」程度に直す。

- L8（節2）場所: `python-04p-choose-b3` のヒント1「前から数えた位置と、後ろから数えた位置を、それぞれインデックスの式で表します。」
  なぜ: 03-index の例は `numbers[len(numbers) - 2]`（後ろから2番目）。i 番目の反対側が `n - 1 - i` になる、と式にするところは、学習者が自分で作る（`n - i` と書いて1つずれる学習者が出る）。「後ろから数えた位置」が `len - 何か` になることは例で見たが、`何か` が `i + 1` になるのが分からない。テスト3（`3, -1, 0, -1`）の「真ん中の値」のずれもここで出る。
  案: ヒントに、`n = 5` のときの i=0 の相手が何番かを1つだけ書く（式そのものは書かない）。

- L9（節2）場所: `python-04p-choose-b2` のヒント1「合計の分を、60で割った商と余りに分けます。」
  なぜ: 03-operators に「秒数を分と秒に分けるときなど、`//` と `%` はよく組み合わせて使います」とあり、そのまま答えになっている。迷う余地が無い。
  案: ヒント1を削って、ヒント2だけにする。

### 要らない（消しても何も失わない文・問題）
- 場所: `python-04p-choose-b2` のヒント1の「合計の分を、60で割った商と余りに分けます。」
  なぜ: 上の L9。03-operators の「秒数を分と秒に分けるとき」と同じことを言い直しているだけ。
