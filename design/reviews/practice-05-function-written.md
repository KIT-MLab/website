## 迷った所・本体に確かめること

1. **関数を書いたことの確かめ方。**
   - `return` と `args` の `call` 形の問題（return 全5問、args-1〜3）は、`kind: 'call'` で関数名を指定して呼ぶので、**関数が定義されていないと落ちる**（確かめられている）。
   - `def` は、`return` をまだ教えていないので、戻り値を比べる `call` が使えない（`print` する関数の戻り値は `None` で、`call` は表示を比べない）。**stdout だけで判定している。** そのため `def-1〜5` は、関数を定義せずに直接 `print` を書いても通ってしまう。問題文に関数名と引数を書き、「その値を渡して、この関数を呼び出します」と書いて頼むだけにした。判定の仕組みでは直せない（`_cross.md`「採らない指摘」の仕組みの限界に近い）。直すなら、ソースに `def 名前(` が含まれるかを見る `require` のような指定が要る（いまは `forbid` だけ）。
   - `args-4`（キーワード引数）も同じで、`meals=` で渡したかは判定できない（教材 5-4 の `nobuild` と同じ理由）。ただし、`trip_cost(fare, meals)` と名前なしで渡すと `nights` に入って出力が変わるので、**飛ばして渡すつもりで間違えた書き方は落ちる**。`fare + meals * 1000` と直接書けば通る。
   - `args-5` も、`points` を定義せずに式で書いても通る（stdout）。
2. **`call` 形の `<Input>`。** 3.11節の例どおり「関数に渡す引数です。入力欄は使いません。」と書き、引数を箇条書きにした（今週の演習 10/13 b1 と同じ形）。
3. **args-2**: 文字列を返す。`greeting` が空文字列のケースを入れた（`山田さん`）。「空」の境界のつもり。
4. **def-4 と return-4 の境界**: 検査5が 0・負・同値・空の組を要求したので、`minutes` を「0以上」にして 0 を足した（def-4 は 0 → `半熟`、return-4 は 0 → 0円）。7分・10分・30分の境目も入れてある。
5. **def-5 の入力**: 「前の週の高さと同じか、それより高い」と明記して、伸びが負にならないようにした。1週のケースと伸び0のケースがある。
6. **return-5（`digit_sum`）**: `n` が `0` のときは while に入らず 0 を返す。数の桁を取り出すのに `str` を使う書き方は未習。
7. **return-3（`arrangements`）**: 0人のとき1通り、と問題文に書いた。「階乗」という語は使っていない。
8. **args-1 の題材**: 面積と体積は無理のない題材だが、`dim` を「掛け合わせる回数」とだけ書いたので、少し数学的。直すなら題材を替えてほしい。
9. `report:practice` の「寄りすぎ」は「関数を作って値を返す（def・return）」。第5章の中心の書き方なので、そのままにした。
10. ヒントの節参照（第5章1節の最初のコード、3節の最初のコードの4・5行目、4節の最後の `print` など）は、節を開いて確かめた。第1章5節（f文字列）、第2章3節（`//` と `%`）、第3章2節（`% == 0`）、第3章3節（elif）、第4章1節・5節も、節の題で確かめた。
11. 検査の結果: `check:practice` は第5章に不合格なし。`04-loop/while.mdx:89` の「入力欄が足りません」は別の人が書いている所なので触っていない。
