## 引っかかる（進めるが、迷うか、分からないまま通る）

- L1（01 / python-08p-combine-b3）
  場所: 「3日の合計の歩数がいちばん多い人を求めてください」と模範解答の `best = 0` / `best_total = totals[0]` / `for i in range(n): if totals[i] > best_total: best_total = totals[i]; best = i`
  なぜ: 教えたのは第4章2節の「いちばん大きい値を探す」で、残すのは**値だけ**（`largest`）。**何番目か**も一緒に残す書き方、`range(n)` で回して `totals[i]` で配列の位置を指す書き方は、まだ見ていない（`range(len(numbers))` と `numbers[i]` は04-index にあるが、配列 `totals` ではない）。自分で考えることは、①1列に読んで reshape（`range(n * 3)` も初めて）②`sum(axis=1)` ③最大探しに位置の変数を足す ④同点なら先、の4つ。3つを超えている。ヒント1が③④をほぼ言っているので、ヒントを開かない人はここで長く止まる。
  案: 位置つきの最大探しを、この章の前のどこかで1問だけ先に出す（04p-practice1 で済んでいるならそこを指す）か、この問題の読み取り＋reshape を `starter` にして、考えることを2つに減らす。

- L2（01 / python-08p-combine-b2）
  場所: 「税込みの値段を整数に丸めて返す関数 `with_tax(price, rate=0.1)`」
  なぜ: 税込みの式（値段×(1＋税率)）が問題文のどこにも書いていない。学習者は `rate=0.1` から「1.1倍だろう」と推測する。通る人が多いが、`price * rate` を足すのか、`price * (1 + rate)` なのかは、問題文だけでは確定しない。丸めに `round` を使うことも「整数に丸めて」から読み取る（`round(2.7)` は第2章で教えてある）。
  案: 「値段×(1＋税率) を整数に丸める」と1句足す。

- L3（01 / python-08p-combine-b4）
  場所: 模範解答の `row = table[i, :]` と `for i in range(d)`、問題文「日ごとに…何日目か」
  なぜ: `scores[1, :]` は08-index にあるが、`i` を変数にして1行ずつ取り出す形は初めての組み合わせ。ヒントが「行のインデックスで1日ずつ」と言っているので進めるが、`table[i]` でも通ることは分からないまま通る人がいる（08-reshape の課題に `table[1]` がある）。通らなくなる原因にはならない。
  案: 直さなくてよい。

- L4（02 / python-08p-choose-b1）
  場所: 模範解答の `for i in range(n - 2): window = arr[i:i + 3]`
  なぜ: 07-slice で教えたのは `scores[:k]` のように「数の入った変数」までで、`arr[i:i + 3]` のように**式**を書く形は見ていない。`range(n - 2)` の `n - 2`（何個ずつずらせるか）も自分で数える必要がある。問題文の「5つなら3行になります」が助けになるので止まりはしないが、`range(n - 3)` や `range(n)`（最後で範囲外を取って平均が小さくなる）の書き間違いが出やすい。
  案: 問題文の例（5つなら3行）は残し、ヒントに「何行出るかを個数 n で表す」の1句を足す。

- L5（02 / python-08p-choose-b2）
  場所: 模範解答の、`if row[1] < low:` と `if row[2] < low:` を `elif` でなく別々に並べる3つの比べ方
  なぜ: 教えた「最大を探す」は `for` で回す形で、3つを `if` で順に比べて位置と値を一緒に更新する形は初めて。`elif` でつなぐと、`row[2]` が `row[0]` より小さいが `row[1]` より大きいときに壊れるが、その理由は教えていない。ヒントは「if文で1つずつ比べて」とだけ言う。
  また、いちばん安い店の番号を探すこの問題は、01 の b3（最大の人の番号）と同じ型で、向きが逆になっただけ。
  案: b3 と b2 のどちらかを減らすか、b2 を「平均との差」だけの問題にして、番号を探す部分を b3 に任せる。

- L6（02 / python-08p-choose-b3）
  場所: 模範解答 `np.round(table / table.max(axis=0) * 100, 1)`
  なぜ: ブロードキャストは08-broadcast で**引き算だけ**教えた。「配列÷1次元の配列」と「配列×100」は、同じ仕組みだとヒントが言うだけで、学習者は見ていない。`table.max(axis=0)` は07-stats の「sum・max・min にも axis」で足りる。`np.round` を2次元の配列に使うのも、教えたのは1次元の例だけ。配列を関数の引数に渡して返す形も初めて（第5章は数だけ）。
  案: ヒントに「引き算と同じ形で割り算もできる」と1句足すか、直さずこの問題で気づかせる。どちらでもよい。

- L7（02 / 節の「はじめに」と3問のヒント）
  場所: 「解き方は1つではないので、自分で選んだ書き方で書いてください」
  なぜ: 節の題が「手を選ぶ」なのに、3問とも、ヒント1がやり方を決めてしまっている（b1 はスライス、b2 は if で1つずつ、b3 は max(axis=0) とブロードキャスト、関数名と print の回数まで指定）。ヒントを開かない人には選べるが、開くと選ぶ余地が無い。b1・b2 は別の道（`arr[i] + arr[i+1] + arr[i+2]`、`row.min()` と `==`）でも通る。
  案: ヒントから手段の指定を減らし、何を使うかは節の初めの一覧に回す。または題と「はじめに」を「手を決められた問題」に合わせる。

## この節は何のためにあるか（学習者の言葉で一文）

- 01 組み合わせる: 「第1〜8章で別々に習った書き方を、1つの問題の中で混ぜて使えるか試す」。b3 だけ、混ぜる数が多い。
- 02 手を選ぶ: 「同じ種類の問題を、スライスやブロードキャストなどの別の書き方で解く」と言えるが、ヒントが手を決めているので、「手を選ぶ」とは学習者は言いにくい（L7）。
