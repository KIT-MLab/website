# 第3章 学習者の目での通し読み

対象: `src/content/lessons/03-branch/`（01-if 〜 05-scores の5節）。`taught.mjs` は `python-03-if` で実行。
読んだ立場: Python を知らない大学1年。教わったのは第0〜2章と、この章で先に読んだ節だけ。

## 止まる（ここで学習者が進めなくなる）

無し。

## 引っかかる（進めるが、迷うか、分からないまま通る）

- L1（02-else） 場所: 説明の「3行目の `else:` は…」「4行目の `print("不合格です")` は…3行目のifと同じ深さのインデント」
  なぜ: 例のコードは5行（1 score、2 if、3 print合格、4 else、5 print不合格）。else は4行目、不合格の print は5行目なのに、文は1行ずつ手前にずれている。「3行目」を見ると `print("合格です")` で、「else:」の説明と合わない。さらに「3行目のif」は、if が2行目であることとも合わない。インデントの深さを教える肝心の文で迷う。
  案: 行番号を4行目・5行目に直し、「3行目の `print` と同じ深さ」と言う。

- L2（01-if） 場所: 課題 `python-03-if-m2`「if文を1行足してください」
  なぜ: if文は `if …:` と中身の `print` の2行になる。「1行」と書かれていて、学習者は1行で済ませようとして迷う。さらに `number = 0` は固定で、テストは `stdout` だけなので、`print("0です")` を1行書くだけでも通る（if文も `==` も使わずに済む）。
  案: 「2行足す」に直し、`number` を変えた別の入力でも確かめる（`number` を入力にする、または starter を `number = int(input())` にして複数の stdin で試す）。

- L3（01-if） 場所: 比べる記号の表の `==`
  なぜ: 学習者は `=` を「名前に値を結び付ける」と習っている（第1章）。`==` が `=` とどう違うのか、`if x = 5:` と書いたらどうなるのかが、どこにも出てこない。表で読み方だけ示され、つまずきやすい点が放置されている。
  案: 表の下に「`=` は変数に入れる、`==` は等しいか比べる。別の記号」と1文足す。

- L4（04-andor） 場所: `not` の Run（`if not (score >= 60):` … else …）
  なぜ: この例は、直前の節の `if score >= 60: … else: …` を逆に書いただけに見える。`not` を使う理由（`score < 60` と書けばよい、ifとelseの入れ替えでもよい）が分からないまま、書き方だけ覚えることになる。また課題で `not` を使う問題は1つも無い（m1・m2・b1 すべて、`not` を使わなくても通る）ので、書けるようになったかどうかは確かめられない。
  案: `not` が要る場面（たとえば「A か B のどちらかが成り立つ、の逆」を `not (A or B)` と書く）の例にするか、課題に `not` を使う問題を1つ入れる。

- L5（04-andor） 場所: 課題 `python-03-andor-b1`
  なぜ: 無料・学生料金・通常の3区分は、`and`／`or` を使わなくても `if age >= 65 … elif age >= 19 … elif age >= 13 … elif age >= 6 … else` のように、elif だけで（無料の print を2回書いて）通せる。この節で教えた `and`／`or` を使ったかどうかは確かめられない。ヒントで「1つの条件にまとめられます」と言い切っているので、実際に使う人は多いが、抜け道は残る。
  案: テストでは確かめにくいので、気にしないなら放置でよい。確かめたいなら「`or` を使って」と問題文に書く。

- L6（05-scores） 場所: 説明の末尾「`average` の値そのものは、ifの中でもelseの中でも変わりません。」
  なぜ: 学習者は「変わる」と疑っていないので、なぜここで言うのかが分からない。直前の文（`threshold` を変えれば合格ラインが変わる）ともつながらない。何を伝えたい文なのか読み取れず、誤解を生むかもしれない。
  案: 消す。

- L7（05-scores） 場所: 課題 `python-03-scores-b1`「平均に続けて1行で表示します」
  なぜ: 出力の形（`平均72.3点 合格` の「点」と空白）は、問題文に書かれておらず、上の Run を見て真似るしかない。画面に出力例が出ていれば進めるが、文章だけでは「平均72.3 合格」など別の形に書いてしまいそう。
  案: `<Output>` に「出力例のとおり」と書く、または形を1行例示する（第2章 scores と同じ）。

- L8（05-scores） 場所: 課題 `python-03-scores-m2`「`平均59.7点 不合格` と表示されるように、`english` の値を決めてください」
  なぜ: 59.7 になる `english` を逆算するには、(60+60+x)/3 を丸めた結果から x を探す必要がある（x=59 で 59.666…→59.7）。ヒントが空で、暗算か試行錯誤になる。進める人は進めるが、この節で教えたことの確かめにはなっていない（if の分岐ではなく、逆算を問うている）。
  案: ヒントを足す（「▶ を押して平均を見ながら値を変える」）か、`threshold` を動かす問題にする。

## 要らない（消しても何も失わない文・問題）

- 場所: 05-scores の説明「判定に使うのは、5行目で計算した `average` の値です。」
  なぜ: 直前の「`if average >= threshold:` は…平均が基準点以上かどうかを判定します」の言い直し。
- 場所: 02-else の説明の最後「ifとelseは片方しか動かないので、`合格です` と `不合格です` が同時に表示されることはありません。」
  なぜ: 前の段落の「2つの処理のどちらか一方だけが実行されます」の言い直し。
- 場所: 各節の最後の段落の前半（01「条件が成り立つときだけ動くif文が書けました」、02「成り立たなかったときの処理も書けるようになりました」、03「elifで3段階以上に分けられるようになりました」、05「点数表に合否を付けられるようになりました」）
  なぜ: 節の題の繰り返し。後半の「次の節では…」だけで足りる。
- 場所: 課題 `python-03-if-m1`
  なぜ: 数を変えるだけで何も書かない。条件が成り立たないときは何も出ない、という点は、b1 の3つの if のうち成り立たない2つが同じことを確かめている。

## 各節は何のためにあるか（学習者の言葉で一文）

- 01-if: 「点数が60以上なら」のように、条件が成り立つときだけ実行する行を書けるようになる。
- 02-else: 条件が成り立たないときの別の行を書けるようになる。
- 03-elif: 2つでなく3つ以上に場合分けできるようになる。
- 04-andor: 「60以上かつ80未満」のように条件を1つにまとめて書けるようになる。（`not` は何のために要るかまで言えない。L4）
- 05-scores: 前の章の点数表に、合格・不合格を付けられるようになる。

## 補足（引っかかるほどではないが）

- 01-if の b1 は、負の入力 `-4` を `int()` に通す。第1章では `int("5")` しか見ていない。通るので止まらない。
- 01〜03、05 の m 問題は、ほとんどが「値を変えるだけ」で、考えることが0。段差は小さいが、b1 との段差（02 の `%`、04 の3区分）が相対的に大きい。
