## 重い順の指摘

### R1 logic-4「うるう年の判定」: ★2 だが、この章でいちばん重い。規則3つを1つの式に訳す所で止まる
- 何で止まるか: 自分で考えることが3つある。(a) 4・100・400の3つの「割り切れるか」を `%` で書く。(b) 「ただし」「それでも」を読んで、3つの規則が前のものを打ち消していく順だと分かる。(c) それを `A and (B or C)` の式にする（または `elif` を3つ並べて書く）。(b) は問題文が「1〜3で決まります」としか言わず、順に優先するのか3つとも満たすのかが決まらない。3つとも満たすと読むと `and` でつないでしまい、2024・2000・2400で落ちる（確認ずみ）。
- 抜け道: かっこ無しの `y % 4 == 0 and y % 100 != 0 or y % 400 == 0` も、`elif` 4本の連鎖も全入力で同じ答えになる。これは問題ではない。
- 案: (1) 問題文を「次の1〜3を、番号の大きいものほど優先して決めます」のように、あとの規則が前を上書きすると分かる文にする。(2) 重さを合わせるなら ★3 に上げ、logic-5 を ★2 に下げる（R3）。ヒント1の「最後のコード」は、模範解答と同じ形 `A and (B or C)` で、写せば通る。ヒントとしては正しく、この問題の考える所は (b) に残る。

### R2 if-3「偶数と奇数で計算」: `/` で書くと `3.0` が出て落ちるが、問題文もヒントもそこに触れない
- 何で止まるか: 「2で割った商」と読んで `n / 2` と書くと `3.0` と出る（`6 / 2` は 3.0。第2章1節で教えたが、「商」を `//` と結び付けるのは学習者任せ）。出力の説明は「計算した結果の数だけ」で、整数とは言っていない。落ちたあと、何が違うのか分からない。ヒントは偶数の調べ方しか言わない。
- 案: 出力の説明を「計算した結果の整数だけを1行で表示します」にする。または問題文の「割った商」を「割った商（小数点以下を切り捨てた整数）」にする。ヒントに「商を求める記号は第2章3節にあります」と足してもよい（`//` を直接は言わない）。

### R3 logic-5「授業の成績判定」（★3）は、logic-4（★2）より軽い。★の順に段差が上がっていない
- 重すぎはしない。規則が番号つきで「上から順に確かめ、最初に当てはまったものを表示」と書いてあり、そのまま `elif` 4本に写せる。考えることは (a) 1番の「または」を `or` に訳す (b) 2番の「欠席が0回」を `== 0` と書いて `and` でつなぐ、の2つ程度。3つ目の「順に確かめる」は問題文が先に言っている。
- 順を間違えると（`>= 60` を先に書くなど）、95,0 / 90,4 / 80,0 の3つのケースで落ちる。判定は順の誤りを捕まえている。
- 案: 段差を直すなら logic-4 と logic-5 の ★ を入れ替える（logic-4 を ★3、logic-5 を ★2）。順を入れ替える場合は `level` と `name` の並びだけ。

### R4 logic-5 のヒント「4つの結果が、強いものから順に並んでいます」の「強い」が分からない
- 何で止まるか: 結果は 不合格・優秀・合格・追試 の順で、どれが「強い」のか決まらない（不合格が最初に確かめられるのは、強いからではない）。「強い」を手掛かりに順を決めようとして迷う。
- 案: 「問題文の1〜4は、上から順に確かめる決まりです。最初に当てはまったものを表示する形は、第3章3節の `elif` です。」にする（「強い」を消す）。参照の「第3章3節の `elif`」は合っている。

### R5 if-5「勉強時間の表示」ヒント1「時間と、それを引いた残りの分に分けます」の「それ」が指すものが取れない
- 何で止まるか: 「それ」が時間なのか分なのか決まらない。「時間を引いた」は、時間ぶんの分を引くという意味に取らないと読めない。続く「`//` と `%` を使います」で救われるが、`//` と `%` が別々の値（時間と残りの分）を作ると、つながらないまま通る人がいる。
- 案: 「60分以上のときは、60で割った商が時間、余りが残りの分になります。第2章3節の `//` と `%` を使います。」にする。
- 補足: `else` の中に行が2本以上並ぶ（`hours = ...` `rest = ...` `print`）形は、第3章の例には出ない（`else` の中身はどれも1行）。インデントの説明（「if文の中身であることを示す」）から類推できるが、初めての組み合わせ。

### R6 elif-5「買い物の支払い」: `if` の中で変数に入れ、`if` の外で使う書き方が、どこにも出ていない
- 何で止まるか: 模範解答の `fee = 0 / fee = 300 / fee = 600` を `if` の分岐の中で作り、`print(total + fee)` を `if` の外で使う形は、第3章の節・例に無い（節の例はどれも分岐の中で `print` する）。ヒント2「送料を変数に入れておくと」でそれを言っているが、「分岐の中で入れて、外で使う」とは言っていない。
- 抜け道（正解になる）: 3つの分岐それぞれの中で `print(0)` / `print(total)` のように書く。分岐の数だけ長くなるが通る。
- 自分で考えること: (a) `price * count` を先に求める (b) 段階を `total` で分ける (c) 送料を後で使えるようにする、の3つで ★3 に合っている。
- 案: 段差は妥当。ヒント2を「分岐のそれぞれで `fee = ...` と入れておくと、`if` の外で `fee` を使えます」に、というより、ヒントを1つにして答えを言い過ぎないようにしたいなら、ヒント2を「`if` の外でも、`if` の中で入れた変数は使えます」の一文にする。

### R7 elif-3「荷物の料金」: 節の説明と逆の順序を、ヒントが勧める
- 節（第3章3節）は「そのため、高い方から順に書きます」と教える。この問題のヒントは「小さいほうから順に条件を並べると、どの条件でも「以下」で書けます」。学習者は節に従い、高いほうから `> 500` / `> 250` / `> 100` と書き、それでも正しく通る（確認ずみ）。ヒントが勧める順と違っても通るので、止まりはしない。ただし「節の説明とヒントのどちらが正しいのか」で一瞬迷う。
- 案: ヒントを「条件は、重さが小さいほうから順に並べても、大きいほうから順に並べても書けます。どちらの順でも、境の値（100、250、500）がどちらの段に入るかに気をつけます。」にする。

### R8 logic-4 のテストに `2024` が2回ある（先頭と末尾）
- 学習者の目には、コード欄の下のテストケースの入力が同じものが2つ並ぶ。落ちたときに、どちらも同じ入力で戸惑う。
- 案: 最後の `2024` を消す（他に 1900・2000・2100・2400・2023・2022 があり、確かめるものは足りている）。

### R9 logic-2「土日は休み」: `day == 0 or 6` と書く間違いが、節で扱われていない
- 節（4節）が警告するのは `and` の右側を省くこと（`score >= 60 and < 80`）だけ。`or` で `day == 0 or 6` と書くと、エラーにならず、いつも「休みです」と出る。出力を見ても、何が悪いのか分かりにくい。ヒント「2つ目のコード」（`score < 0 or score > 100`）は左右とも条件を丸ごと書いているので、見比べれば気づける。止まりはしない（ヒントで足りる）。
- 案: 直さなくてもよい。直すなら、ヒントを「どちらか一方でも成り立てばよいときの書き方は、第3章4節の2つ目のコードを見てください。`or` の左右にも、条件を丸ごと書きます。」にする。

## 読み終わってから

### 題材の重なり
- **if-1「送料無料」と elif-5「買い物の支払い」は、どちらも通販の送料。** 別の問題として読めるが、題材が近い。elif-5 の題材を、送料以外（たとえば入場料の割引）に替える手もある。`design/spec` を読んでいないので、替える必要があるかは判断しない。
- 気温が3回: 教材の3節の例、elif-4、logic-3。
- 「2つの数を読んで比べる」手順が if-4 と elif-4 と logic-3 で似る（読み方は同じで、if-4 は大小、elif-4 は3通り、logic-3 は `and`）。同じ問題ではない。
- if-1 と if-2、logic-1 と logic-2 は、それぞれ ★1 の「条件を1つ書いて2通りに分ける」で、手順がほぼ同じ。確かめるものは違う（`>=` と `==`、`and` と `or`）ので、どちらかを消す理由にはならない。

### 節の課題とそっくりな問題
- elif-1 は第3章3節の `python-03-elif-b1`（点数5段階）と、手順が同じで段数が3に減っただけ。★1 なので許容。ヒントも「3節で見た気温のコード」を指すので、写せば通る。
- logic-1 は第3章4節の1つ目のコード（`score >= 60 and score < 80`）の値と名前を替えただけ。★1 なので許容。
- logic-4 は第3章4節の最後のコード（`A and (B or C)`）と同じ形（R1の案参照）。
- if-1 は第3章1節の最初のコード（`score >= 60` で合格）と同じ形。
- 同じ手順の問題が2つ、という問題は無い（if-2 と logic-2 は `==` を使う点が同じだが、後者は `or`）。

### 日本語（reader-japanese の目で）
- 引っかかる文: if-5 ヒント1（R5）、logic-5 ヒント（R4）。
- 問題文・入出力の説明は、全問で意味が取れる。「うるう年」の書き方は一貫。「欠席」「追試」「送料」は1年生に通じる。
- 番号つき・箇条書きの読みやすさ: elif-3・elif-5（金額・重さの段）は、`<Input>` の前に置かれていて読みやすい。logic-4・logic-5 の番号つきは、文頭の「次の1〜3で決まります」「上から順に確かめ」が効いている。logic-4 は R1 の点だけ足りない。

### 入力の範囲（負の数・0）
- 問題文が範囲を言っていないのにテストにある入力: if-2 の `-7`、logic-1 の `-4`（ともに「整数」と書いてあるので、負の数は範囲内）、logic-3 の `-5`（気温は整数）、elif-4 の `-3 -5`。どれも「整数」に収まる。範囲を言っているのに外れる入力は無い。
- 0 は if-1・if-3・if-5・elif-1・elif-3・elif-5 で出る。どれも「0以上」と書いてある。
