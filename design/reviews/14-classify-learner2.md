## 1節 01-label「合格の割合を確率とみなす」

### 止まる
無し

### 引っかかる
- L1 場所: 題「合格の割合を確率とみなす」と、課題 python-14-label-b1「続けて、合格の割合を求めます」
  なぜ: 本文は「直線の予測は0〜1をはみ出す」ことしか言っておらず、「合格の割合」も「確率とみなす」も本文に一度も出てこない。b1 で割合を求めさせられるが、それが何のためか（確率とどうつながるか）が分からないまま通る。題を読んで期待したことが本文に無い。
  案: 割合（ラベルの平均）が「この集団で合格する確率」と読めることを本文で一文言うか、題を本文の中身（ラベルを作る・直線でははみ出す）に合わせる。
- L2 場所: 「出てくる予測は0や1からずれた中途半端な数になります」（困る例）と「予測はその範囲をはみ出し、確率としては読めません」（説明）
  なぜ: 困る例では「中途半端な数」が困ることのように読めるが、直前の文で「確率は0.8のように言える」と言っており、0.8も中途半端な数である。説明まで読むと、困るのは「0〜1をはみ出すこと」だと分かる。困る例の段階では何が困るのか取り違える。
  案: 困る例の「中途半端な数」を「0より小さい数や1より大きい数」に言い換える。
- L3 場所: 「5行目の `(scores >= 60) * 1` は、真偽の配列に1を掛け」
  なぜ: 「真偽」という語はこれまでに出ていない（第7章3節は「`True` と `False` の配列」「ブール」と呼んでいる）。また、`True` に1を掛けると1、`False` に1を掛けると0になる、ということ自体は説明されず結果だけ言われる。結果は出力と合うので進めるが、なぜ数になるのかは分からないまま。
  案: 「`True` と `False` の配列（第7章3節）に1を掛けると、`True` は1、`False` は0になる」と、既に見た言い方で書く。

## 2節 02-sigmoid「シグモイド関数で確率に直す」

### 止まる
無し

### 引っかかる
- L4 場所: 「合格に `z`、不合格に `0` という値を付けたものとして、2つを `np.exp` に通し、その和で割ります。不合格の側を0と決めておくと、合格の確率は `z` 1つで決まります。」
  なぜ: 第11章3節は「点数の並び」を分布に直した。ここでは、1節で「ラベルを予想する直線の予測」だった `z` が、急に「合格の側の点数」として扱われ、不合格の側は勝手に0と決められる。なぜ0と決めてよいのか（決めても困らないのか）が書かれていないので、「そう決めた」として飲み込むしかない。
  案: 「不合格の点数を0とおいて、合格の点数 `z` がそれより大きいほど合格の確率が大きくなる」という読み方を一文足す。
- L5 場所: 困る例「この `z` を、確率として読める0から1の値に直したいです」
  なぜ: 1節の `z`（-0.08〜1.26）にこの節のシグモイド関数をそのまま当てると、確率は約0.48〜0.78になり、全員が五分五分付近になる（`py` で確認）。学習者はこの節を読むと「1節の直線にシグモイドを付ければ終わり」と思うが、実際は4節で `w`・`b` を学習し直す。そのことはこの節でも3節でも言われない。
  案: つながりか困る例で「直す式を決めたら、直線の `a`・`b`（`w`・`b`）は学習し直す」と先に一言いう。
- L6 場所: python-14-sigmoid-m1「`[0.269 0.5   0.731]` が2回表示されるように、3行目の `z` を書き換えてください。」
  なぜ: 本文は「`z` が0なら0.5」「`z` の符号を反対にすると1から引いた値になる」を言っていない。真ん中の0.5は式から `z = 0` と求められるが、0.731 になる `z` は当てずっぽうで試すしかない。ヒント2「0を中心にした等間隔の数」で答えの形がほぼ言われる。
  案: 本文に「`z = 0` のとき確率は0.5」を一文入れて、問題はそれを使えば解けるようにする（b1 の「0.5以上なら1」ともつながる）。

無し

## 3節 03-entropy「交差エントロピーで確率のずれを測る」

### 止まる
無し

### 引っかかる
- L7 場所: 困る例「自信を持って外したときの損失が小さくなってしまいます」と、説明「どれだけ自信を持って外しても1を超えません」「上限がありません」
  なぜ: 二乗誤差が1を超えないこと、交差エントロピーに上限が無いことは数で見える。だが「上限が無いほうがなぜ良いのか」（強く外したものを強く直したい、など）は書かれていない。また困る例の「小さくなってしまう」は、0.9998 を見ると「小さい」とは思えず、何と比べて小さいのか迷う。
  案: 「自信を持って外したときほど損失を大きくして、強く直させたい。二乗誤差は1で頭打ちになる」と、困る理由を一文で言う。
- L8 場所: python-14-entropy-b1 のヒント2「`-np.log(p)` に `y` を掛けると、正解が1の人の項だけが残ります。……この2つを足して平均を取ります。」
  なぜ: 正解が1の人と0の人を1つの式でまとめる `y * … + (1 - y) * …` の形は、本文に無く、このヒントにしか出てこない。本文の説明（37行目）は正解が0のときの式を言葉で言うだけ。ヒントを見ずに for と if で解いた学習者は、この形を一度も説明されないまま4節に進み、4節の `loss` の式（L10）を読むことになる。
  案: 本文で、`y` を掛けて足す形を例で1回見せる（例えば正解1と0が混ざった `p` と `y` で）。

### 要らない
- 場所: python-14-entropy-m1
  なぜ: 出力の `[0.81 0.01]` から `1 - p` を逆にたどれば答えが出る（ヒント2がその手順を言う）。交差エントロピーの側は見なくても解け、この節で新しく出た `-np.log(p)` について何も確かめていない。
