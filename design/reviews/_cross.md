## 画面が自動で出すもの（原稿に無くても、学習者には見えている）

- 組む問題（`<Input>` `<Output>` のある形）の**入力例・出力例**（判定のケース1から）と、コード欄の下の**テストケース**の入力
- 各節の説明のあとの**「この節の書き方」の表**（構文の一覧 `src/lesson/syntax-list.ts` の、その節の行）
- 節の題、章の名前、節の一覧。**原稿の `{/* 困る例 */}` などの印は出ない**
- 節への参照「第N章M節」は自動でリンクになる

## 問題を消す・替えるとき

- 課題の id は変えない（進み具合の記録が id に付いている）。中身を替えるときも同じ id を使う
- 消してよいのは、採否に「消す」と書いたものだけ

## 採らない指摘（どの章でも）

- 「出したい出力をそのまま `print` に書けば通る」。判定は出力しか見ないので、どの問題でもそうなる。仕組みの限界で、直せない。**例の値を写せば通る**、**starter のままで通る**、は別で、これは直す
- 「Mac では違う」。メンバーは全員 Windows のノートパソコンを使う

## 組む問題の形（2026-10-02 追加）

組む問題（`kind="build"`）の古い形（問題文・入力・出力・例を全部地の文に書く形）では、画面は入力例・出力例を出さない。**直す章の組む問題は、全部 `spec/10` 第3.11節の形（問題文・`<Input>`・`<Output>`）に直す。** 地の文に手で書いてある出力の例は消す（画面がケース1から出す）。ケース1は、例としてふさわしい組にする。ケース1に出てこない文言（別の分岐で出す文字列）は、`<Output>` に全部書く。

## 第3部（第12〜15章）の30人のデータ（2026-10-02 追加）

第12〜15章は同じ30人のデータ（`design/spec/51-part3-data.md`）を使う。読み手は「問題に要る30人ぶんのデータが、その節の画面のどこにも無い（別の章のページから写すしかない）」「問題文に、どのデータを使うかが書いていない」と何度も指摘した。

- **問題に要るデータは、その節の画面に、コピーできる形で必ず出ていること。** 節の例（`<Run>`）が同じデータを持っているなら、問題文で「この節の最初のコードの1〜3行目のデータを、そのまま使ってください」のように指す
- 節の例にそのデータが無いときは、次のどちらかにする。(1) 節の例を、問題と同じデータで書く。(2) 問題のデータを、節の例と同じ人数に減らす（減らすときは先頭から順に取る）。実行結果と期待する出力は、動かして確かめて書き直す
- 問題文には、どのデータを使うか、標準化するか、始めの値（`w` `b`）、学習率、くり返す回数のうち、入力で与えないものを全部書く。**模範解答が決め打ちにしている数は、問題文に書いてあること**
- 始めの値を `0` と書くか `0.0` と書くかで出力が変わる問題（0回くり返すテストで `[0 0]` と `[0. 0.]` が分かれる）は、そのテストケースを外すか、問題文に始めの値の書き方を書く
- 丸めの境目で通る・通らないが分かれる問題（第13章2節の練習問題）は、境目に来ない数にするか、丸める桁を粗くする
