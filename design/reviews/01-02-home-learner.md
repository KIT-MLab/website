## 引っかかる（進めるが、迷うか、分からないまま通る）

### L1（2-04 precedence）本文の規則が `**` では成り立たず、直す表の行が本文に出てこない
- 場所: 本文「同じ順位の演算子が並ぶときは、左から順に計算します（`8 / 4 / 2` は `(8 / 4) / 2` と同じです）」と、画面上部の表の行「`print(8 / 4 / 2)` … 同じ順位は左から順に計算する（** だけは右から）」
  なぜ: 本文は例外を言っていない。`2 ** 3 ** 2` を本文の規則で読むと `(2 ** 3) ** 2` で 64 になるが、実際は 512 である（実行して確認）。「`**` だけは右から」は表の説明の括弧の中にしか無く、`2 ** 3 ** 2` の例も無い。本文だけ読んだ学習者は誤った規則を覚える。表を読んだ学習者も、何を右から計算するのかが分からない。
  案: 本文に `2 ** 3 ** 2`（結果 512）を1つ書き、`**` だけは右から計算すると言う。
- 同じ表の `-2 ** 2` → -4 の行も、本文の「計算する順」の表（`**` / `* / // %` / `+ -`）に単項の `-` が無いため、`-` が `**` より後で `*` より前に計算される理由が本文から出てこない。説明は表の「** が先」の一言だけである。

### L2（01-print）`print()` の「結果」の列が実際の出力と違う
- 場所: 表の行「`print()` → （出力なし）  … 何も渡さず空の行を出す」
  なぜ: `print()` は何も書かれない空行を1行出す（実行して確認）。「出力なし」と読むと何も起きないことになり、同じ行の説明の「空の行を出す」と食い違う。`import math` の「（出力なし）」は本当に何も出ないので、同じ書き方なのに意味が違う。
  案: 結果の欄を「（空の行が1行出る）」のように直す。

### L3（2-02 round）末尾の 0 を残す書き方が、表の1行にしか無く、読み方の説明が無い
- 場所: 表の行「`print(f"{2.5:.2f}")` → 2.50  … 末尾の0も残して、小数第2位まで表示する」。本文は「小数の末尾が0になる桁は表示されません。たとえば `round(2.504, 2)` は `2.50` ではなく `2.5`」で終わる。
  なぜ: 本文は「0 が消える」と言うだけで、残したいときの手立てを言わない。その手立てが、本文に出てこない `:.2f` として表にだけ出る。`.` と `2` と `f` がそれぞれ何かは、どこにも書かれていない。調べに戻った学習者は写せるが、1桁にしたいとき `:.1f` と書いてよいかが分からない。
  案: 本文の末尾0の段落に `f"{2.5:.2f}"` を足し、「`.2` が桁数」と一言書く。

### L4（2-01 int-float）「小数を整数にするには」で戻ってきても、見つかるのは切り捨てだけである
- 場所: `int(7.9)` の段落、型変換の表（`int()` の例が `int("5")` で文字列からの変換）
  なぜ: この節で分かるのは `int()` が小数点以下を捨てることまでで、四捨五入したいときの `round()`（次の節の表に「整数に丸める」）と、切り上げの `math.ceil`（2-05 の表）への案内が無い。型変換の表の `int()` の例も文字列から整数であり、小数を整数にする例が無い。この見方で戻ってきた人は、「8 にしたいのに 7 になる」で終わる。
  案: `int(7.9)` の段落の末尾に「四捨五入は第2章2節の `round()`、切り上げは第2章5節の `math.ceil()`」と案内を足し、型変換の表の `int()` の行に `int(7.9)` を加える。

### L5（2-05 math）「平方根が書けません」と「math で切り上げは」
- 場所: 困る例「平方根や円周率を使う計算をしたくても、`print` や `+` `-` `*` `/` だけでは書けません」
  なぜ: 直前の節の表に `2 ** 0.5` → 1.414…（0.5乗は平方根）が出ているので、平方根は `**` で書ける。それを知っている学習者は、`math.sqrt` を学ぶ理由が分からない。`2 ** 0.5` と `math.sqrt(2)` の関係はどちらにも書かれていない。困る例の本当の困りごとは円周率だけである。
  案: 困る例を円周率（と、桁を間違えること）に絞るか、`math.sqrt(2)` が `2 ** 0.5` と同じ値だと一言書く。
- 同じ節の本文「`floor` と `ceil` は整数（int）を、ほかの関数は小数（float）を返します」: `floor` と `ceil` が何をするかは、本文のどこにも書かれていない（名前だけ出る）。「math で切り上げは」と調べに戻った人は、表の `math.ceil(7 / 3)` → 3「切り上げ（何箱いるか、など）」にたどり着けるので答えは出る。ただし本文の文は、読んだ時点で意味が分からないまま通る。また「ほかの関数は小数を返す」は、同じ表にある `abs(-3)` → 3（整数）と合わない（`abs` は math の関数ではないとも表に書いてある）。
  案: 本文を「`math.floor`（切り捨て）と `math.ceil`（切り上げ）は整数を返す。一覧は表を見る」にし、「ほかは小数」を `math.` の付くものに限る。

### L6（02-variable）`a, b = 3, 5` が本文の流れから浮いている
- 場所: 「名前と値をコンマで並べて `a, b = 3, 5` と書くと、`a` に `3`、`b` に `5` を一度に入れられます。」
  なぜ: `price = price + 10` の例の直後、名前の決まりの表の直前に、1文だけある。▶ の例が無く、出力は表の `print(a, b)` → `3 5` でしか見えない。課題（m1〜m3）にも出ない。一度に入れる理由が書かれていない。さらに、`print("合計", 5)` で覚えたばかりのコンマと、左辺のコンマが同じ記号なので、「コンマは並べる」と一緒くたに覚えかねない。
  案: 名前の決まりの表のあとに移し、小さな `<Run>` を付ける。または、この節で扱わない。

### L7（01-print）演算子の段落が、print の説明の途中に挟まっている
- 場所: 「`print` は1回呼ぶごとに1行を表示します。」の次の段落「計算の記号は、足し算が `+`、引き算が `-`、掛け算が `*`、割り算が `/` です。割り算の答えは…（第2章1節）。計算に使う記号の一覧は第2章3節に、計算の順番は第2章4節にあります。」
  なぜ: 前後が引数（`,` で区切る）の話で、ここだけ話題が変わる。足し算の書き方を調べに戻った人は、ここと表で答えを得られるので、中身は要る。ただし位置が悪く、`print` の説明が途切れる。割り算が「小数になる」は、この時点では 3.5 の1例だけの説明である。
  案: 引数の段落の後ろ（`print` を書かない場合の段落の前）に移す。

### L8（modify 問題の全般）出力を打ち写せば通る
- 場所: print-m2、variable-m1/m3、fstring-m1/m2、int-float-m1/m2、round-m1/m2、operators-m1/m2、precedence-m1/m2、math-m1
  なぜ: 問題文に期待する出力が書いてあり、テストが `stdout` だけなら、`print(3.0)` や `print("名前:鈴木 点数:95点")` のように結果を打ち写しても通る。問題文の「`()` を1組足して」「`/` の左右の数を書き換えて」「引数は2つ渡します」は、検査されていないことになる。たとえば precedence-m1 は `print(3.0)` で、print-m2 は `print("赤 青")` で通る。確かめたい「その書き方を使う」が通らなくても分からない。
  案: 機械の検査側の話なので、書き手に回す（コードの形を検査できるなら `forbid` / 必須の形を足す）。学習者の側からは、解いた感触が残るかどうかの問題である。

### L9（2-01 int-float）表だけにあって本文に無い行
- 場所: 表の行 `type(2.5)`、`float(3)`、`int("2.5")`（ValueError）、`2.5e3`、`1e-3`
  なぜ: 本文に出てこない。`type()` は本文の「型（type）」と名前が同じだけで、関数として何かの説明が無い。`2.5e3` は「2.5×10の3乗」と読めるが、`e` が何の記号かは書かれていない。`int("2.5")` のエラー行は、読み取りで小数を `int()` に渡してしまう間違いを防ぐ大事な行なのに、課題でも本文でも触れない。調べに戻れば表で答えは得られるが、初めて読む学習者は表を読み飛ばす。
  案: 重いのは `int("2.5")`。本文の `float()` の段落に「小数の文字列は `int()` では変えられず、`float()` を使う」を足す。e 表記と `type()` は表のままでよい。

### L10（2-01 int-float）「小数は近似」の段落が型変換の表のあとに唐突に出る
- 場所: 型変換の表のあと「小数は近似の値なので、`0.1 + 0.2` は `0.3` ではなく `0.30000000000000004` のように…」
  なぜ: 直前までの話題（型の変換）とつながらず、▶ の例も無い。「近似」の意味（なぜずれるか）が1文も無く、数が合わないのは自分のミスか PC の故障かと迷う学習者がいる。結論（round で丸める）は書いてあるので、読んだ後に動けなくなりはしない。
  案: 段落の頭に「ここで別の話」の合図（1文）を置くか、`print(0.1 + 0.2)` の `<Run>` を付ける。

### L11（2-01 int-float 課題 b1）`{}` の中の関数呼び出しが初めての組み合わせ
- 場所: b1 の模範解答 `print(f"小数:{q} 整数:{int(q)}")`
  なぜ: `{}` の中に書けるのは「式」と第1章5節で教わったが、見たのは `{100 - score}` という計算だけである。関数呼び出し（`int(q)`）を入れた例は、次の節の `{round(average, 1)}` まで出てこない。回避は簡単（`i = int(q)` と変数に入れる）なので、止まりはしない。数えると、この節の例からの距離は3（`/` で割る、`int()` を通す、`小数:` `整数:` のラベルを出力例から読む）で、ちょうど限度に近い。
  案: 問題はこのままでよい。ヒント3つ目に「`{}` の中に `int(q)` と書いてもよい」を足してもよい。

### L12（05-fstring）表だけにあって本文に無い行
- 場所: 表の行 `print("=" * 10)` → ==========、`print('赤')` → 赤
  なぜ: 文字列に `*` を使う書き方と、`'` で囲む書き方は、本文にも課題にも無い。本文は `+` が「つなぐ」ことを丁寧に説明するので、`"=" * 10` の行だけが、ここまでの説明に当てはまらない書き方として表に出る。調べに戻る人には役立つが、初めて読む人には何の準備もなく出る。
  案: 後で使う場面（罫線や区切り）の節で本文に出すなら、表のままでよい。この節で使わないなら、そのままでよい（報告のみ）。

### L13（2-03 operators）負の指数の括弧書きが濃い
- 場所: 「（`10 ** -3` のように、`**` の指数が負のときだけ、int どうしでも float です）」
  なぜ: 型のそろえ方の規則の中に、ほかの演算子には無い例外が括弧書きで入る。`10 ** -3` の結果（0.001）は本文のどこにも出ず、表の行 `print(10 ** -3)` → 0.001 でだけ見える。数IIまでの学習者は 10 のマイナス3乗を知っているので読めるが、「負の指数」という語は説明されていない。
  案: そのままでよい。「負の指数」を「`-3` のようにマイナスの指数」と言い直すと、さらに読みやすい。

### L14（2-02 round）「四捨五入」という語が無い
- 場所: 本文全体
  なぜ: 学習者が `round` を探すとき、「四捨五入」と調べる。本文には「いちばん近い整数」「ちょうど真ん中は偶数の側」はあるが、`round(2.5)` が 2 になることが、四捨五入とは違うという一言が無い。高校までの四捨五入で `round(2.5)` を 3 と思う人は、「3 ではなく 2」の一文で気づけるので、進めはする。検索の入り口と、学校の言葉との違いが抜けている。
  案: 「四捨五入に近いが、ちょうど真ん中だけ偶数の側へ寄る」の一文を足す。

- 01-print: 値や計算の結果を画面に出す方法（`print`、コンマで並べる、四則の記号）を知る節。

1. 調べに戻る見方

   - 「小数を整数にするには」: 2-01 では `int(7.9)` → 7 までしか分からず、四捨五入（2-02）と切り上げ（2-05）への案内が無い（L4）。

2. 表の「結果」と実行結果: 全行を `py` で実行して照合し、`print()` の1行以外はすべて合っていた。食い違いは `print()` の「（出力なし）」のみ（L2）。本文の数値の主張（`int(-9 / 2)` = -4、`-9 // 2` = -5、`round(2.504, 2)` = 2.5、`round(average, 0)` = 82.0、`math.sqrt(9)` = 3.0 など）もすべて合っていた。
