# 第5章 関数 学習者の目で読む（章まとめ）

対象: `src/content/lessons/05-function/` の6節（01-def, 02-return, 03-args, 04-keyword, 05-scope, 06-scores）。
前提の一覧は `node scripts/taught.mjs python-05-def` の出力に、節ごとに前の節の内容を足して考えた。

## 止まる（ここで学習者が進めなくなる）

- L1（02-return）場所: 課題 `python-05-return-b1`「そのうち最大の値を返す関数 `largest(a, b, c)` を書いてください」
  なぜ: 「いちばん大きい値を探す手順」（いまの最大を変数に持ち、順に比べて入れ替える）は、この節の例にも、これまでの章にも出てこない。`if` だけを繰り返し並べる形も、`else` を付けない `if` を2回続ける形も、組み合わせとして初めて。ヒント1「`a` と `b` を比べて大きいほうを求め、それと `c` を比べます」は方針だけで、「大きいほうを入れておく変数を作る」ことは書いていない。例（`average`）からは、考えることが「最大を保持する変数」「if を2回」「その変数を return」の3つ以上に増える（段差が大きい）。
  案: 「いまのところの最大を変数に入れ、次の値と比べて入れ替える」という手順を、この節か第3章の例で先に見せる。または2つの値の大きいほうを返す `larger(a, b)` から始め、3つに伸ばす問題にする。

- L2（02-return）場所: 課題 `python-05-return-b1`「入力欄の3行を整数として読み取ってください」と、関数の外の `a`, `b`, `c`
  なぜ: 関数の引数の名前と、関数の外で入力を受け取る変数の名前が同じ `a` `b` `c` になりやすい。スコープは5節（05-scope）まで教えないので、学習者は「関数の中の a と外の a は同じものか」で悩む。ここでは止まるほどではないが、03-args 以降の課題と違い入力部分の書き方も同時に求められる。
  案: 課題文に「関数の外で読み取った値を `largest(...)` に渡して、返ってきた値を表示する」と1文足す。

## 引っかかる（進めるが、迷うか、分からないまま通る）

- L3（04-keyword）場所: 「困る例」の「`price_with_tax(0.2, 1000)` と順番を逆にしても……それでも `200.2` という、意図しない金額になります」
  なぜ: 実際に Python で `0.2 * (1 + 1000)` を計算すると `200.20000000000002` と表示される（小数の誤差）。学習者が試したら、本文と違う数が出て混乱する。浮動小数点の誤差は第2章で `float` として触れているだけで、この種の誤差は教えていない。
  案: 本文の数を、誤差の出ない例（`price_with_tax(0.5, 1000)` など）に変えるか、「約 `200`」と書く。

- L4（04-keyword）場所: 「困る例」の「前の節の `price_with_tax(amount, rate)` は……」
  なぜ: 前の節の関数は `price_with_tax(amount, rate=0.1)` で、`rate` にデフォルト値があった。ここでは `rate=0.1` が無いかのような書き方で、前の節と食い違う。さらに、順番を逆にして `price_with_tax(0.2, 1000)` を呼ぶことを、学習者は前の節で見ていない。
  案: 「前の節の `price_with_tax(amount, rate=0.1)` は」と書くか、逆順の呼び出しを、困る例の中でコードとして見せる。

- L5（04-keyword）場所: 「4行目の `rate=0.2` は、呼び出すときに書く名前と値です」「5行目は……」
  なぜ: 実行例のコードで、`rate=0.2` や `shipping=500` が書かれているのは4行目と5行目ではなく、`<Run>` のコードの 4・5行目に相当する `print(...)` の行である（1行目が `def`、2行目 `return`、3行目が空行、4行目・5行目が `print`）。数えると合っているが、「4行目」のように行番号で指す読み方は、空行を数えるかどうかで迷いやすい。
  案: 行番号で指すのをやめ、`print(price_with_tax(rate=0.2, amount=1000))` のようにコードそのものを引用する。

- L6（03-args）場所: 「デフォルト引数（既定値のある引数）は、デフォルト値のない引数より後ろに書きます」
  なぜ: ルールを述べるだけで、守らないとどうなるか（エラー）も、例も無い。課題の `judge(score, border=60)` では自然に守れるので、この文が無くても通る。学習者は「そうなんだ」と覚えるだけで、確かめる機会が無い。
  案: 理由を1文（「渡す値の数があいまいになるため」など）添えるか、削る。

- L7（04-keyword）場所: 「名前を書いた引数より後ろに、名前のない引数は書けません。」
  なぜ: 例が無い。`price_with_tax(amount=1000, 0.2)` のような書き方がどうなるかを、学習者は想像するしかない。
  案: 書くとエラーになる例を1行示す。

- L8（05-scope）場所: 「困る例」の「関数の中で `total = a + b` のように変数を作ったとします。この `total` を関数の外の `print(total)` で使おうとしても、見つけられません。」
  なぜ: 実行例は「同じ名前の x が、中と外で別物」を示すもので、困る例の「外から中の変数を見ようとするとエラー」は実行例に出ない。「困る例」と実行例で扱っていることがずれている。エラーの表示も見ない。
  案: 実行例に、関数の中の変数を外で `print` するとエラーになる例を足すか、困る例を「同じ名前が別の変数になる」に合わせる。

- L9（05-scope）場所: 課題 `python-05-scope-m1`「外側の `total` にも割引後の値が入るように書き換えてください」
  なぜ: 解答は `return total` を足し、`total = apply_discount(total)` と書く。`return` の値を、同じ名前の変数に入れ直す書き方は、02-return の `result = average(80, 90)` と同じ形で、組み合わせは初めてではない。ただし、関数の中でも `total` に `print` をしたまま `return` もする書き方（表示と返すの両方）は、01と02で別々に出てきただけで、一緒に使うのは初めて。ヒント2が `return` を直接指しているので進めるが、「外の変数を関数の中から直接書き換える」道を考えて迷う学習者が出る。
  案: 課題文に「関数の中で変えた値は `return` で持ち帰る」と1文足すか、ヒントに残す。

- L10（06-scores）場所: 課題 `python-05-scores-b1` の「3教科の点数を読み取ります」
  なぜ: 3教科の点を、リストに入れてから関数に渡す形 `scores = [int(input()), int(input()), int(input())]` は、リストの要素に `input()` を直接並べる書き方で、第4章までに見ていない（リストは値を並べたものとして習っただけ）。`append` で足す道もあるが、どちらも課題文に出ていない。リスト・for・関数・if・round・f文字列を一度に組み合わせるので、段差が大きい。
  案: 課題文に「3つの点数を1つのリストに入れて関数に渡す」と書くか、ヒントに「空のリスト `[]` に `append` で足していく」を出す。

- L11（06-scores）場所: 実行例の `def average_score(scores): return round(total_score(scores) / len(scores), 1)`
  なぜ: 1行に「関数の呼び出し」「割り算」「`len`」「`round`」が入れ子に入っている。説明は「`total_score(scores)` を `len(scores)` で割る」とだけで、`round(..., 1)` の部分には触れていない。`round` は第2章で習ったが、関数の中で入れ子にした形は初めて。
  案: 説明に「`round(..., 1)` で小数第1位に丸めています」と1文足す。

- L12（06-scores）場所: 課題の「基準点は `60` とし、変数にします」と、人数 0 のテスト
  なぜ: 人数が 0 のとき何も表示されなくてよいのか、課題文には書いていない。`range(0)` がどうなるかも教えていない（学習者は、空振りでよいのか迷う）。
  案: 課題文に「人数が0のときは何も表示しません」と1文足す。

- L13（01-def）場所: 「困る例」の「2教科の平均を3か所に計算式で書いたとします。……計算のしかたを変えたくなると、3か所とも直すことになります」
  なぜ: 困る例は文だけで、コードが無い。「3か所」「計算のしかた」が何のことか、1年生には想像しにくい（「計算のしかたを変える」とは、たとえば何か）。
  案: 3行の `print((80 + 90) / 2)` などを例に出す。

- L14（01-def）場所: 課題 `python-05-def-m1`「1行足して、`平均85.0` の下に `平均60.0` も表示されるようにしてください。」
  なぜ: 足す行 `show_average(50, 70)` は、本文の例の5行目とそっくり同じで、答えが例に書いてある。6割の学習者は考えずに写せる。確かめるのは「呼び出しの追加」だけで、`b1` が確かめている。
  案: 課題を消すか、`starter` を例と違う値にして「別の2教科の平均を表示する」にする。

- L15（01-def）場所: 課題 `python-05-def-b1`
  なぜ: 「人数を読み取る→人数ぶん繰り返す→1組ずつ2つの点数を読み取る→関数に渡す」の4つを組む。例からの段差は、`for` の中で関数を呼ぶ（1）、`input()` を int に直して2回読む（1）、人数を先に読む（1）で3。ぎりぎり。ヒントは「先に関数を定義する」「単体で確かめる」で、使える。止まるほどではない。
  案: 不要。

## 要らない（消しても何も失わない文・問題）

- 場所（01-def）: 「同じ計算を書く行は、この2行だけで足ります。呼び出す場所がいくつ増えても、直すのは関数の中身1か所です。」
  なぜ: 「困る例」の言い直し。ただし、この節の動機を回収する文でもある。
- 場所（02-return）: 「前の節の `show_average` は `print` だけをしていて、値を持ち帰りませんでした。`return` があると、関数の外で値を使い回せます。」
  なぜ: 「困る例」と同じ内容の繰り返し。
- 場所（03-args）: 「よく使う値をデフォルト値にしておくと、呼び出す側は短く書けます。違う値を使いたいときだけ渡せばよいので、同じ関数を使い回せます。」
  なぜ: 「困る例」と実行例で既に分かること。
- 場所（06-scores）: 「点数の数が増えても、直すのは `total_score` と `average_score` の中身だけです。呼び出す側の書き方は変わりません。」
  なぜ: 「点数の数が増える」と関数の中身を直すことの関係が分からず（引数はリストなので、数が増えても直す必要が無い）、むしろ誤解を招く。
- 場所（各節の「つながり」）: 「〜できるようになりました。次の節では〜を扱います。」
  なぜ: 毎回の定型。消しても学習者は何も失わない（ただし章の流れの予告にはなっている）。

## 各節は何のためにあるか（学習者の言葉で一文）

- 01-def: 同じ計算を何度も書かずに、名前を付けて呼ぶだけにできる。
- 02-return: 関数が計算した値を、表示するだけでなく後の計算にも使える形で受け取れる。
- 03-args: 渡さなくてもよい引数を作って、ふつうの値を省略できる。
- 04-keyword: 引数に名前を付けて渡すと、順番を気にせず、途中を飛ばせる。ただし課題では名前を使わなくても通るため、この節が本当に身に付いたかは確かめられない。
- 05-scope: 関数の中で付けた名前は外から見えず、外の同じ名前の変数も変わらない。
- 06-scores: これまでの関数・リスト・for・if を合わせて、点数表の合計と平均を関数に任せる。
