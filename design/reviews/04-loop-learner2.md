### 引っかかる（進めるが、迷うか、分からないまま通る）

- **L1（04-append / python-04-append-b1）段差が大きい**
  場所: 「入力欄の5行を整数として読み取ってください。そのうち偶数だけを、読み取った順のままリストに集め…」
  なぜ: 模範解答は、空リスト `kept = []`、`for` で5回読む、`if value % 2 == 0:`、その中で `kept.append(value)`、と「for の中の if の中の append」の3段の入れ子になる。この節の例は `append(int(input()))` を for の中に1つ置くだけで、「if の中で append する」「for → if → append の3段」は初めての組み合わせ。ヒントは `%` の使い方しか言わない。自分で考えることは「空リストを用意する／条件を作る／if の中に append を置く／読み取りと選別を同じ繰り返しにするか分けるか」で4つ前後（3を超える）。
  案: 例の2つ目の Run に「条件が合うときだけ append する」形を1つ入れる、または課題の前に、読み取りと選別を分けた形（modify の `starter` で if だけ足す）を1問挟む。

- **L2（04-index / python-04-index-b1）出力が出ているだけで通る道がある**
  場所: 「そのリストを逆順に、1行ずつ表示してください」（`forbid` は `reversed` と `[::` だけ）
  なぜ: `print(numbers[4])` から `print(numbers[0])` まで5行書けば全テストに通る。for と式 `len(numbers) - 1 - i` を使わなくても済むので、この節の肝（「i と len を式で組み合わせてインデックスを作る」）が確かめられない。例の `numbers[i]` と `numbers[len(numbers) - 2]` は別々で、2つを1つの式にする組み合わせは初めて。ヒントは `i` が 0 のとき 4 になる式と言うので、学習者は `4 - i` と書くだろう。
  案: `forbid` に `numbers[4]` `numbers[3]` を足す（または「個数が変わっても動くように `len()` を使う」とm2のように書き、5個でも7個でも通るテストを足す）。

- **L3（02-list / python-04-list-m1）何を加えるのか、手計算の数字を書き写すだけになる**
  場所: 「`numbers` の最後に値を1つ加えて、出力の最後の行に、元の5つの値の合計が出るようにしてください。」
  なぜ: 模範解答は `[3, 7, 2, 9, 4, 25]` で、3+7+2+9+4 を頭で計算して `25` を書くだけ。この節にも前の節にも合計を求める書き方は出てくる（01-for の `total = total + i`）が、ここでは使わなくても通る。またテストは標準出力だけを見るので、`numbers` を書き換えず末尾に `print(25)` を足しても通る。「リストに値を足す」のか「合計を出す」のか、問題文だけでは何を確かめたい問題か分からない。
  案: 問題の意図を決めて書き直す（リストの値を増やして for が追従することを見せたいなら「6個目に `10` を足して、6行出す」程度でよい）。合計を出させたいなら別問題にする。

- **L4（02-list / 2つ目の Run）入れ子と「4行を1+3に分ける」説明が足りない**
  場所: `numbers = [int(input()), int(input()), int(input())]` と、`for` の中の `if value > largest:`
  なぜ: (a) `for` の中に `if` を入れて2段のインデントになるのは、この章で初めて。説明は「4〜5行目で…入れ直します」だけで、`if` の中身がさらに1段下がることには触れていない。(b) 「4行の中から」と言いながらリストには3つだけ入れる理由（最初の1つは `largest` に使うから）が「いまのところの最大として」の一言で済まされている。課題 list-b1 では5行なので `int(input())` を4つ並べると気づく必要があり、ヒントはそこに触れない。
  案: 入れ子のインデントを1文説明する。b1 のヒントに「最初の1行を `smallest` に使うので、リストには残りの4行を入れます」の趣旨を足す。

- **L5（05-while）文字列を `!=` で比べるのは初めて**
  場所: `while line != "終わり":`
  なぜ: ここまでに `!=` は `5 != 5` の数の比較しか出ていない。文字列どうしを比べてよいことは説明が無い（学習者は推測で読める程度）。入力が `終わり` のときは `int()` に通せない、という b1 のヒントの話にもつながる。
  案: 説明に「文字列も `==` `!=` で比べられます」を1文足す。

- **L6（06-scores / python-04-scores-b1）例と課題の作りが合っていない**
  場所: Run は `points = [40, 55, 50, 65, 82, 70]` に全員の点を先に並べ `points[i * 3 + 1]` で取る形。課題は入力から読む。
  なぜ: 例の方法を課題に使うには、人数×3行をリストに集めてからループする必要があり、それは前の節の append で可能だが段差が大きい。一方、模範解答は「`for` の中で1人ぶん3つを読み、`scores[0] + scores[1] + scores[2]`」で、例のインデックス計算 `i * 3 + 1` はまったく使わない。ヒント2「前の節までのリストとインデックスを使ってまとめます」は、第3章の `japanese = int(input())` を for の中に入れるだけでも通ることを隠し、学習者を重い道へ誘う。この節は新しい書き方が無く（`terms: []`）、「第3章のコードを for で包む」ことが核なのに、例は包んでいない。
  案: Run を、第3章の入力付き点数表を `for i in range(人数):` で包んだ形にする（課題の骨格と同じにする）。ヒント2は「第3章の点数表を、for の中に入れます」にする。

- **L7（01-for / python-04-for-b1）公式で通る**
  場所: 「for文で1つずつ足して合計を求め」
  なぜ: `forbid` は `sum(` だけ。高校数学を知る学習者は `print(n * (n + 1) // 2)` で全テストに通る（`//` は第2章で習済み）。for と「合計を入れる変数に足し込む」型が確かめられない。ヒント「終わりの数を n より1大きく」は、`range(1, n + 1)` の式の中に n を入れることもほぼ言ってしまっている。
  案: `forbid` に `*` を含む式は入れにくいので、テストに n が大きくて公式でも通るのは変わらない点を認めたうえで、「for の中で `total = total + i` を使う」を `must`（必須の書き方）で確かめる仕組みがあればそれを使う。無ければ、問題文を「1から n までのうち、偶数だけを足す」などにして公式が使えないものにする。

- **L8（04-append）`remove()` の挙動が1つ曖昧**
  場所: 「リストから `7` という値を1つ取り除くメソッドです。」
  なぜ: 同じ値が2つあるとどちらが消えるか、リストに無い値を渡すとどうなるかが書かれていない。この節の課題では起きないので進める。後でインデックスと取り違える学習者がいるかもしれない（「7番目を消す」と読む）。「値」と書いてあるので読めば分かる。
  案: 無くてよい。気になるなら「指定した値を、先頭に近い方から1つ」と一言足す。

- **L9（04-append / python-04-append-m1）ヒントが答えを言っている**
  場所: hints「`remove()` の行をもう1つ、`print(numbers)` の前に足します。」
  なぜ: 問題文「`[2, 9]` と表示されるように…1行足してください」と合わせると、どの値を消すか（3）以外はすべて書いてある。ヒントを開くまでもなく、問題文だけで足りる問題で、ヒントは何も足さない。
  案: ヒントを消す。

### 要らない（消しても何も失わない文・問題）

- 01-for「つながり」以外の文は、どれも次の文の準備になっていて削れない。
- 05-while / python-04-while-m1
  なぜ: 例のコードの `count = count + 1` の行を `print(line)` に置き換え、最後の `print(count)` を消すだけの問題。b1 が同じ形（`while line != "終わり":` で読み直し、本体で何かする）をもう一度、`int()` の置き場所という考える点付きで確かめるので、m1 を消しても b1 が通らなくなる学習者は少ない。踏み台として段差を下げる役割はある。残すなら現状のまま。
- 06-scores「困る例」の2文目「人数が増えると、同じコードを人数ぶん書き写すことになります」は、01-for の「困る例」の言い直し。ただしこの節の動機として必要な面もある。

## 各節は何のためにあるか（学習者の言葉で一文）

- 01-for: 同じことを何回も書かずに、数を決めて繰り返す書き方を知る節。
- 02-list: 点数のように複数の値を1つの名前にまとめ、for で順に取り出す書き方を知る節。
- 03-index: リストの「何番目」を数字で指定して取り出し、`len()` で個数を数えられるようになる節。
- 04-append: 空のリストを作って、入力や条件に合った値だけを後から足していく節。
- 05-while: 回数が決まっていなくても「この行が来るまで」と終わりを決めて繰り返す節。
- 06-scores: 第3章の点数表を、人数ぶん繰り返すようにつなげる節（この節は新しい書き方を足さないので、「ここまで学んだ for と input を点数表に使う」まとめ）。

## 補足（短く）

- 01〜05 の説明文は、1文ずつ読んで止まる語は無かった（「関数」「値」「インデント」は第1〜3章で既出）。
- 04-append の「値の後ろに `.` を付けて呼ぶ関数をメソッドといいます」は、`numbers` が値というより変数の名前なので一瞬迷うが、例で `numbers.append(9)` を見れば分かる。
