# 練習問題集 第1章・第2章 学習者読み（practice-learner2）

対象: `src/content/practice/01-python/`（4ファイル・20問）と `02-numbers/`（5ファイル・25問）。
学習者の持ち物: 第1章ぶんは `python-02-int-float` 時点、第2章ぶんは `python-03-if` 時点の「ここまでに教えた」。

## 確かめた方法

- 模範解答45本を、`tests` の全ケース（1問につき1〜4ケース）で `py` で実行した。エラーは0件。出力は全問、問題文と `<Output>` の言う形になっていた（行数・順序・文字列の部分・`.0` の付き方）。
- 問題文と `<Input>` `<Output>` だけから、学習者が書きそうな別解を作って全ケースで比べた。比べたもの: 計算の順序違い（`a / b * 100` と `a * 100 / b`、`(f-32)*5/9` と `(f-32)/9*5`、`p*(100-r)/100` と `p - p*r/100`、複利の `(1+r/100)**y` と `(100+r)**y/100**y`、BMI の `/ m**2` と `/ (m*m)`、円周 `d*math.pi` と `2*(d/2)*math.pi` など）。**どれも模範解答と同じ出力になった。** 問題文の足りなさで通らなくなる所は無かった。
- 模範解答に使われている書き方は、第1章は第1章まで（print のコンマ、変数、`int(input())`、f文字列の `{}` の中の式）、第2章は `python-03-if` までで全部見たことがある。未習の行は0。入れ子や関数の中で関数を呼ぶ形（`round(side * 4, 2)`、`int(around / width)`）は節の例に近い形がある。

## 引っかかる（進めるが、迷うか、分からないまま通る）

- L1 場所: `practice-01-format-5`（自己紹介カード）の `<Output>`
  なぜ: 出力例は `名前: 佐藤` のように、コロンの後ろに空白が付く形。問題文に「半角」の注意が無い。同じ話題の format-3 は「間の空白はすべて半角です」と書いてあるのに、format-5 には書いてない。日本語入力がオンのまま打つと、コロンも空白も全角になりやすく、見た目は似ていて、判定の差分でしか気づけない。
  案: format-3 と同じように「コロンと空白は半角です」の一文を `<Output>` に足す。

- L2 場所: `practice-02-power-2`（セットの代金・★1）
  なぜ: 確かめたいのは「`+` を先に計算させるかっこ」（ヒントもそう言っている）。ところが `burger * sets + drink * sets` と書いても全ケースで通る。かっこを使わなくても答えが出るので、優先順位を確かめられない。power-4 の摂氏の式は、問題文が「32を引いた値に5を掛け」と手順を言っているので、かっこ無しでは書けず、そちらは確かめられている。
  案: 「組の数」を2つに分ける問題でなく、たとえば「合計に対して割引率を掛ける」など、かっこ無しだと別の式になる形に変える。または power-4 に任せて power-2 は消してもよい（消したら失うものは「ほぼ無い」）。

- L3 場所: 星の段差（`practice-02-power-4` 華氏を摂氏に・★1、`practice-01-input-5` 2人ぶんの代金・★3、`practice-02-int-float-5` 大袋と小袋・★3）
  なぜ:
  - power-4 は、かっこ・3つの演算・`round` が1つの式に入る。同じ話題の power-2（かっこ1つ）や、★2 の power-3（`**` を2回）と比べて軽くない。★2 のほうが近い。
  - input-5（★3）は、同じ型の掛け算を2回して足すだけで、variable-5（★2、掛け算2回＋合計）や variable-4（★2）と考えることの数が同じ。「前の話題もまたぐ」にもなっていない。
  - int-float-5（★3）は、`/` と `* 100` を2回同じ形で書くだけで、int-float-4（★2）より重くない。
  案: power-4 を★2へ。input-5 と int-float-5 は、★2 に下げるか、前の話題と組む形（たとえば input-5 に f文字列の表示を足す）にする。

- L4 場所: `practice-02-divmod-4`（偶数と奇数の個数・★2）のヒント
  なぜ: 解き方を「1から7までを書き出して数え、きまりを探す」としか言っていない。偶数の個数が `n // 2` になることを自分で見つける問題になっている。`//` は第2章3節で習っているが、「きまり」から `//` を結ぶ手がかりが無く、数え上げでは `n = 10` までしか書き出せない学習者は止まりかける。通る人は通る。
  案: ヒントに「2で割ったときの商や余りを、書き出した数と並べてみます」のような、`//` か `%` を探す方向の一文を足す。または★3に上げる。

- L5 場所: `practice-02-int-float-2`（給油の合計）のヒント「小数点を含む文字列は `int()` では数に直せません。第2章1節を見てください。」
  なぜ: 第2章1節には、`float()` で小数を読むとは書いてあるが、「`int()` では直せない」とは書いてない。ヒントが指す節に、言っている内容が無い。
  案: 「小数を含む入力は `float()` で読み取ります」に直す（第2章1節に書いてある）。

- L6 場所: `practice-02-math-5`（丸いテーブル）の `<Output>`「座れる人数（整数）」
  なぜ: `around // width` と書くと `6.0` になり、`int(around / width)` なら `6` になる。`//` は第2章3節で習っていて、整数どうしの例しかないので、小数にも使えて `6.0` が出ることは学習者の知識に無い。「（整数）」の一語とヒント2（`int()` の切り捨て）で `6` のほうに気づけるので、止まりはしないが、`//` を試して `6.0` を見て迷う人は出る。
  案: ヒント2に「`//` ではなく、第2章1節の書き方」と一言足すか、「整数で、`6` のように小数点を付けずに」と書く。

## 節（話題）ごとに何のためにあるか

- print: 計算の式と文字列を、順に print に並べる練習
- input: 入力の値を `int()` で数にして計算する練習
- variable: 途中の値を変数に入れて、あとの計算に使う練習
- format: 計算した値を f文字列で文の中に入れる練習
- int-float: `/` と `float()` と `int()` の使い分けの練習
- round: 最後に1回丸める、桁数の有無で型が変わる練習
- divmod: 商と余りで、分ける・取り出す・数える練習
- power: `**` と、かっこで先に計算させる練習
- math: `math.sqrt` と `math.pi` を使って、丸める前の値を使い回す練習
