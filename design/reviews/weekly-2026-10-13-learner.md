## 止まる（ここで学習者が進めなくなる）

- L1 場所: weekly-2026-10-13-b5「アイスの代金を返す関数 `ice_cream_bill`… 代金」
  なぜ: 代金の式が問題文のどこにも無い。模範解答は `count * price + topping_fee`（追加料金は全体で1回）。学習者が自然に考える `(price + topping_fee) * count`（1個ごとにトッピング）は、例の 3個・100円で 1200 になり、答え 1000 と合わない。例の出力が 1000 と見えても、式を逆算するしかない。「トッピングの追加料金」が1個ごとか全体で1回かが決まらない
  案: 「代金は 個数 × 1個の値段 に、トッピングの追加料金を1回だけ足した額です」と式を問題文に書く。

- L2 場所: weekly-2026-10-13-b5「引数は `count`、`price`（デフォルト値300円）、`topping_fee`」
  なぜ: 書いてある順に `def ice_cream_bill(count, price=300, topping_fee):` と書くと SyntaxError（`parameter without a default follows parameter with a default`、実行して確認）。第5章3節には「デフォルト値のある引数は、デフォルト値のない引数より後ろに書きます」とあるが、この組み合わせで自分で順番を直す（topping_fee にデフォルト値を付ける／順番を入れ替える）のは別の考えになる。エラーは第6章の SyntaxError の説明（コロン・全角・かっこ）にも当てはまらない種類。問題文は topping_fee にデフォルト値を付けるとは言っておらず、模範解答だけ `topping_fee=0`
  案: 「`topping_fee` にもデフォルト値 `0` を付けてください」と書くか、引数の並びを `count`、`topping_fee`、`price`（デフォルト値300円）に変えて問題文に書く。

- L3 場所: weekly-2026-10-13-b2 ヒント2「0で割ろうとするとエラーになることは、第2章3節（べき乗と余りを求める）で見ました。」
  なぜ: 第2章3節には0で割る話も ZeroDivisionError も無い（教えた節全体を検索しても出ない。`taught.mjs` の一覧のエラーも NameError / SyntaxError / IndexError / TypeError / ValueError だけ）。学習者はヒントに従って読み直しても見つからない。事実と違う案内
  案: この節名への案内を消す。「0で割るとエラーで止まるので、割る前に `hours` が0かを調べる」と、ヒント自身の中で言い切る。

## 引っかかる（進めるが、迷うか、分からないまま通る）

- L4 場所: weekly-2026-10-13-b3 ヒント1「第5章1節と第4章2節（リストで値をまとめて持つ）を読んでください」
  なぜ: 問題文は「読み取った冊数のリストを使って」とだけ言う。入力の n 行をリストに集める書き方（`counts = []` と `append(int(input()))` を `range(n)` で回す）は第4章4節にだけある。ヒント1は第4章2節を指しているので、2節を読み直しても `counts = []` も `append` も出てこない。しかも `range(n)` と変数を渡すのは第4章1節の `range(3)` と値が違うだけなので通るが、「n 行をリストに集める」手順そのものは学習者が4節の例を思い出せるかにかかっている
  案: ヒント1に「入力の行をリストに集める書き方は、第4章4節（append()とremove()でリストを変える）の最後の例を読んでください」を足す。

- L5 場所: weekly-2026-10-13-b4「最後に、`"注意"` だった日数を表示します。形は出力例のとおりです。」
  なぜ: 例が見えていれば `注意 2日` の形は分かる（出力例は自動表示のため）。ただし、返ってきた言葉の `注意` と、最後の行の `注意 2日` の2つが同じ語で並ぶ。例を見ない学習者は `print("注意", 2, "日")`（`注意 2 日`）と書いてしまう。例を見れば解決するので止まるほどではない
  案: 出力例に任せるならこのままでよい。迷いを減らすなら、最後の行は「`注意 ○日`」と書いて ○ に数が入ると示す。

- L6 場所: weekly-2026-10-13-b4 課題全体（1日の判定の関数＋while＋数え上げ）
  なぜ: 自分で考えることは、(1) 関数を作る（if の中で return 2回）、(2) while の先読み、(3) 返り値を変数に入れて比べる、(4) 注意の日数を数える、(5) 最後に f 文字列で表示、の5つ前後。第4章5節の例（`count = count + 1` と先読み）がほぼそのまま使えるので、実際の段差は関数部分とその返り値を2回使う部分（`result` を print と if の両方で使う）。ここで学習者が `judge_day(count)` を2回呼んで書くことは通るので、詰まりは少ない
  案: 必要なら、返り値を変数に入れてから表示と比較の両方に使う、という手順をヒントに足す。

- L7 場所: weekly-2026-10-13-b2「時給は整数に丸めます。」
  なぜ: 教えたのは `round()`、`int()`、`//` の3通り。4つの判定のケース（9000÷3、10000÷3、0÷5）では `round`、`int`、`//` のどれでも同じ答え（実行して確認: 3000、3333、0）。学習者は `round(pay / hours)` のつもりで書くが、`int(pay / hours)` でも通る。「丸める」と「切り捨てる」の違いは確かめられない
  案: 切り捨てと四捨五入を分けたいなら、割り切れず小数第1位が5以上になるケース（例: 給料5000、時間3 → 1666.67）を判定に足す。分けなくてよいなら何もしない。

- L8 場所: 冒頭「教材をまだ進めていなくても、問題に書いてある節を読めば解けます。」
  なぜ: 問題文そのものには節の指示が無い。節を指すのはヒントだけ（ヒントが開いてからでないと分からない）。「問題に書いてある」は「ヒントに書いてある」と読み替えないと合わない
  案: 「ヒントに書いてある節を読めば解けます」に直す。

- L9 場所: weekly-2026-10-13-b1「`charge(minutes, rate=20)`」ヒント2「延滞料金は『延滞した分数 × 1分あたりの料金』で求めます」
  なぜ: ヒント2が式を言ってしまっている（答えをそのまま言っている）。問題文には「1分あたりの料金」と書いてあるので、式は問題文だけで分かる。ヒント1（第5章3節）で十分
  案: ヒント2を消す。
