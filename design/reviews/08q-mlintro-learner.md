# タイタニック1（01-accuracy）予測と正解率

## 止まる

- **L1** 場所: python-08q-accuracy-b1（模範解答 `solutions/python-08q-accuracy-b1.py`）
  なぜ: 問題文の `<Input>` は「1行目: 1等で**生き残った**人数、2行目: 1等で**亡くなった**人数、3行目: 2等で生き残った、4行目: 2等で亡くなった…」。ところが模範解答は
  ```python
  first = int(input())
  first_survived = int(input())
  ...
  passengers = first + second + third
  second_died = second - second_survived
  ```
  と、奇数行を「その等級の人数」、偶数行を「生き残った人数」として読んでいる。判定のケースを模範解答で動かすと、出力は次のようになる（画面の出力例はケース1から出るので、学習者はこれを見る）。
  ```
  1等なら生存: -0.535
  全員亡くなった: -0.605
  差: 0.07
  ```
  ケース2〜4も `-1.0` `-1.333` `1.143` など、正解率としてありえない数になる。問題文どおりに正しく書いた学習者は、4ケースすべてで落ちる。出力例を見ても、なぜ負の正解率になるのか分からず、進めなくなる。
  問題文どおりの正しい出力は次のとおり（確かめ済み）。
  | ケース | 規則 | ベースライン | 差 |
  |---|---|---|---|
  | 136 80 87 97 119 372 | 0.679 | 0.616 | 0.063 |
  | 5 0 0 3 0 2 | 1.0 | 0.5 | 0.5 |
  | 0 0 1 3 2 4 | 0.7 | 0.7 | 0.0 |
  | 2 8 3 2 2 3 | 0.35 | 0.65 | -0.3 |
  ケース1は「丸めた2つを引く」と `0.06300000000000006` になるので、問題文の「丸める前の2つで引いてから丸める」を確かめる役もちゃんと果たせる。運営メモの 67.9% とも合う。
  案: 模範解答を、問題文の入力の順（生き残った・亡くなった の組を3つ）で読むように直す。

## 引っかかる

  なぜ: 「学習」「学習用」は、ボードより下の説明（「データを使って規則の数を決めることを学習と呼びます」「訓練データ（学習用データ）」）で初めて出る。節を開いて最初に読む問いに、まだ知らない語が2回出る。「境目」も、ボードの下の「困る例」で初めて意味が分かる。
  案: ボードの問いを「最初の30人でいちばん当たる境目を選ぶと…、選ぶのに使わなかった残りの10人では…」のように、まだ出ていない語を使わずに書く。

- **L6** 場所: 「これを訓練データ（学習用データ）と呼びます。残りの10人は学習に使わずに取っておいたテストデータで…」
  なぜ: 同じものに「訓練データ」「学習用データ」「学習用」の3つの呼び名がある。コードの出力・本文の続き・タイタニック4 はすべて「学習用」「テスト用」で、「訓練データ」はこの文のあと章の中に二度と出ない（部品の画面には出るかもしれない。L4）。学習者は「訓練データ」と「学習用」が同じかどうか、あとで迷う。

- **L7** 場所: 例のコード4〜13行目の `accuracy` の中の `ages[i]` `survived[i]`
  なぜ: 関数の外で作ったリストを、関数の中で引数として受け取らずに読んでいる。第5章のスコープの節は「関数の中で付けた名前は外では使えない」ことだけを教えていて、「外の名前は中から読める」ことは見せていない。学習者は「スコープで使えないと習ったのに、なぜ動くのか」で止まりうる。演習問題2（b1）ではリストを引数で受け取る形に変えるので、なおさら2つの違いが気になる。
  案: 説明に「関数の外で作ったリストは、関数の中から読める」と一文足す。

# タイタニック4（04-overfit）学習用に合わせすぎる

## 止まる

無し

## 引っかかる

- **L8** 場所: 例のコード9行目 `print(age[:30][sex[:30] != survived[:30]])` と、説明「9行目は、学習用で外れた6人の年齢を、ブールインデックスで並べています。」
  なぜ: 教わったブールインデックスは `scores[scores >= 60]` のように、取り出す配列そのものに条件を付ける形だけ。ここは (1) スライスした配列にさらに `[ ]` を続ける、(2) 条件を別の2つの配列（`sex` と `survived`）から作り、それで `age` を取り出す、の2つが初めての組み合わせ。説明は名前を言うだけで、「`sex` と `survived` が違う位置の `age` だけを取り出す」とは書いていない。
  案: 説明に、条件の配列は別の配列から作ってもよく、同じ位置の値が取り出されることを一文足す。

- **L9** 場所: 例のコード11〜22行目の `fine`
  なぜ: `if … return 1` が5つ続き、最後に `return s` がある形は初めて見る。`return` で関数が終わることは定義（「関数の実行を終え…」）にあるが、「どの条件にも当たらなければ最後の `return s`、つまり女性なら生存の予測になる」という読み方は書かれていない。説明は「条件を5つ足した規則です」だけ。
  案: 「どの if にも当たらなければ、最後の行で `sex` の値をそのまま予測として返す」と一文足す。

- **L10** 場所: 例のコード24〜28行目（`pred = []` から最後の `print` まで）
  なぜ: 説明がどこにも無い。とくに、`fine` の結果を一度リストに `append` してから `np.array(pred)` で配列にする理由が分からない。演習問題（b1）のヒントは「受け取ったリストを np.array() で配列にすると」とこの手順を前提にしている。
  案: 「24〜27行目で40人ぶんの予測を `fine` で作って配列にし、28行目で8行目と同じように正解率を出す」と一文足す。
