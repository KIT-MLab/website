# 練習問題集 第4章 後半3話題（append / while / total）読み手の報告

対象: `src/content/practice/04-loop/append.mdx` `while.mdx` `total.mdx`（各5問）と、模範解答 `solutions/practice-04-{append,while,total}-*.py`。
手順: 節（第4章1〜6節）と `taught.mjs` を読み、模範解答を見ずに自分の解答を考えたうえで、模範解答を全 `tests` の入力で実行した（15問 × 全ケース、すべて問題文の説明どおりの出力。落ちるものは無し）。そのあと、学習者が書きそうな別の書き方を実行して確かめた（scratchpad の `alt.py`）。

## 重い順の指摘

### R1 while-4「積み木を積む」: 節で教えた「最後に読み直す形」で書くと、全部のテストが EOFError になる
- どこで止まるか: 5節の形は「最初の1行を先に読み、繰り返しの最後でも読み直す」。ヒントは「第4章5節のように、繰り返しの条件を〜」と、その形を指している。この問題で同じ形に書くと（`block = int(input())` を前に置き、`while height < goal:` の最後でも `block = int(input())`）、塔が完成した回の最後にもう1行読もうとして、入力が尽きている。実行すると 入力例（20/8/5/9）、`0`、`5/5` のどれも `EOFError: EOF when reading a line` で、何も表示されない。
- 模範解答は「繰り返しの先頭で1個読む」形だが、節にその形の例は無い（部品の `input()` `int` は既習）。問題文の「必ず入力されます」からは、読み直しの形が使えないことが分からない。
- 案: ヒントを「積み木の高さは、繰り返しの中で1個ずつ読みます。読んだ数を高さに足し、個数を1つ増やします。繰り返すかどうかは、足す前の高さと目標で決めます」のように書き直す（5節の形は使えないと分かる文にする）。「第4章5節のように」は消す。
- 補足: 5節の形（先読み）が使えるのは、終わりの合図の行が入力に入っている while-5 だけである。この違いを学習者に気づかせる問題が、この3問の中に無い。

### R2 while-5「予算内の買い物」/ while-3 / while-1: 無限ループになりやすい書き間違いに、ヒントが届いていない
- while-5: 読み直しの `line = input()` を `if price <= budget:` の中に入れてしまう（インデントの間違い）と、予算を超える値段の入力で `line` が変わらず永久に回る。実行すると 入力 `0 / 100 / 終わり` で TIMEOUT。ヒントは「繰り返しの最後でも読み直す」までで、「読み直しは if の外、while の中の最後に書く」とは言っていない。案: ヒントに「読み直す行は、値段が買えたかどうかに関係なく、毎回実行される位置に書きます」を足す。
- while-3: `number // 10` と書くだけで `number = number // 10` と代入しない書き間違いで、無限ループ（実行して TIMEOUT）。ヒントは「取り除き方は第2章3節の `//` と `%`」で、計算した結果を入れ直す、とは言っていない。案: 「1の位を取り除いた数を、`number` に入れ直します。入れ直さないと、繰り返しが終わりません」。
- while-1: 「繰り返しが終わるように、繰り返しの中で数を入れ直します。第4章5節の最初のコードを見てください」。5節の最初のコードで入れ直しているのは `count = count + 1`（増やす）と `line = input()` で、「数を減らして条件を終わらせる」形は、そのコードには無い（節の冒頭の表の `n = n - 1` にある）。コードを見に行った学習者は、`input()` で終わらせる形を探してしまう。案: 「第4章5節の冒頭の表にある、`n = n - 1` の形を見てください」。

### R3 while-3「受付番号の各桁の和」: ★2 だが、問題の中でいちばん発想が要る。★3 の while-5 より難しい
- 考えることは、(1) 1の位を `% 10` で取る、(2) `// 10` で1の位を捨てて数を縮める、(3) 数が 0 になるまで繰り返す、(4) 足す変数、の4つ。節の例は「入力が `終わり` になるまで」の形だけで、「数を縮めて 0 で終わる」例は節の冒頭の表の `n = n - 1` しか無い。ヒントは (1)(2) の道具を名指ししているが、(3) の終わり方は言っていない。
- 一方 while-5（★3）は、節の課題 `python-04-while-b1`（終わりまで読んで足す）に `if` を1つ足した形で、考えることは (1) `int` に直すのは `終わり` を除いてから（ヒントに明記）、(2) 条件を比べる、(3) 残りを引く、の3つ。実際に迷う量は while-3 のほうが多い。
- 案: while-3 を ★3 にして while-5 と入れ替える（id は変えない約束なので、`level` と並びだけ変える）。または、while-3 のヒントに「`number` が 0 より大きい間、繰り返します」を足す。

### R4 append-5「最高点を除く」: `max()` で1行で通る
- 実行確認: `points.remove(max(points))` で 入力例のとおり `[8, 7, 9, 6]` が出て通る。この問題の狙いは、ヒントが指す「2節の最大を探す手順」を使うこと。同じ章の total-3 は `forbid={['max(', 'min(']}` と、問題文の一文で禁じているが、append-5 には無い。
- 学習者は `max()` を知らない前提なので重くはないが、`forbid` と問題文の一文が total-3 と揃っていない。
- 案: `forbid={['max(']}` を足し、問題文に「`max()` は使わず、繰り返しで探してください。」。

### R5 while-2「バケツで水を運ぶ」: 割り算を禁じたが、`/` と `%` で繰り返しなしに通る
- `count = int(need / bucket)` のあと `if need % bucket != 0:` で1足す、で全テストが通る（実行確認。4、0、3、1）。`forbid` が `//` だけで、`/` を禁じていない。問題文も「割り算（`//`）は使わず」としか言っていない。
- 案: `forbid={['/']}`（`//` も含まれる）にして、問題文を「割り算（`/` と `//`）は使わず、繰り返しで求めてください」。
- 補足（R9 に続く）: while-2 と while-4 は、手順がほとんど同じ。

### R6 while-4「積み木を積む」: 「積み木の高さは1個ずつ違い」が、テストの入力と合わない
- 「1個ずつ違い」と読むと、「どの積み木も別の高さ」と取れる。しかしテストの入力は `5/5` や `10/3/3/3/3` で、同じ高さが並ぶ。学習者は「同じ高さは来ない」と思って、同じ値で試したときに戸惑う。
- 案: 「積み木の高さは、1個ごとに入力されます」。または「積み木の高さは同じとは限りません。積むたびに入力されます」。

### R7 append-2「ロッカーの返却」: 使用中の番号のリストを、どこに書くのかが読み取れない
- 「使用中の番号を、リストにまとめておきます」は、すでにリストがあるような言い方に読める。入力は返却された番号の1行だけで、リストは入力に無い。学習者は「リストはどこにある？」と止まる。
- さらに、`lockers.remove(input())` と書くと `ValueError: list.remove(x): x not in list`（文字列 `"5"` はリストに無い）。問題文は整数に直すことを言わない（append-1 の入力の説明のように「整数」とも書いていない）。
- 案: 「使用中の番号は 0、3、5、8、12 の5つです。この5つを、プログラムの中でリストにして、返却された番号を取り除いてください。」入力の説明は「返却されたロッカーの番号（整数）」。
- 補足: 入力例が `5` で、問題文の「5つ」と同じ数字に見える。「5番」が返却される例だと気づかれにくい。ケース1を `3` か `8` にすると、番号だと分かりやすい（`tests` の先頭の入れ替えだけで済む）。
- 問題としては、節の課題 `python-04-append-m1` とほぼ同じ（`remove` の値を、入力から取るだけ）。考えることは 0〜1 個。★1 としては妥当だが、この問題を消すと確かめられなくなることは「`remove` に変数を渡す」くらいしか無い。append-3 が `remove` を含むので、消しても失うものは小さい。

### R8 append-5「最高点を除く」: 「集計します」が何を指すか分からない
- 「最も高い点数を1つだけ除いて、残りを集計します」と書いてあるが、求めるのは合計ではなく、除いたあとのリスト。「集計」を見て、合計や平均を探す学習者がいる。
- 案: 「体操の競技で、審判が出した点数のうち、最も高い点数を1つだけ除きます。」（「残りを集計します」は消す。除いたあとのリストを出すことは、次の段落と `<Output>` が言っている）。

### R9 題材・手順の重なり
- while-2（バケツ）と while-4（積み木）: どちらも「足していき、目標以上になったら止まる。止まるまでの回数を数える」で同じ手順。違いは、足す量が毎回同じか、入力から1個ずつ読むか。while-4 は、手順の変化が「入力を繰り返しの先頭で読む」だけで、それは R1 のとおり節で教えていない。重なりを減らすなら、while-2 を別の手順（例: 回数が決まっていないが、入力を読まない、数を半分にし続ける）に替える案があるが、題材の選び直しになるので、採否は任せる。
- append-3（注文の取り消し）は、append-1（集める）と append-2（取り除く）を続けた形で、新しいことは「同じ値が複数あるとき、最初の1つだけ消える」だけ。それは問題文に書いてあり、学習者は迷わない。★2 の段差としては小さい。
- 最大を探す手順は append-5 と total-3 の2か所（と節の課題 `python-04-list-b1` の最小）。total-3 は最大・最小の両方で、append-5 より1つ多い。重なりは許容範囲。
- スポーツの記録が3問: append-1（走り幅跳び）、append-5（体操）、total-3（砲丸投げ）。手順は別なので問題は無いが、題材が似る。
- 節の課題との近さ: while-5 ≈ `python-04-while-b1`（`終わり` まで読んで整数を足す）に条件分岐を足したもの。total-1 ≈ `python-04-for-b1`（合計）の入力版。append-1 ≈ 4節の最後の例の人数を変数にしただけ。いずれも「そっくり」とまでは言えないが、★1 の total-1・append-1 は、節の例からの差が1個。

### R10 total-3「投てきの最長と最短」: 最小の出発値を 0 にしてしまう
- 最大のコードをまねして `shortest = 0` から始めると、最小がいつも 0 のまま（実行確認: 入力例で `720` と `0` が出て不合格）。ヒントは「比べる向きが逆になります」だけで、出発値の決め方に触れていない。2節の例は、出発値を最初の1行にしている。
- 案: ヒントに「最大も最小も、出発値は最初の記録にします」を足す。ただしこれは答えの一部なので、「出発値を 0 にすると、最小が正しく出ません」と注意する形でもよい。

### R11 total-4「勤務時間の合計」: ★2 にしては考えることが多い
- 考えることは、(1) 7行を先に読んでリストにする、(2) その後ろの2行（はじめ・終わり）を読む、(3) 日付とインデックスの1のずれを直す、(4) `range(first - 1, last)` のように、`range` に式を渡す（節の例は `range(1, 4)` のような数だけ）、(5) 合計を足す。5個。別の道（`for i in range(7)` で `if i + 1 >= first and i + 1 <= last:`）も通るが、それも (3)(4) の代わりに同じくらい考える。
- ヒント: 「`i` 日目の勤務時間は、リストのどのインデックスにあるか」。問題文に `i` は出てこない。「ある日の勤務時間が、リストのどのインデックスにあるか」と書くほうが分かりやすい。
- 案: ★3 にする（total-5 と入れ替える。total-5 は、ヒントが手順を全部言っているので、実際の負担は ★2 に近い。R12 参照）。

### R12 total-5「平均を超えた人数」: ヒントが手順をほとんど言っている
- ヒントは「平均は全員を足し終えてから求める」「もう一度全員を見るので、リストに残す」と、(1) 2回に分ける、(2) リストを使う、の2つを先に言っている。★3 の考えることは3個のはずだが、残るのは「足す・平均を出す・数える」の組み立てだけになる。
- 案: ヒントを2段にする（1つ目: 「平均は、全員の点数を足し終えてから求めます」。2つ目: 「そのあと、もう一度全員の点数を見るので、点数はリストに残しておきます」）。
- 確認: `/` と `//` を取り違えても、人数は変わらない（整数の点数が `平均より大きい` ことと `平均の切り捨てより大きい` ことは同じ）ので、取り違えで落ちることはない。小数の誤差による境目の問題も無い。

### R13 「`sum()` `max()` `min()` は使わず」という一文が、知らない関数の名前を出している
- total-1/4/5（`sum()`）と total-3（`max()` `min()`）は、学習者が一度も見ていない関数の名前を、問題文で禁じている。学習者は「それは何？ 使えると楽なのか？」と引っかかる。`forbid` は、すでに知っている人を止めるために必要。
- 案: 「（合計を出す `sum()` という関数がありますが、ここでは使いません。）」のように、一言添える。または、問題文からは消して `forbid` だけにする（上の `forbid` の一文があるほうが、通らなかったときの理由が画面に出るので、残すほうがよい。判断は任せる）。

### R14 while-4/while-5 の入力: 例の見え方
- while-4 のヒント「何個で終わるかは、先に決まりません」は、先に決まらないこと（先に個数が分からない）と、入力の読み方（繰り返しの中で1個ずつ）の関係を言っていない。R1 の直しに含める。
- while-5 のヒント「最初の1行を先に読み」の「最初の1行」は、5節では判定に使う最初の行。この問題では、最初の1行は予算なので、「予算の次の行を先に読み」と書くほうが、学習者が取り違えない（予算を読んだあとに、`line = input()` をもう1つ書く）。
