# 練習問題集 第8章（index / transpose / make）学習者の目での読み

読んだもの: `src/content/practice/08-table/{index,transpose,make}.mdx` の15問、模範解答 `practice-08-*.py`、第8章の節1〜5、第7章5・6節。
全問、模範解答と全 tests の入力で実行して出力を確かめた（15問・計60ケース）。模範解答はどのケースでも問題文どおりの出力になる。出力の食い違いで落ちる問題文の欠けは無かった（下の「出力の見た目」参照）。

## 止まる

- なし。ただし R1 は、ヒントを使っても止まる可能性が高い。

## 引っかかる（重い順）

### R1 transpose-5（★3）: 最後の `.T` と `(式).T` が、問題文にもヒントにも出てこない
- 模範解答は `print((scores.T - average).T)`。ヒント2は「行と列を入れ替える書き方で、表の形を合わせます」までで、**引き算のあと、もう一度入れ替えて元の向きに戻す**ことは書いていない。問題文は「人ごとに1行」と出力の向きを言っているので、学習者は `(2, 3)` で出た結果を見て自分で気づく必要がある。
- `(式全体).T` は初めての組み合わせ。第8章3節の例は `(scores - average)[0]` だけで、かっこのあとに `.T` を付ける形はどこにも無い。
- 考えること: (1) `axis=1` を選ぶ (2) 長さが合わず、表を転置して合わせる (3) 引いた結果を転置し直す。★3 は3個でちょうどだが、(2)(3) は「列の数と長さが合うときだけ引ける」という第8章3節の最後の1文を、逆向きに使う力が要り、transpose-3（★2）からの段差が大きい。
- 案: ヒントを1つ足す。「引き算の結果は、行と列が入れ替わった向きで出ます。問題が求める向きに戻してください。」答えの式は言わない。

### R2 transpose-2 / transpose-4: `forbid` の `'for '` が、第7章7節で教わった読み取り方も落とす
- 第7章7節の例（`for i in range(2): table.append([int(input()), ...])`）を真似て、読み取りに `for` を使った学習者が不合格になる。問題文は「for文は使わないでください」とだけ書いてあり、**計算にだけ使わない**のか、**読み取りにも使えない**のかが読み取れない（transpose-2 は9行、transpose-4 は9行読む）。模範解答は `table.append([...])` を同じ行で並べて書いていて、これは第7章5節の例の形。
- 同じ決まりは節の課題 broadcast-b1 にもある。
- 案: 問題文を「読み取りにも for は使えません。同じ行を並べて書いてください」に直す。または `forbid` をやめて、問題文から「for文は使わないでください」を消す（どちらの問題も、`for` を使っても配列の計算は同じ）。

### R3 index-1 / index-3: 第7章の書き方で通る（この話題を使わずに通る）
- index-1: `parking[floor][area]`（第7章5節の `[行][列]`）で通る。節の課題 index-b1 は `forbid=['for ', '][']` で塞いでいるが、index-1 は塞いでいない。
- index-3: `scores[person]`（第7章5節の `scores[0]`）で通る。`scores[person, :]` を使う必要が無い。`,` を含む形を要求する `forbid` は作れないので、直すなら問題側。
- 案: index-1 に `forbid={['][']}` を足す。index-3 は、行を取り出すだけの問題にせず「指定した人の点数を、列を指定して比べる」など `[:, k]` と `[k, :]` の両方が要る形にする。または、index-3 は「通る別の道がある」と承知して残す。

### R4 make-1: テストケース3が問題の筋と合わない
- 問題は「いちばん下の目盛り」と「いちばん上の目盛り」。ケース3は `30`, `20`, `3` で、いちばん下（30度）がいちばん上（20度）より高い。出力は `[30. 25. 20.]`。温度計として読むと矛盾する。
- 案: ケースを `20 30 3`（または `10 30 3`）にする。減る向きを確かめたいなら、入力欄の説明に「いちばん下の温度は、いちばん上の温度より低いとは限りません」と書く。

### R5 節の課題と、ほぼ同じ手順の問題が多い
- transpose-1 ＝ 節 transpose-b1（2人3科目を読み、`.T`）から `shape` の表示を除いただけ。手順が同じ。
- index-2 ＝ 節 index-b1（3×3を読み、変数の列を取り出す）から平均を除いただけ。
- transpose-2 ＝ 節 broadcast-b1（表から1次元配列を引く）。引くものが「平均」から「入力で与える目標」に変わっただけ。
- make-2 ＝ 節 reshape-b1（1列に読み、reshape で表にする）。人数が固定になっただけ。make-4 はそこに `sum(axis=0)` を足した形。
- 問題の中でも、transpose-2 と transpose-4 は「3列の表から、3個の並びを引く」で同じ。違うのは、並びが入力から来るか、`stock[0]` かだけ。
- ★1 は節の課題の言い直しで構わないが、transpose-4 は「引く並びを、表の1行目から取る」が違いとして残るので問題として成り立つ。transpose-1 と index-2 は、節の課題を解いた学習者には、考えることが0個になる可能性がある。
- 案: transpose-1 は、行と列を入れ替えたあとで1行ぶんだけ取り出す（`.T` のあとにインデックス）など1つ足す。または置き換える。

### R6 初めての組み合わせ（すべて、値が変わるだけではない）
- index-1: `parking[floor, area]`、index-2: `visitors[:, slot]`、index-3: `scores[person, :]`、index-5: `rain[:, point]`。**`[ ]` の中に変数を書く**のは、第8章1節の例（`0, 1` などの数字だけ）に無い。第7章の `scores[:k]` で変数を書く形は見ているので、止まるほどではない。
- index-5: `column[column > column.mean()]` は、`[ ]` の中の条件に、同じ配列の計算 `column.mean()` を書く。第7章3節の `scores[scores >= 60]` は右が数字だけ。
- make-3: `np.arange(1, days + 1) * 10` は `arange` の引数に式を書き、結果にそのまま掛ける。第8章4節の例は数字の引数と、変数に入れた配列の `** 2`。
- make-4: `np.array(values).reshape(weeks, 5)` と `range(weeks * 5)`。`reshape` に変数、`range` に式。
- make-5: `np.arange(1, rows * columns + 1).reshape(rows, columns)` と `seats.T`。
- transpose-5: `(scores.T - average).T`（R1）。
- 案: 上のうち、`reshape` に変数、`[ ]` の中に変数、は★1〜2の問題でも出てくるので、ヒントに「`[ ]` の中の数字を、変数に替えてかまいません」のような一言があると止まらない。いまのヒントは節の行を指すだけで、変数に替えてよいとは言っていない。

### R7 make-5: `reshape(m, n)` と書く学習者がいる
- 問題文は「n行m列に番号を付け、行と列を入れ替えた向きで表示」。出力の説明は「表は m 行 n 列になります」。`reshape(m, n)` でも「m 行 n 列」にはなるが、中身が違う（`2 3` で `[[1 2] [3 4] [5 6]]` になり、期待は `[[1 4] [2 5] [3 6]]`）。
- 画面が自動で出す出力例（ケース1）で見比べれば気づけるので、止まるとまでは言えない。問題文に1文あると親切: 「番号は、まず n 行 m 列の座席に付けたものです」。

## 出力の見た目（戸惑うか）

- 2次元配列が複数行で出る: transpose-1〜5・make-2・make-5。問題文に「配列のまま」とあり、出力例が画面に出る。戸惑わない。
- 小数の点: transpose-5・make-1 は問題文に `5.` `10.` の例が書いてある。`[ 0.   2.5  5.   7.5 10. ]` のように、桁をそろえる空白が入るのは出力例を見れば分かる。
- 空の配列 `[]`: index-5・make-3 は問題文に書いてある。
- 負の数で列がずれる（`[[  5   0 -22]` など）: 自分で `print` した結果と同じ空白になるので問題ない。
- 「配列のまま」という言い方は、数学の言葉のようで、学習者が「リストにしない」の意味だと分かるか少し気になる。ただし出力例が画面に出るので、引っかかっても進める。

## 整数・小数、0 始まり・1 始まり

- 行・列の番号を入力で読む問題（index-1, 2, 3, 5）は、全部「0が…」と問題文に書いてある。index-4 は番号を読まないが、「1回目」→ インデックス0、「3回目」→ インデックス2 を学習者が自分で対応させる（これは★2の考えることの1つで、意図どおり）。
- `/` と `//` の取り違えで見た目が変わる問題は無い（transpose-5 は `mean` の小数のみ）。`np.linspace` を使えば make-1 は小数で出る。`np.arange` で刻みを自分で計算した場合、`np.arange(low, high + step, step)` は数が1つ増えることがあるが、`linspace` を教えた節の直後なので、そう書く学習者は少ない。
- make-3 で `np.arange(10, days * 10 + 10, 10)` と書くと、日数0のとき `[10]` になって落ちる（これは意図どおりで、ケース `0` が拾う）。問題文に `[]` が書いてあるので、気づける。

## ヒントの確かめ

- 15問のヒントが指す「節・コードの何行目」は、すべて節を開いて確かめた。`index` 1〜3、`transpose` 1・2・4、`make` 1〜3 の行番号は合っている。
