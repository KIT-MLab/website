# 練習問題集 第7章（array / stats / select 各5問）初見の学習者の読み

読み方: `taught.mjs python-07-slice`（第7章3節まで）と `python-08-index`（第7章の終わりまで）を見て、15問を自分で解き、模範解答と全テストの入力で出力を比べた。numpy は使える（`py`）。
結果: 模範解答は全テストで正常に動く。問題文だけで出力が決まらない問題は無い（R1 の `//` だけ、決まっても見た目が合わない道がある）。止まって進めなくなる所は無い。引っかかる所を重い順に書く。

## R1 array-3「摂氏から華氏へ」（★2）: `//` で割ると型が変わって不合格になる

- 入力に「5の倍数の整数」とあるので、5で割り切れる。第2章3節で習った `//`（商）が目に入りやすい。実際に `celsius * 9 // 5 + 32` と書くと、値は同じでも整数の配列になり、`[32 50 77 95]` と表示される（正解は `[32. 50. 77. 95.]`）。
- 学習者は「値は合っているのに違う」と感じる。出力例の `32.` の点が何か、第7章3節までには説明が無い（点の説明は6節の最後の段落だけ）。
- 「5の倍数」という条件は、学習者から見ると理由が分からない。
- 案: 条件の「5の倍数の」を外す（`/` で書くと 1 のような値でも通る）。Output に「小数のまま表示します」と一言足す。

## R2 select-4「あと何点で合格」（★2）: ヒントの「配列から引き算」の向きが逆。`60 - low` は未習の形

- ヒント2「取り出した配列に対して、配列から引き算する計算（第7章1節）をします」。1節の例は `scores + 10`（配列が左・数が右）と、配列どうしの引き算だけ。模範解答は `60 - low`（数が左・配列が右）で、この形はどこにも出ていない。
- 「配列から引く」は `low - 60` に読める。そう書くと `[-15  -1]` が出て、出力例 `[15  1]` と符号が逆になる。学習者は気づけるが、なぜ `60 - low` と書けるのかは分からないまま通る（`+ - * / **` は要素ごと、とだけ1節に書いてある）。
- 案: ヒント2を「60から、取り出した配列を引きます。数が左、配列が右でも、すべての値から引けます」に直す。または問題を「何点超えたか」の形にして配列が左に来るようにする。
- 自分で考える数は2個（取り出す、引く）で、★2の目安どおり。

## R3 array-5「2店の売上個数」（★3）: 2次元配列を使わなくても通る。stats-5 は節の課題とそっくり

- array-5: 1店目と2店目を別々の1次元配列（`a`, `b`）にして `print(a + b)`、`print(b[2])` で通る。リストの `[2]` は第4章で習済み。すると array-2（★1）と同じ手順で、第7章5節（2次元配列）が確かめられない。ヒント1が2次元に誘導しているので、ヒントに従えば2次元になるが、問題自体は強制しない。
  - 案: 店の数を3にして「日ごとの全店の合計」を `axis=0` で出させる（stats-5 と被るので、array 側は「2店目の行をそのまま取り出す」`sales[1]` など、行を取り出す問いに変える）。`sales[0]` と `sales[1][2]` を求める問いにすれば、2次元でないと自然に書けない。
- stats-5: 節の課題 `python-07-stats-b1`（2人×3科目の2次元配列→軸0と軸1の集計）と同じ手順。違いは集計が sum/min、行が3つ、の3点だけ。確かめることが新しくない。
  - 案: 軸の向きを取り違えやすい問いに替える（例: 店ごとの最大の売上の曜日の値、を軸指定で出し、答えが縦横どちらから出たかを選ばせる）、または `axis` を使わないと書けない別の形にする。決めるのは書き手側。
- array-5 と stats-5 は、題材も「店×3日の表を `append` で作る」手順も重なる（R9）。

## R4 語: 「損益」「該当する」

- select-2「お店の5日間の損益を記録しました。損益が負の数（赤字）だった日の金額…」: 「損益」は経済学部以外の1年生に通じるとは限らない。「赤字」は括弧で説明があるが、「損益」自体は説明が無い。
  - 案: 「お店の5日間の、1日ごとのもうけ（売上から費用を引いた金額。赤字の日は負の数）を記録しました。赤字だった日の金額だけを取り出してください。」、Input も「5日間のもうけ（円、整数）」。
- select-1・select-5 の Output「該当する日が無いときは」: 「該当」は硬い。案: select-1「25度以上の日が無いときは」、select-5「超えた日が無いときは」（select-4 のように条件で言い直す）。
- select-1 の題「夏日」: 本文に「25度以上」と定義があるので問題は無い（題だけでは分からないが、画面の題の下に本文が続く）。
- array-4 ヒント2「縦と横の和の2倍」: 「和」より「縦と横を足したものの2倍」のほうが他の文と揃う（引っかかる程度）。

## R5 array-2「午前と午後の歩数」: 問題文の一文が分かりにくい

- 「日ごとの1日の歩数を求めてください」: 「日ごとの」と「1日の」が重なって、何を足すのか読み取りにくい（午前と午後を足すことは Input を読めば分かる）。
- 案: 「日ごとに、午前と午後を合わせた1日の歩数を求めてください。」

## R6 出力例の配列の見た目: 空白と小数点

- array-1 の出力例（ケース1）は `[ 900 1350 1560]`。`[` のあとに空白が入る。array-3 は `[32. 50. 77. 95.]`、stats-4 は `[-15.   5.  -5.  15.]`、select-2 は `[-200  -50]`、select-4 は `[15  1]`。桁をそろえて空白が入る、`15.` の点は `15.0` の略、という説明は、第7章の6節（`70.` の段落）にしか無い。1節は「空白で区切る」とだけ書いてある。
- 学習者は `print` した結果をそのまま出すだけなので進める。ただ、手で並べた文字と合わなくなったときに気づけない。
- 案: ★2の array-3 と stats-4 の問題文（Output）に「小数点のあとの0は省かれ、`15.` のように表示されます」を足す。空白の件は、どの問題でも `print` した結果をそのまま出せば合う、と stats-1 のような最初の問題に一言添えれば足りる。優先度は低い。

## R7 stats-1・stats-3: numpy の `mean()` `sum()` を使わずに通る

- stats-1（5日間の平均気温）は `(a + b + c + d + e) / 5` で通る（`21.0` も合う）。stats-3（4週間の合計と目標まで）は `a + b + c + d` と変数で通る。`forbid` は `for ` だけ。
- 5個・4個なら、numpy を使わない道が「明らかに長い」とまでは言えない。
- 案: 気になるなら `forbid` に `+` を足す（ただし stats-3 の `300 - total` は `-` なので影響しない）。stats-1 は `forbid={['for ', '+']}`、stats-3 は `forbid={['for ', '+']}`。

## R8 select-3 のヒントが答えの形を言っている

- hint「条件で取り出した配列にも、第7章2節の合計を求める書き方が使えます」は、この問題が確かめる「取り出す→足す」の組み合わせそのもの。ヒントが1つだけなので、読むと考える所が残らない。
- 案: 「取り出した結果も配列です。配列にできることは、第7章2節にあります」くらいに薄める。

## R9 題材の重なりと、手順が同じ問題

- 歩数: array-2、stats-2、select-5。気温: array-3、stats-1、select-1。店×日の表: array-5、stats-5。お金の話: array-1、select-2、select-3。同じ題材が2〜3回出る。
- 手順が同じもの: select-1 と select-2（条件で取り出して表示。違いは `>=` と `<` だけ。どちらも★1）。array-1 と stats-1 と stats-2 と array-2 は「入力を配列にして、1つのメソッド（または演算）を使う」で同じ形。★1の課題は全て「配列を作る→1操作」。
- 節の課題とそっくり: array-2 は `python-07-array-b1`（2つの3値の配列を引き算）の足し算版。stats-5 は `python-07-stats-b1`（R3）。select-5 は `python-07-slice-b1` と入力の形（1行目 k、続く6行）が同じ（確かめることは違う）。
- 案: 気温と歩数のどちらかを別の題材（体重、電車の本数など）に替える。select-2 は「0以下の日が無い」など条件の形を変えるか、select-1 と統合する。

## R10 stats-5 のヒント2の指し先

- hint2「…どちらが `axis=0` でどちらが `axis=1` かは、第7章6節の `shape` の説明で確かめます」。6節には `shape` の独立した説明は無く、`axis=0` の段落の中で「`shape` の `(2, 3)` の0番目」と触れているだけ。`shape` の説明は5節。学習者は6節で `shape` の見出しを探して戸惑う。
- 案: 「…は、第7章6節の `axis=0` と `axis=1` の説明で確かめます」。

## 段差

★1（1操作）→★2（式を組む、取り出して計算）→★3（2次元、またはスライス＋全体の平均）で、基本は上がっている。array-5 は R3 のとおり1次元で通るため、★3の段差が出ない。stats-3 は考えることが1〜2個で★2としては軽い。

## 全体として

直したほうがよいのは、R1（array-3 の `//`）、R2（select-4 のヒントと `60 - low`）、R3（array-5 が2次元を要求しない、stats-5 が節の課題と同形）。R4〜R10 は文言と重なりの調整。

## 問題文と出力の関係

全15問で、問題文と Input・Output の説明に従えば出力が決まる（R1 の `//` を除く）。条件の境目は、select-1（25）・select-3（1000）・select-4（60）・select-5（平均と同じ値）のテストで確かめられる。「超えた」「以上」「届かなかった」の使い分けも正しい。
