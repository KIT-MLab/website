## 止まる（ここで学習者が進めなくなる）

- L1 場所: weekly-2026-10-13-b3 のヒント2「for文の中でif文を使って、条件に合うときだけ数を増やします。第4章1節（for文で繰り返す）を読んでください。」
  なぜ: 4-1 を開くと、書いてあるのは `for i in range(...)` と `total = total + i` だけ。**リストの値を順に取り出す `for value in counts:` も、for の中の if も、4-1 には無い**。どちらも 4-2（リストで値をまとめて持つ。`largest` の例）にある。はじめの「教材をまだ進めていなくても、ヒントに書いてある節を読めば解けます」は、この問題では成り立たない。「ここまでに教えた」を全部持っている学習者なら 4-2 の形を思い出して通るが、ヒントの節だけ読む人は、リスト `counts` の中身を1つずつ見る書き方がどこにも見つからない。
  案: ヒント2の節を「第4章2節（リストで値をまとめて持つ）」に直す（4-2 に for の中の if と、条件が成り立つとき入れ直す形がある）。

## 引っかかる（進めるが、迷うか、分からないまま通る）

- L2 場所: b3 ヒント1「入力の行をリストに集める書き方は、第4章4節の2つ目のコードにあります」
  なぜ: 4-4 の2つ目のコードは `for i in range(3):` と回数が数字で書いてあり、入力に「人数」の行は無い。b3 では1行目が人数 `n` で、`n = int(input())` を先に読み、`range(n)` に変数を入れる必要がある。`range` に変数を入れる形は「値が違うだけ」とは言い切れず（4-1 の例は数字、4-3 の `range(len(numbers))` が近い）、「先に人数を読む」の一手は問題文にもヒントにも書かれていない。通れるが、4-4 のコードを写しただけでは動かない。
  案: ヒント1に「1行目の人数を先に読み、その数だけ繰り返します」の一文を足す。

- L3 場所: b2 ヒント2「割る数が0かを先に確かめる形は、第6章3節（TypeErrorとValueError）の2つ目の問題と同じです。」
  なぜ: 6-3 の本文（説明と例）には、0で割る話も、割る数を先に確かめる形も無い。あるのは「2つ目の問題」（06-type-b1）の**問題文だけ**で、模範解答は学習者に見えない。問題文は「2つ目が0のとき `計算できません` と表示」と言うだけなので、「同じ形」を見て書き方が分かるわけではない（分かるのは、やはり3-1 の if と `==`）。さらに、`ZeroDivisionError` という名前もどこにも出ない。ヒント1の方が役に立っていて、ヒント2は誰のどの文を読めばよいかが空振りになる。
  案: ヒント2を「`if hours == 0:` のように、割る前に調べます。第3章1節の `==`」のように、本文にある書き方に向ける。

- L4 場所: b4（judge_day と while と数える処理を1問に組む）
  なぜ: 模範解答の1行ごとに見たところは全部「教えた」にあるが、**組み合わせが初めてのものが4つ**ある。(1) `def` の中の `if` で値を `return` し、if の外にもう1つ `return`（4-5 の例にも 5-3 の本文にも無く、5-3 の課題 judge と同じ形だが解答は見えない）、(2) `while` の中で、文字列のままの `line` を `終わり` と比べたあとに `int(line)` にする（4-5-b1 のヒントにしか書かれていない）、(3) 返ってきた言葉を変数に入れてから `if result == "注意":` で数える、(4) 最後の `f"注意 {warnings}日"`。例から模範解答までに自分で考えることは、数えて4つ。3を超えていて、この回でいちばん段差が大きい。ヒント2は「数える」とだけ言い、「返ってきた値を一度変数に入れる」ことは言っていない。
  案: 問題を2つに分ける（判定の関数だけ／while で読んで数える）か、ヒント2に「返ってきた言葉を変数に入れて、その言葉で if を書く」を足す。

- L5 場所: b2「時給は整数に丸めます」と、判定の4ケース
  なぜ: `round(pay / hours)` でも `int(pay / hours)` でも `pay // hours` でも、4つのケースを全部通る（10000÷3 = 3333.33… は切り捨てても丸めても 3333。ちょうど .5 になる値が1つも無い）。「整数に丸める」を確かめるケースが無いので、`round` を使ったかどうかは判定されない。
  案: 丸めと切り捨てが分かれる値（例: 給料 8000、時間 3 → 2666.67 で、`round` は 2667、`int` は 2666）を1ケース足す。

- L6 場所: m1 ヒント2「def の行の () の中に書いてある名前と、return の行で使っている名前を見比べてください」
  なぜ: 直す場所（`english_socre`）の見つけ方をほぼそのまま言っている。ヒント1だけで、エラーの最終行に `english_socre` が出るので足りる。ヒント2は答え寄りで、学習者が自分で気づく所を奪う。
  案: ヒント2を「エラーに出た名前を、def の行で作った名前と1文字ずつ見比べる」程度にする、または消す。

## 要らない（消しても何も失わない文・問題）

- 場所: b1「`charge(minutes, rate=20)`」問題そのもの
  なぜ: 「デフォルト値のある関数を書き、`return` で料金を返す」は 5-3 の例とほぼ同じ（`amount * (1 + rate)` が `minutes * rate` になるだけ）。しかも b5 が、デフォルト値のある関数をそのうえで呼び出し方まで確かめている。b1 を消しても b5 が同じものを確かめる。肩慣らしとして置くなら残してよいが、確かめる役は無い。
- 場所: m1（total_score の綴りミス）
  なぜ: 6-1 の課題（`mesage`）と同じく、名前の綴り違いを NameError から読み取って直す問題。違いは、直す名前が def の引数の名前に対する綴り違いであることだけ。ほかの問題（b1〜b4）が全部、エラー無しで動くことを確かめているので、「エラーを読む」を回に1問入れる意味はあるが、新しく確かめることはほぼ無い。
