## 引っかかる（章を通して、重い順）

### L1（3節 input-basic）質問つきの input の例で、「19」がどこから出た文字か分からない
- 場所: `age = input("あなたの年齢は？")` / `print(age, "歳です")` と、出力 `あなたの年齢は？19 歳です`、直後の「質問の後ろに答えを薄い色で出します」
  なぜ: 出力は1行で、`19` は1回しか出ない。一方、説明は「答えを質問の後ろに薄く出す」と言う。学習者には、`19` は薄く出た答えなのか、`print(age, ...)` が出した `19` なのか、両方なら2回出るはずでは、と区別がつかない。「ふつうのパソコンで動かすと…その後ろに答えを打ち込みます」も、打ち込んだあとの改行がこの出力にあるのか無いのか、説明がない。「ふつうのパソコン」も何を指すか曖昧。
  案: 質問つき input の例では、薄く出る部分と print が出す部分が見分けられるように、出力の書き方（または説明）を直す。

### L2（5節 fstring）`+` と `str()` は文章だけで、実行して見る機会も、使う課題も無い
- 場所: 「文字列どうしは `+` で…」「`"点数は" + 80` …エラーで止まります」「先に `str()` で数を文字列に変えます」
  なぜ: `<Run>` が無く、エラーも実際には見えない。課題で使うのは b2（`+` で3つつなぐ）だけで、`str()` を使う課題は章のどこにも無い。b2 は `{}` の中に `input()` を書いても通りそうだが、`{}` の中に書いてよいのは「計算の式」とだけ説明されている。ヒント1が `+` に誘導するので学習者は進めるが、`str()` は読んだだけで終わる。
  案: `+` と `str()` の短い `<Run>` を1つ足す（または `str()` を使わせる小さな課題を足す）。使わないなら説明を削る。

### L3（6節 scores / m1）変数は使う前に作る、という順番が教わっていない
- 場所: `python-01-scores-m1`「`english = 70` も合計に加えてください」
  なぜ: starter は `total = japanese + mathematics` の行が先にある。学習者が `english = 70` を `total` の行より後ろに書くと、`english` がまだ無い状態で計算してエラーになる。2節の「あとの行で `price = 150` と書くと置き換わる」は読んだが、「上の行から順に実行される／使う前に入れておく」は書かれていない。エラーの理由が学習者に分からない。
  案: 2節で「上の行から順に実行する」を1文足す。または m1 の問題文に「`total` を計算する行より前に」と添える。

### L4（3節 input-basic / c1）選択肢の正解の番号が、学習者の目では確かめられない（確認依頼）
- 場所: `python-01-input-basic-c1`、`correct: 2`、選択肢3つ
  なぜ: 学習者としての正解は2番目の「`こんにちは 3 + 4`」。`correct: 2` が1始まりなら合うが、0始まりなら3番目「エラーで止まる」が正解になってしまう。画面の仕様は私には見えないので、書いた人が確認してほしい。
  案: `correct` の数え方（0始まりか1始まりか）を確かめる。
- 補足: この問題は「最初のコードの入力欄を書き換えて ▶」と、1つ前の `<Run>` を直接いじる指示。入力欄が書き換えられる状態で出る前提。

### L5（5節 fstring / m1, m2）「改造」の問題文だけでは、出力全体の形が分からない
- 場所: m1「`点数:95` の後ろに `点` を付けて `点数:95点` と表示」／ m2「`点数:95点 名前:鈴木` のように…」
  なぜ: m1 は、starter の出力 `名前:鈴木 点数:95` のうち `名前:鈴木` を残すのかどうか、文面から確定しない（「後ろに付ける」から残すと推測はできる）。modify 問題には入力例・出力例の自動表示がないので、確かめる手がかりが無い。m2 の「のように」も、完全一致が必要かが曖昧。
  案: m1 は「`名前:鈴木 点数:95点` と表示」と1行全体を書く。m2 も「のように」を「と」にして全体を書く。

### L6（1節 print）言葉がいくつか、説明なしに出る
- 場所: 「かっこの中に書いた値を画面に表示する命令」「`print` は1回呼ぶごとに1行を表示します」
  なぜ: 「値」「命令」「呼ぶ」は定義がない。この節では文脈で読めるが、「呼ぶ」（＝書いて動かす）は3節以降もそのまま使われる（`input()` は呼ぶたびに…）。また `"5"`（文字）と `5`（数）の違いは1節では述べられず、`print("合計", 5)` の `5` に引用符が無い理由は説明されない（3節の「数ではなく文字の `5`」で初めて出る）。
  案: 1節で「呼ぶ」に一言（「書いて動かす」）を添える。`"5"` と `5` の違いは3節の前に1文あるとよい。
- 補足（学習者の引っかかりではなく食い違い）: `taught.mjs` の出力は `print(5)` と `print()`（空の行）をこの節の内容として挙げているが、`01-print.mdx` の本文・例・課題のどこにも無い。

### L7（2節 variable）困る例と最初の `<Run>` が合わない
- 場所: 困る例「値段と、送料50円を足した額と、20円引きの額を、3行で表示する」／ `<Run>` は2行（150, 80）だけ
  なぜ: 「3行」のはずが、例は `price` そのものを表示せず2行。Compare の goodCode は3行で合う。▶ を押した結果が文と食い違い、一瞬「何か書き忘れたか」と思う。
  案: 困る例を「2行」にするか、Run に `print(price)` を足す。

### L8（4節 input）「文字列に数は足せない」が、見せられないまま断定される
- 場所: 困る例「`print(x + 1)` と書くと…エラーで止まります…文字列に数は足せないため」
  なぜ: エラーを見せる `<Run>` が無く、「文字列に数は足せない」は5節で `+` を教える前に出る。学習者は信じて進めるが、なぜ足せないのかは分からない。
  案: 3節の c1 のように、エラーを学習者が自分で見られるようにするか、5節へ送る。

### L9（6節 scores）説明の最初の段落は、これまでの節の繰り返し
- 場所: 「1行目と2行目は変数（第1章2節）です…3行目は `+` で…4行目はf文字列（第1章5節）です…入力欄から点数を受け取るときは `input()`（第1章3節）と `int()`（第1章4節）を使います。」
  なぜ: 知っていることの列挙。学習者が新しく得るものは無い。次の段落（教科が増えたら／平均は割る）だけが、この節の新しい情報。
  案: 復習は2行に縮めるか、「忘れたら戻る」の案内だけにする。
