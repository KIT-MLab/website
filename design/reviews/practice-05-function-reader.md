# 練習問題集 第5章（関数）読み手の報告

対象: `practice/05-function/def.mdx` `return.mdx` `args.mdx`（計15問）。
読み方: 第5章の節（1〜4節）と、それまでに教えたことだけを持つ1年生として読んだ。各問を、模範解答を見る前に自分で解き、そのあと模範解答と全テストで比べた。
別の書き方（`print` のまま、`return` を `if` の中だけに書く、`*=` の繰り返し、`amount * bonus // 100` の順）は、手元の小さなスクリプトで動かして確かめた。
結論: 学習者が進めなくなる所は無し。迷う所が数か所ある。

## R1 args-5「買い物のポイント」: 「2倍」を、端数を切り捨てる前にかけると落ちる

- 何で止まるか: 問題文は「100円ごとに1ポイント。100円に満たない分はポイントにならない。ただし、5の倍数の日は、ポイントが2倍」。ここから `amount * 2 // 100` と書く人が出る。
  - 「100円ごと」を割り算にするとき、「金額を2倍してから100で割る」と読める。
  - 25日に1299円で、正しい答えは `1299 // 100 * 2` の24。`1299 * 2 // 100` は25になり、テスト3で落ちる。
  - 落ちた理由は、出力例（ケース1）の日付が5・12で、5の日は2000円（切り捨ての差が出ない金額）だから分からない。学習者には「どの行が違うのか」が見えない。
- 案: 問題文の2文目を次のように直す。「ただし、日付が5の倍数の日は、100円ごとにたまったポイントを2倍にします。」ここで「100円ごとにたまったポイントを数えてから2倍にする」と順番が決まる。

## R2 args-4「日帰り旅行の費用」: `meals=meals` を、学習者は初めて見る

- 何で止まるか: 4節の例で名前を書いて渡すのは、定数だけ（`rate=0.2`、`shipping=500`）。この問題では、読み取った変数を名前付きで渡すので、`meals=` の右に変数を書く形になる。
  - 変数の名前を `meals` にすると、`meals=meals` になる。「左は関数の引数の名前、右は読み取った値」と分からず、止まる人が出る。
  - 4節の説明に、変数を渡す例は無い。ヒントも「最後の `print` の呼び出しを見てください」だけ。
- 案: ヒントを次のように変える。「`meals=` の左は関数の引数の名前、右には読み取った食事の回数を入れた変数を書きます。第5章4節の最後の `print` の呼び出しを見てください。」

## R3 args-3「コピー代」: ★2 だが、args-1 より易しい。ヒントは、問題がもう決めていることを言っている

- 自分で考えること: デフォルト値を2つ書き、掛けるだけ。1個。`**` の選択や `dim` の意味を考える args-1（★1）より軽い。
- ヒント「デフォルト値のある引数は、…より後ろに書きます」は、順番を問題文が `copy_cost(pages, copies, price)` と先に決めているので、使わない。指す所（3節の最後の説明）は合っている。
- 案: ★はそのまま ★1 に下げるか、問題を「`copies` だけ名前で渡す呼び出しが要る」形にするか。下げるなら、args の ★1 が3問並ぶ。ヒントは、順番の説明を、「渡さなかった引数がどう使われるか」に替える。

## R4 return-5「数字占い」: ヒント1が、考えどころをそのまま言っている

- ヒント1「10で割った余りは1の位の数、10で割った商は1の位を取り除いた数です」で、★3 の中心の発想が、問いの前に答えとして出る。
  - 残るのは、`while` と足し込みの形だけ。
- ヒント2「数がなくなるまで繰り返す」は、「なくなる」が何を指すか決まらない。`n` が0になるまでのこと。
- 案:
  - ヒント1を、「`1234` の1の位の4は、10で割ったどちらの計算で取り出せるでしょう。」の問いにする（答えは言わない）。
  - ヒント2を、「`n` が0より大きい間繰り返す書き方は、第4章5節を見てください。」にする。

## R5 return-4「駐車場の料金」: 関数の中の `return`（if の中）を初めて書く

- 2節は `return` を1か所にしか書かない。`if` の分かれ目ごとに `return` を書く形は、節の例にも課題にも無い。
- `if minutes > 30: return …` だけを書くと、20分のとき `None` が返る（動かして確認した）。なぜ `None` か、学習者には分からない。
- 案: ヒントに「どちらの場合にも、`return` が実行されるように書きます」を足す。

## R6 return-3「並べ方の数」: `return` を繰り返しの中に書く人が出る（軽い）

- `return result` を `for` の中に書くと、4人でも1が返る。
- 「関数の中の繰り返しのあとで `return`」も、2節に例が無い。
- 案: ヒントの最後に「`return` は、繰り返しがすべて終わってから書きます」を足す（`return` の位置がインデントで決まるので、字下げの高さも言うと良い）。

## R7 同じ手順の問題・節の課題と近い問題（採否は書き手に任せる）

- return-1「上映時間を分にする」と return-2「おつりの計算」: どちらも、2つの数を式にして `return` するだけ。手順が同じで、片方を消しても確かめられることは変わらない。
- args-1（デフォルト値1つ、返す）と args-2（デフォルト値1つ、返す）は、手順が同じ。3節の課題 `judge` も同じ形。args-3 と args-4 は、掛けたり足したりして返すだけで、デフォルト値を2つ持つ形が重なる。
- def-3「電車の運賃表」は、1節の課題 `python-05-def-b1`（人数のあとに、1回ごとに関数を呼ぶ）と、手順がほぼ同じ。違うのは、読む値が1人ぶん2つか、1回ぶん1つかだけ。
- def-1「文房具の代金」は、1節の例（`show_average`）に、`print` の文面と式を入れ替えただけで解ける。
- 題材: 金額が出る問題が15問中7問（代金、運賃、おつり、駐車場、コピー代、旅行の費用、ポイント）。args は5問中3問がお金。

## R8 def-5「植物の成長記録」: ★3 の難しさがヒント1に乗っている

- 「1つ前の高さは、繰り返しのたびに入れ直す変数に持っておきます」で、中心の発想が言ってある。
- ヒントを見ずに解くと、出力例の数列（10→13→15→15）と「前の週の高さ」の説明だけから、最後に `previous = height` と入れ直す手順を思いつく必要がある。★3 の段差は、これ1つ。
- 案: ヒント1を、「週ごとの伸びは、いまの高さから、1つ前の週の高さを引いて求めます。1週目の『1つ前』は何の高さでしょう。」に分け、変数の話は2つ目のヒントに回す。

## 日本語・言葉

- 「定義してください」（def、args-5）と「書いてください」（return、args-1〜4）が混ざる。どちらも通じる。意味は変わらないので直さなくてよい。
- 「関数を定義して」「呼び出して」「返して」は、節の言葉（定義・呼び出す・返ってきた値）と合っている。
- args-1 の `dim` は、学習者の知らない語。Input の欄に「掛け合わせる回数」とあるので進めるが、`dim` が何の略かは分からない。
- def-2「ふちを1周した長さ」は、長方形の周のこと。小学校の語なので通じる。「周の長さ」でもよいが、直さなくてよい。

## 見つからなかったもの

- 「入力例・出力例・テストの入力」が画面に出ることを前提に、`stdout` 問題の手順（読む、関数を呼ぶ）は、5問とも問題文で分かる。
- 節との対応（ヒントが指す節・コードの位置）は全て合っていた（例: args-5 ヒント2「最初のコードの4行目と5行目」、args-4 ヒント「最後の `print`」）。
- 返り値の型は、return と args-1〜4 の Output が全て書いてあり、`/` と `//` の取り違えが起きる問題は無い。
- 引数の順番は、全問で問題文が関数の形を先に書いているので、取り違える余地が無い。
