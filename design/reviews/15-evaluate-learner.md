## 01-split（学習用とテスト用に分ける）

### 止まる
- **L1** 場所: python-15-split-m1「`17.0`と`28.7`が表示されるように、6行目の`default_rng`の引数を書き換えてください。」
  なぜ: 種と出力の間には考えて分かる関係が無く、答えの `9` は試すしかない。問題文にもヒントにも「0から順に試す」とは書かれていないので、何か計算で求める方法があると思って止まる。種0〜29を動かすと、`17.0 28.7` になるのは種9だけ（0〜1999でも9だけ）。種4は `17.0 27.3`、種0は `17.1 27.1` と近い値が多く、試していても迷う。
  案: 問題文かヒントに「0から順に1つずつ試す」と書く（または、種を選ぶ問題をやめて、種を書き換えたら出力がどう変わるかを答える問題に変える）。

### 引っかかる
- **L2** 場所: 説明「学習用の損失は`15.4`ですが、テスト用の損失は`34.1`まで上がります。」と、m1 で種を試す流れ
  なぜ: m1 で種を0から試すと、種2は `22.6 5.1`、種7は `22.2 6.6` と、テスト用のほうがずっと小さくなる（種24は `22.8 4.2`）。この節は「テスト用では損失が上がる」としか言っていないので、学習者は自分の結果が間違っているのか、と迷う。テスト用が6人しかなく、誰が入るかで大きく動くことはどこにも書かれていない。
  案: 「テスト用が6人だけなので、分け方によってはテスト用のほうが小さく出ることもある」と一文足す。
- **L3** 場所: 「6行目の`np.random.default_rng(3)`は、種3の乱数の生成器を作ります。」
  なぜ: 「乱数」「生成器」「種」がここで初めて出るが、どれも説明が無い（語の一覧にも無い）。次の文の「種が同じなら、並びは毎回同じ」で種の働きは何となく分かるが、乱数・生成器は分からないまま通る。
  案: 「乱数＝毎回ばらばらに出る数」「種＝その出方を決める数」程度の説明を足す。
- **L4** 場所: 「11行目の`hours[train_idx]`のように、配列をインデックスにして複数の値をまとめて取り出せます。」
  なぜ: `idx` や `train_idx` の中身が一度も表示されないので、「インデックスの配列」で何が起きているかを目で確かめられない。小さな例（`x[np.array([3, 0])]` → `[40 10]` のような）も本文に無い。
  案: `print(idx)` を1行足すか、小さな配列での例を1つ見せる。

## 02-overfit（学習用に合わせすぎる）

### 止まる
- **L5** 場所: python-15-overfit-b1「次数と学習用の損失、テスト用の損失を、この順で1行に並べて表示してください。」
  なぜ: 丸めの指示が無い。そのまま表示すると `1 25.053112033195017 19.9...` のようになり、模範解答（`round(…, 1)`）の `1 25.1 19.9` と合わずにテストに落ちる。問題文だけからは、小数第1位に丸めることが分からない。
  案: 「損失はどちらも`round()`で小数第1位まで丸めて」と問題文に足す。

### 引っかかる
- **L6** 場所: 困る例「勉強時間の2乗や3乗を特徴量として足すほど」と、例の `np.polyfit(…, degree)`
  なぜ: 困る例は「特徴量を足す」と言うが、例のコードには特徴量を足す行が無く、`polyfit` に次数を渡すだけ。説明の「次数3なら、勉強時間の1乗・2乗・3乗を使った曲線」で何とかつながるが、第13章4節の「入力を並べて X を作る」とどう同じなのかは分からないまま通る。
  案: 困る例を「曲線の次数を上げるほど」と例のコードに合わせた言い方にする。
- **L7** 場所: 「次数5の曲線は、学習用の6人をちょうど通るので」
  なぜ: なぜ次数5なら6人を通せるのかが書かれていない（数IIの範囲でも、5次式が6点を通せることは習っていない）。「そういうものだ」と受け取るしかない。
  案: 「次数5の曲線は係数が6つあるので、6人ぶんの点をちょうど通るように決められる」と一言足す。
- **L8** 場所: 説明「テスト用の損失は`19.9`→`56.8`→`723.0`と上がります。」
  なぜ: m1 で次数を試す学習者が6以上を入れると、テスト用の損失は 592.3（次数6）→489.0（7）→410.1（8）と下がっていき、「次数を上げるほど上がる」と食い違う。次数6以上では `RankWarning: Polyfit may be poorly conditioned` も出る（実行して確かめた。0〜5では出ない）。軽い。
  案: m1 の問題文に「次数は1から5の中で」と範囲を書く。

無し

## 04-confusion（4つの場合を数える）

### 止まる
- **L12** 場所: 例の8〜11行目 `hit = np.sum((pred == 1) & (passed == 1))` など
  なぜ: `&` がここで初めて出るが、何をする記号か本文のどこにも書かれていない（第3章で習ったのは `and`）。学習者が自分で `and` と書くと `ValueError: The truth value of an array with more than one element is ambiguous…` が出て止まる（実行して確かめた）。また、真偽の配列を `np.sum` すると True の個数になることも書かれていない（第3節は `.mean()` だけ）。b1 はヒントどおり8〜11行目を写せば通るので、分からないまま通る。
  案: 「配列どうしで『両方成り立つ』を調べるときは `and` ではなく `&` を使う」「真偽の配列の合計は True の個数」の2つを説明に足す。

### 引っかかる
- **L13** 場所: python-15-confusion-m1 のヒント「pred_aの一部を0から1に変えると、見逃しが減り、空振りが増えます。」
  なぜ: 求める答えは「見逃しが2人のまま、空振りが1人」なので、見逃しは減らない。ヒントどおり見逃しを減らそうとして、合格の人（先頭の3人）の0を1に変えると `0.875 / 2 1 0 5` 方向に動き、目標から離れる。ヒントが問題文と食い違っている。
  案: ヒントを「実際は不合格の人（4〜8人目）の予想を1つ1に変えると、空振りが1人増えます」に直す。
- **L14** 場所: 題「4つの場合を数える（混同行列）」
  なぜ: 「混同行列」という語が本文に一度も出てこない。出力は4つの数が1行に並ぶだけで、「行列」と呼ぶ理由（2行2列の表になること）も分からない。
  案: 4つの数を2×2の表に並べた形を見せ、「これを混同行列と呼ぶ」と一文足す。

無し

## 章を通して

- テスト用が6人と少ないため、種によって結果が大きく動く（L2・L8・L18）。章のどこにもそのことが書かれていないので、課題で種や次数を試した学習者が、本文の言い切りと違う結果に出会う。
- 「乱数」「種」（L3）、配列どうしの `==`（L9）、`&` と真偽の合計（L12）が説明なしに出る。いちばん重いのは `&`。
