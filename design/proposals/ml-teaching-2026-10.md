- 予定に無い節に頼る前半の節（13.5・14.2・14.4 など）を外し、学習の2通り・分けて測る理由・評価の仕方の違い・数を当てるか種類を当てるかの見分け方を、タイタニックの題材で教える回に替える。
- **良い点**: 前半と後半が1本の話になる。1月の穴（U17・U18）も前半で埋まる。
- **悪い点**: 前半の5〜6回ぶんを作り直す。「第12〜15章の一部の節を前半で使う」という今の組み方を変えることになる。

### 推す組み合わせ

**A を 10/27 に入れ、B（頭の1文と終わりの問い）は 10/13 から始めます。C は 11/10 までに決める別の分かれ道（分かれ道4）にします。**

理由:
- 難しいのは計算やコードではなく「評価」と「人が決めること」だ、と Lavesson・Sulmont らが報告しています【資料】。
- そうしたことは、一度の講義より何度も出会う方が身に付くと考えます（B）【推測】。
- それでも一度は全体を並べる場があった方が、代表が準備しやすいです（A）【推測】。

### コードと一緒か、概念中心か（区間ごとの推し）

| 区間 | 主役 | 集まりでのコードの扱い |
|---|---|---|
| T1〜T4 | 概念（体験して名前を付ける） | 「▶ の前に結果を予想 → 数を変えて確かめる」。作る演習は1つだけ集まりに残すか、家で任意にする（分かれ道3） |
| 地図の回 | 概念 | ほぼ無し |
| pandas・scikit-learn | コード | 写さずに書けるまで。条件や関数を書く力はここでも要る |
| Kaggle・1月 | 判断（何を変えるか・なぜか） | 1行ずつの差し替え |

「まず提出してから学ぶ」型の fast.ai は、コードを1年ほど書いた人を前提にしています【資料】。今のメンバーには、12/1 の Kaggle 1 まで待つ今の順番が合っています。

## 5. タイタニックが「お遊び」に見える件への手当て

1. **節の頭に「今日分かってほしいこと」を1文で書き、代表が最初に読み上げる。** 文は第3節の目標をそのまま使います。今は T1 以外、本文の要点がコードの組み立てです（T2 は【確認】、ほかは【監査】）。
2. **意味を言葉にする段を、最後の7分の頭に移す。** 時間が押しても消えないようにします。T2 では、運営メモにある「なぜ下がった？」の段を本文にも1文書きます。
3. **終わりに確かめの問いを1つ**（第3節）。詰まったときの手がかりを運営メモに書いておきます（例「訓練データとテストデータ、どちらで測った？」）。
4. **予想ボードの答え合わせのあとに「この数から分かること」を1文。**
   - T2: 少ない人数の話は**足しません**。T2 にはすでに if と for・規則・正解率・ランキング・Kaggle の話が詰まっています。
   - T3: 「先週の20人では 85%、891人では 78.7%。人数が少ないと1人で大きく動く。10人だと1人で10%」を、目の前の数で1回だけ言います。
   - T4: 「女性なら生存」が 0.8 → 0.9 と上がる点には、運営メモに問答を1つ用意します。「T3 の『高めに出る』は、訓練データを見て数を選んだときの話。『女性なら生存』はこの40人を見て選んだ規則ではないので、高めに出る理由が無い。10人だと1人で10%動くので、上がることもある」。または、比べる相手を「全員亡くなった」に替える案もあります。
5. **「モデル」の言葉は 10/20 に一度だけ結ぶ。** T2 では「この規則は、だれが使っても同じ答えになる手順になっている」とだけ言い、名前は付けません。12.1 では、モデルを「入力から予測を返す関数」として教えるからです。10/20 の T4 の終わりか運営メモに、対応表を置きます。

   | 後半（タイタニック） | 前半（第12章） |
   |---|---|
   | 規則 | モデル |
   | 境目の年齢 | パラメータ |
   | 正解率（大きいほど良い） | 損失（小さいほど良い） |
   | 全部試していちばん良いものを選ぶ | 学習（11/17 の勾配降下法は別の選び方） |

6. **T3 の「手で探す」段**: 「3分で、手でいちばん当たる境目を探す。だれがいちばん高いか」の小さな競争にします。答え（17歳）は先に見せません。そのあと全部試すコードで「手でやったことを for がやった」と見せます。Google の講座の「手で動かす → 自動で探す」の2段です【資料】。
7. **T3 の「学習したのに人の規則より弱い」**: 年齢だけで当てたことを1文で言います。数は T3 と同じ人で比べます。批評での計算では、女性なら生存は訓練 0.833・テスト 0.7、年齢の規則は 0.733・0.6 です。書く前に計算し直します。「どの列を使うかは人が決めた。11/17 の決定木は列も含めて探し、性別を選ぶ」と、scikit-learn 2 につなぎます。
8. **言葉をそろえる**: T3・T4 の運営メモの「学習用・テスト用」を「訓練データ・テストデータ」に。
9. **台本を1か所に**: 頭の1文・終わりの問い・詰まったときの手がかりを、運営メモの最初の段にまとめます。代表が当日それだけ見ればよい形にします。

## 8. 今すぐできること、あとでよいこと

教材を直すときは `design/AUTHORING.md` の手順（設計メモ → 書き手 → 機械の検査 → 読み手2人 → 採否）を通します。手間が大きいので、**運営メモだけで済むもの（軽い）**と**本文やコードを変えるもの（手順を通す）**に分けます。

### 今夜（10/6 の T2）。口頭だけ、ファイルは直さない
- 運営メモの進め方4（「なぜ下がった？」）は**今のままやる**。時間が押しても飛ばさない。
- 新しく足すのは1文だけ: 「この規則は、だれが使っても同じ答えになる手順になっている。答えはサーバだけが持っていて、見ていない20人にも同じように当てはめられた」。
- ランキングの画面を残す（▼ の行を T3・T4 で見せるため。「出した規則を消す」は押さない）。

### 10/13（T3）までに
軽い（運営メモ）:
1. 頭の1文と、終わりの確かめの問い（体重の例）
2. T2 のランキングの呼び戻し（2通りの台本）
3. 「学習用・テスト用」を「訓練データ・テストデータ」に（T3）

手順を通す（間に合わなければ 10/20 以降に回してよい）:
5. 本文に「年齢だけなので女性の規則より弱い。列を選んだのは人」の1文（数は計算し直す）
6. 手で境目を探す短いコード

### 10/20（T4 と前半）までに
軽い: T4 の運営メモの言葉の統一。0.8 → 0.9 の問答。ランキングの呼び戻し。対応表（第5節の5）。

### あとでよいこと
- **10/27**: 地図の回（または 11/10 にずらす）。
- **11/10 まで**: 分かれ道4。前半の各節が予定に無い節に頼っていないかの一覧を作る（今わかっているのは 12.1・13.3・13.5・14.2・14.4）。

- **2〜3月**: 限界を言う練習（U19）を、学内発表の筋に入れる。

### 「作る演習を家で」の置き場所
`plan.ts` の復習の欄（`after`）は、練習問題集の章と今週の欄しか持てません【監査】。節の中の演習を指すには、型と今週のページを変える仕事になります。**本文と運営メモで「家で」と言うだけにするか、型に欄を足すか**も選んでください（推しは前者。軽いので）。メンバーが家の課題をどれだけやっているかは提案者には分かりません。代表の見立てを教えてください。

- 1月の月例コンペの形（数か種類か・評価の仕方）。2026年3月の回は AUC でした【資料】。
- 書き直しの量は、どれも行数からの見積もりです。
- Kaggle Learn と How Models Work の本文、fast.ai の Titanic の表計算の中身は読めていません。
