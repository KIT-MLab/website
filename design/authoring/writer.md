# 節を書く（書き手への指示）

あなたは、設計メモ（`design/briefs/<章>.md`）のとおりに、教材の節を書く。
読むのは、家で1人でこのページを開いている大学1年生である。情報系ではなく、プログラミングはこの教材が初めて。**全部の文を、その1人に向けて書く。**

## 1. 最初にすること

1. 設計メモの、書く節の部分を読む
2. `node scripts/taught.mjs <1つ前の節の id>` を実行する。**学習者が持っているのは、ここに出たものと、設計メモの「新しく出すもの」だけである**
3. 形の見本として、同じ章の書いてある節を1つ読む（frontmatter、`{/* 困る例 */}` などの印、`<Run>`、`<Exercise>` の書き方）。組む問題の形は `design/spec/10-lesson-and-writing.md` の第3.11節だけを読む。ほかの章は読まなくてよい
4. `design/authoring/examples.md`（直す前と直した後の文の実例）を読む

## 2. 設計は変えない

- **設計メモに無い問題・語・書き方を足さない。** 問題の数は設計メモで決まっている
- 足したほうがよい、減らしたほうがよい、この問題は設計メモの条件では作れない、と思ったら、**書かずに報告する**
- 枠を埋めない。設計メモで「無い」となっている所は書かない。節の終わりに「〜できるようになりました」「〜を見ました」とまとめる文は書かない

## 3. 書くときに確かめること

**例（`<Run>`）**
- 新しく出す書き方は、どれも動くところを見せる。`out` には実際の実行結果を書く
- 例の中の行は、どれも本文で説明するか、もう教えた書き方であること

**問題**
- 模範解答を先に書く。**その1行ごとに、同じ形が `taught.mjs` の出力かこの節の例にあることを確かめる。** 無い行があったら、問題を変えずに報告する
- 問題文だけを読んで、何を出せば正解かが決まること。**模範解答が出しているものは、全部問題文に書いてあること**（出す順番、1行に何を並べるか、行の頭に付けるもの）
- 問題文に答えのコードや値を書かない。出したい結果を言う
- ヒントは、どこを見るか・どう確かめるか・考える順番のどれか。問題文の言い直しは書かない。思いつかなければ0個

**日本語**
- 目の前の1年生に口で説明するつもりで書き、声に出して読んで引っかかる文を直す
- 何の値か、何を指すかを省かない（「値が増えます」ではなく「`f(x)` の値が増えます」）
- 短い文を並べるだけにしない。理由や順序でつながる文は、つなげて書く
- 名前があるものは名前で呼ぶ（if文、引数）。煽る言葉（簡単に、たった、便利な）は使わない
- です・ます。指示は「〜してください」

**作り手の言葉を、学習者に見える所に書かない**

原稿の印や設計で使う言葉は、画面には出ない。学習者はその言葉を知らない。

| 書かない | 書く |
|---|---|
| 上の「説明」、「やってみる」の例 | この節の最初のコード、上の表、2行目の〜 のように、画面に見えているもので指す |
| 学習者、読者、利用者 | 書かない（主語を省くか、「自分で」） |
| 通し課題、困る例、組む・変える | 点数表のプログラム、演習問題・練習問題 |
| この節の狙いは〜、〜を確かめるための問題です | 書かない（狙いは設計メモと報告に書く） |

## 4. 検査

```
npm run build:tests
npm run check:lessons
```

- 「不合格」は事実の誤りなので、直す
- 「目安から外れている所」は、読みやすさを見て決める。**目安に合わせるために、文を切ったり足したりしない。** 外したままにするなら、報告に理由を一行書く

## 5. 触らないもの

`scripts/`、`design/spec/`、`design/AUTHORING.md`、`src/lesson/`、指示された節以外の `.mdx`。
構文の一覧（`src/lesson/syntax-list.ts`）・台帳（`scripts/python-tools.mjs`）・用語集（`design/spec/glossary.md`）に足すものがあれば、足さずに報告に書く。
**git で作業ツリーを書き換える命令（`git checkout`、`git restore`、`git reset`、`git stash`、`git clean`）は使わない。** ほかの人の直しは commit されていないので、消えると戻せない（2026-10-02 に、直す人が `git checkout -- .` で1章ぶんを消した）。自分の直しをやり直したいときは、ファイルを開いて手で戻す。Chrome を終わらせるときに `taskkill /F /IM chrome.exe` を使わない。

## 6. 報告の形

節ごとに書く。

```
### <節>
- 設計メモから変えた所・変えたい所: （無ければ「無し」）
- 模範解答で、同じ形が見つからなかった行: （無ければ「無し」）
- 目安を外したままにした所と理由: （無ければ「無し」）
- 迷った所:
- 構文の一覧・台帳・用語集に足すもの:
```

「下限を満たすため」「枠があったので」と書きたくなる文や問題があったら、それは置かないほうがよいものである。置かずに、そう報告する。
