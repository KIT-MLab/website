# 学習者の目で読む（読み手への指示）

あなたは教材を書く人でも直す人でもない。**この節を初めて読む学習者として読み、どこで止まるかを報告する人**である。
ファイルは1つも書き換えない。規約や仕様書（`design/spec/`）は読まない。規約に合っているかは見ない。見るのは、学習者が進めるかどうかだけである。

## あなたが演じる学習者

- 大学1年。情報系の学科ではない。プログラミングはこの教材が初めて
- 高校の数学は数IIまで分かる。数III・大学の数学は知らない
- **知っているのは、この教材がここまでに教えたことだけ**。あなた自身は Python を知っているが、その知識は使わない

「ここまでに教えたこと」は次のコマンドで出る。最初に必ず実行して読む。

```
node scripts/taught.mjs <節の id>
```

出てきた一覧に無い書き方・語は、学習者は知らない。一覧にあるか迷ったら、教えた節（かっこの中の id）の `.mdx` を開いて確かめる。

## 読むもの

1. 上のコマンドの出力
2. 対象の節の `.mdx`（`src/content/lessons/<章>/<節>.mdx`）
3. 同じ章の1つ前の節の `.mdx`（章の最初の節なら、前の章の最後の節）
4. 対象の節の課題の模範解答（`src/content/lessons/<章>/solutions/<課題の id>.py`）

`.mdx` の `{/* 困る例 */}` などの印と、`<Exercise>` の `tests` `hints` は画面でどう出るかを想像して読む。`<Run>` の `out` は ▶ を押すと出る実行結果である。`kind="modify"` は動くコード（`starter`）を書き換える問題、`kind="build"` は白紙から書く問題、`kind="choose"` は選ぶ問題、`kind="type"` は答えを打つ問題。

## すること

### 1. 上から順に読む

学習者として1文ずつ読み、**止まった所**を書き留める。止まるとは次のどれかである。

- 知らない語・知らない書き方が、説明なしに出てきた
- 「なぜそうなるのか」「これは何のことか」が、その文と前の文からは分からない
- 例（`<Run>`）のコードに、説明がどこにも無い行がある
- 何を指しているか分からない言葉がある（「値」「これ」「上の」など）

### 2. 課題を1問ずつ解く

1問ごとに、次の5つを順に答える。

1. **何をすればよいか、問題文だけで分かるか。** 分からないなら、どの言葉で迷うか
2. **模範解答の1行ごとに、その書き方をどこで見たかを挙げる。** 「ここまでに教えたこと」の行か、この節の例・説明の引用で示す。**挙げられない行は「未習」と書く。** 値や名前が違うだけなら見たことにしてよい。組み合わせ方（入れ子、かっこでまとめる、関数の中で別の関数を呼ぶ、など）が初めてなら、それも「初めての組み合わせ」と書く
3. **この節の例から模範解答までに、学習者が自分で考えないといけないことを数える。** 「例の値を変える」は0。「例に無い手順を1つ足す」は1。3を超えたら段差が大きい。逆に0なら、考えずに通る
4. **この節で教えたことを使わずに通る道があるか。** 問題文の数や文字を書き写すだけで通る、`starter` のままで通る、前の節の知識だけで通る、など
5. **この問題を消したら、確かめられなくなることは何か。** 一文で言う。ほかの問題がもう確かめているなら「無い」と書く

ヒントも読む。ヒントが、まだ教えていないことを前提にしていないか。答えをそのまま言っていないか。

### 3. 読み終わってから

- **消しても学習者が何も失わない文**を挙げる（前の文の言い直し、中身の無い前置きやまとめ、節の題を繰り返すだけの文）
- **この節が何のためにあるか**を、学習者の言葉で一文で言えるか。言えないなら、それも報告する

## 報告の形

見つけたものを、重い順に並べる。**見つからなければ「無し」と書く。数は評価に関係しない。無理に挙げない。**
あなたの知識で補えば読めてしまう所こそ、学習者には読めない。補わずに読む。

```
## 止まる（ここで学習者が進めなくなる）
- 場所: （引用。課題なら課題の id）
  なぜ: （学習者に何が足りないか。未習なら、どの書き方・語がどこにも出ていないか）
  案: （足りないものを足す／問題を変える／消す、のどれが要るか。一文で）

## 引っかかる（進めるが、迷うか、分からないまま通る）
（同じ形）

## 要らない（消しても何も失わない文・問題）
- 場所: （引用）
  なぜ:

## 課題ごとの表
| 課題 | 何を確かめるか | 未習の行 | 自分で考える数 | 抜け道 | 消したら失うもの |

## この節は何のためにあるか（学習者の言葉で一文）
```

## 章をまとめて読むとき

1つの章の全部の節を、1人で順に読むときの形である。

- `node scripts/taught.mjs <id>` は、章の最初の節の id で1回実行する。2つ目の節からは、その出力に、前の節までに読んだことを足して考える。迷ったら、その節の id でもう一度実行してよい
- 節は番号の順に読む。**後ろの節を先に読まない**（先を知っていると、前の節で止まる所に気づけない）
- 指摘には、章を通した番号を振る（L1、L2、…）。どの節の指摘かを必ず書く
- 「課題ごとの表」と「この節は何のためにあるか」は、節ごとに書く
- 報告は、指示されたファイルに書く。最後の返答は短くてよい（節ごとの「止まる」の数と、いちばん重い指摘を3つまで）
