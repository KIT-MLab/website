# 練習問題集を書く（書き手への指示）

練習問題集の1つの章ぶん（話題ごとに1つの `.mdx`）を書く。練習問題集は、教材の節を読んだ人が、その話題を**自分の手で書いて練習する場所**である。説明は書かない（説明は教材の節が受け持つ）。

解くのは、大学1年生（情報系ではない。プログラミングはこの教材が初めて）。全部の文を、その人に向けて書く。

## 1. 最初に読むもの

1. `design/authoring/writer.md`（書くときに確かめること、作り手の言葉を書かない、検査、触らないもの）と `design/authoring/examples.md`（直す前と直した後の文の実例）
2. `design/spec/10-lesson-and-writing.md` の**第3.11節と第3.12節だけ**（組む問題の形、練習問題集の書き方）
3. `design/reviews/_cross.md`（どの書き方をどこで教えるかの決定。これに反する問題を作らない）
4. 見本: `src/content/practice/02-numbers/divmod.mdx` と、その模範解答 `src/content/practice/solutions/practice-02-divmod-*.py`
5. 書く章の、教材の節（`src/content/lessons/<章>/*.mdx`）。**全部読む。** その話題の frontmatter の `sections` に書いてある節が、その話題を教えた節である
6. `node scripts/taught.mjs <次の章の最初の節の id>`。**使ってよい書き方は、ここの「ここまでに教えた」に出たものだけ**（その章の終わりまでに教えたこと）

## 2. 1つの話題に置く問題

| ★ | 何を確かめるか | 数 |
|---|---|---|
| ★1 | その話題の書き方を、短い問題で確かめる。自分で考えることは1個 | 2問 |
| ★2 | その話題だけで組む。自分で考えることは2個 | 2問 |
| ★3 | 前の話題・前の章の書き方もまたいで、手順を自分で考える。自分で考えることは3個 | 1問 |

- ★1 → ★3 の順に並べる。**段差は★の順に上がること**（★1 が★2 より重い、のようにしない）
- 自分で考えることが4個以上になる問題は置かない。★3 でも3個まで
- 全部「組む」問題（`kind="build"`）。入力を読み、出力を表示する
- 数は上の表のとおり（1つの話題に5問）。**足したいから足す、はしない。** 5問を埋めるために、確かめることが同じ問題を並べるより、題材と数を変えて同じ書き方を練習させる（練習の数を多くするのが練習問題集の役目なので、同じ書き方を別の題材で練習させるのはよい。まったく同じ手順の問題を2つ置くのはよくない）

## 3. 問題を書くときに必ず確かめること

1. **模範解答を先に書く。** 1行ごとに、同じ形が `taught.mjs` の出力か、教えた節の例にあることを確かめる。無い形は使わない
   - 1つの式の中で `input()` を2回呼ばない。`print(int(input()) * 2)` のような3重の入れ子にしない。変数に分ける
   - 足し算と掛け算が混ざる式は、第2章4節（計算の順番）より前の章では、途中の値を変数に入れる
   - `True` `False` を変数に入れる形、`max()` `min()` `sum()` `sorted()`、リストの `[-1]` は使わない（`_cross.md`）
   - numpy の章では、入力から配列を作る形は、教えた節の例と同じ形にする（`_cross.md` と、その章の節を見る）
2. **問題文と `<Input>` `<Output>` だけを読んで、何を出せば正解かが決まること。** 模範解答が出しているもの（出す順番、1行に並べるもの、区切りの空白や記号、丸めるかどうか、別の分岐で出す文言）は、全部書く。出力例に出てこない文言は `<Output>` に書く
3. **自分で、問題文だけを見て別の書き方で解き直す。** 全部のテストケースで模範解答と同じ出力になることを、Python で動かして確かめる（`py` で動く。`python` は無い）
4. **その話題の書き方を使わないと通らないこと。** 使わない書き方が最短にならないようにする（テストケースを選ぶ）。「出したい出力をそのまま `print` に書けば通る」は、入力を読む問題でテストケースが複数あれば起きない
5. **教材の節の課題と同じ問題にしない。** 題材と数を変える。入力例まで同じ、は不可
6. 小数の誤差で末尾が揺れる出力（`0.30000000000000004`）にならない数を選ぶ。丸めるなら、丸めの境目（`.5`）に来ない数にする
7. テストケースは3つ以上。ケース1は出力例として画面に出るので、ふつうの場合を置く。境界の場合（0、同じ値、負の数、空）を1つ以上、ケース2より後ろに入れる
8. ヒントは、どこを見るか（教材の節を「第N章M節」で指す）・考える順番。問題文の言い直しや、答えの式は書かない。思いつかなければ0個
9. `name`（一覧の札の名前）は14字以内。題材が分かる名前にする（「文房具の代金」）。`title`（話題の見出し）は変えない

### 第7章だけの約束（集まりの回と合わせる。`design/spec/54-week-pace.md`）

第7章は2回の集まりに分けて教える。10/6 の回のあとに★1・★2を、10/13 の回のあとに★3を解く。

- **★1・★2**: 10/6 に教える節（`python-07-array` `python-07-agg` `python-07-select`）と第6章までで解けること。`stats` の★1・★2は1次元の配列の集計だけ、`select` の★1・★2は条件で取り出す形だけ、`array` の★1・★2は1次元の配列だけ
- **★3**: 10/13 に教える節（`python-07-slice` `python-07-shape` `python-07-stats`）の書き方（スライス、2次元の配列、軸）を使う

## 4. 題材

身の回りの、数で考えやすい場面（買い物、時間、点数、気温、歩数、本のページ）。同じ話題の5問で、題材を重ねない。教材の章の題材（点数表）は使ってよいが、5問のうち1問まで。

## 5. 検査

```
npm run build:tests
npm run check:practice
npm run report:practice
```

- 「不合格」は直す。ほかの章・ほかの話題は別の人が同時に書いているので、ほかの不合格は無視してよい（報告に一行書く）
- `report:practice` の「試せていない技能」「寄りすぎ」を見て、その章の問題の偏りを直す
- 文の長さなどの目安は、読みやすさを見て決める。目安に合わせるために文を切ったり足したりしない
- **git で作業ツリーを書き換える命令（checkout・restore・reset・stash・clean）は使わない。** commit・push もしない。開発サーバは起動しない
