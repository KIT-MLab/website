**最初の問いかけ（はじめの3分）**

- 「"女性なら生存" が学習用で外れた6人に合わせて、条件を5つ足す。学習用の正解率はいくつになると思う？」（答え: 1.0。全員当たる）
- 「そのとき、テスト用の10人では、"女性なら生存" の 0.9 より上がる？ 下がる？」（答え: 0.7 に下がる）

**答え合わせで言うこと（最後の7分）**

- 女性なら生存: 学習用 0.8、テスト用 0.9
- 条件を5つ足した `fine`: 学習用 1.0、テスト用 0.7
- テスト用で新しく外れたのは2人。42歳の2等の女性（2等の女性で42〜46歳は亡くなる、という条件のせい）と、26歳の3等の男性（3等の男性で25〜34歳は生き残る、という条件のせい）。4歳の3等の男の子は、どちらの規則でも外れる
- 演習問題2の `gap` で `fine` を測ると 0.3（1.0 − 0.7）。差が大きいほど合わせすぎを疑う
- ひとことの要点: 学習用だけを見て条件を足すと、たまたまの当たり外れまで覚えてしまう（過学習）。規則の良さはテスト用で決める

**次につなげる問い（答えは言わない。来週の pandas で確かめる）**

- 「891人の表から "3等の女性" だけを取り出して、生き残った割合を出すには、どう書けばよいと思う？」

**よく詰まるところ**

- `sex[:30] == survived[:30]` は True と False の配列。`.mean()` を付け忘れると、配列がそのまま表示される
- `[:30]` と `[30:]` の取り違え。インデックス30の人はテスト用に入る
- 演習問題2で、リストのまま `pred[:n] == survived[:n]` と書くと、配列ではなく `True` か `False` が1つだけになる。先に `np.array()` で配列にする
- 条件の範囲 `a >= 25 and a <= 34` の `and` を1つ書き忘れて、範囲にならない

{/* 説明 */}

3行目の `sex` は、女性を1、男性を0 で表しています。そのまま「女性なら生存」の予測として使えます。

8行目の `sex[:30] == survived[:30]` は、予測と答えが同じかを True と False で並べた配列です。平均を取ると True の割合、つまり正解率になります。`[:30]` が学習用の30人、`[30:]` がテスト用の10人です。

9行目は、学習用で外れた6人の年齢を、ブールインデックスで並べています。11〜22行目の `fine` は、この6人の性別・等級・年齢に合わせて、条件を5つ足した規則です。

`fine` は学習用では 1.0 当たりますが、テスト用では 0.9 から 0.7 に下がりました。学習用に合わせすぎて、新しい人に外れることを過学習（overfitting）と呼びます。条件が細かいほど、たまたまの当たり外れまで覚えてしまいます。
