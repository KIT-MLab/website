{/* 困る例 */}

配点の重みを、理系・文系の順に2行3列の表で持っているとします。そのまま `scores @ weights` と書くと、形が合わずエラーで止まります。

{/* やってみる */}

次のコードの ▶ を押してください。

<Run
  code={`import numpy as np

scores = np.array([[80, 70, 90], [60, 50, 40]])
weights = np.array([[0.3, 0.3, 0.4], [0.4, 0.2, 0.4]])
print(scores.shape, weights.shape)
print(scores @ weights.T)
print((scores @ weights.T).shape)`}
  out={`(2, 3) (2, 3)
[[81. 82.]
 [49. 50.]]
(2, 2)`}
/>

{/* 説明 */}

5行目で形を確かめると、`scores` は `(2, 3)`、`weights` も `(2, 3)` です。行列の積 `(n, k) @ (k, m)` は、左の列の数と右の行の数がそろっていないと計算できません。

6行目の `weights.T` は、第8章2節の転置です。形を `(3, 2)` に変えることで、`scores` の列の数3とそろいます。

7行目の形は `(2, 2)` になります。掛ける前に `(n, k) @ (k, m) → (n, m)` の形を言えると、エラーが出ても原因をすぐ探せます。

この形の決まりは、行と列の数がいくつであっても同じです。掛ける前に形を確かめる習慣は、あとの章でも役に立ちます。

{/* よくある間違い */}

<Mistake
  id="matmul-shape-mismatch"
  code={`import numpy as np
scores = np.array([[80, 70, 90], [60, 50, 40]])
weights = np.array([[0.3, 0.3, 0.4], [0.4, 0.2, 0.4]])
print(scores @ weights)`}
  error={`ValueError: matmul: Input operand 1 has a mismatch in its core dimension 0, with gufunc signature (n?,k),(k,m?)->(n?,m?) (size 2 is different from 3)`}
>
`scores` の列の数は3、`weights` の行の数は2です。そろっていないので、`weights.T` で形を `(3, 2)` に変えてから掛けます。
</Mistake>
