第12章4節では、パラメータが増えると、候補を全部は試せなくなることを確かめました。この節も④の学習の話で、全部を試す代わりに、いまの値から、損失が小さくなる向きへ少しずつ動かしていく方法を見ます。どちらへ、どれだけ動かしていけば、値がいちばん小さくなる所にたどり着けるでしょうか。

{/* 困る例 */}

どちらへ動かすかは、少しだけ動かしてみれば分かります。`(x - 3) ** 2 + 1` の値は、`x = 0` で `10`、`x = 0.1` で `9.41` なので、`x` を増やすと値が減ります。だから、`x` は増やす向きに動かします。

このように、少し動かしたときの値の増え方を、動かした幅で割った数が傾きです（くわしくは第10章1〜3節）。ここでは (9.41 − 10) ÷ 0.1 ＝ −5.9 です。傾きが負なら `x` を増やし、正なら減らせば、値が小さくなります。

ですが、どれだけ動かすか、何回動かすかは、まだ決めていません。この節では、損失の代わりにこの `(x - 3) ** 2 + 1` を使い、`x = 0` から値を小さくしていきます。

{/* やってみる */}

次のコードの ▶ を押してください。

<Run
  code={`def f(x):
    return (x - 3) ** 2 + 1

x = 0
h = 0.0001
for i in range(5):
    slope = (f(x + h) - f(x)) / h
    x = x - 0.3 * slope
    print(round(x, 4), round(f(x), 4))`}
  out={`1.8 2.4401
2.52 1.2304
2.808 1.0369
2.9232 1.0059
2.9692 1.0009`}
/>

{/* 説明 */}

5行目の `h` は、少しだけ動かす幅で、`0.0001` ととても小さくしています。7行目の `slope` は、`x` を `h` だけ増やしたときの `f(x)` の増え方を `h` で割った数で、いまの `x` での傾きです。`x = 0` では約 `-6` になります。上で `h` を `0.1` にしたときの傾きは `-5.9` でしたが、`h` を小さくするほど、本当の傾きの `-6` に近づきます。

6〜9行目は5回くり返す部分で、いまの `x` での傾きを求め、`0.3`（歩幅）をかけて `x` から引きます。引いたあとで、そのときの `x` と `f(x)` を表示します。傾きが負のときは、引くと `x` が増え、正のときは `x` が減るので、どちらも `f(x)` が小さくなる向きに動きます。

1回目は 0 − 0.3 × (−6) で、`x` は `1.8` になります。全体図2 で名前だけ出てきた勾配降下法は、傾きに歩幅を掛けた量だけ動かす計算を、くり返すことです。ここでは、傾きと勾配は同じ数です（動かす値が2つ以上になると、傾きを並べたものを勾配と呼びます。第13章3節）。

`x` は `1.8` → `2.52` → `2.808` と、`f(x)` が最も小さくなる `x = 3` に少しずつ近づきます。動かす量は `0.3 * 勾配` なので、勾配が0に近づくほど1回に動く量も小さくなります。
