第15章3節では、正解率をベースラインと比べました。この節も全体図の5つの段階の⑤で、正解率だけでは見えない、間違いの中身を数えます。正解率が同じモデルどうしは、同じくらい良いと言えるでしょうか。

{/* 困る例 */}

同じ正解率75%の2つのモデルがあります。一方は合格する人を見逃しがちで、もう一方は不合格の人を合格と言いがちです。正解率だけでは、この違いが分かりません。

{/* やってみる */}

次のコードの ▶ を押してください。ここでも、別の8人の記録を使います。

<Run
  code={`import numpy as np

passed = np.array([1, 1, 1, 0, 0, 0, 0, 0])
pred_a = np.array([1, 0, 0, 0, 0, 0, 0, 0])
pred_b = np.array([1, 1, 1, 1, 1, 0, 0, 0])

def show_counts(pred, passed):
    hit = np.sum((pred == 1) & (passed == 1))
    miss = np.sum((pred == 0) & (passed == 1))
    false_alarm = np.sum((pred == 1) & (passed == 0))
    correct_reject = np.sum((pred == 0) & (passed == 0))
    print(hit, miss, false_alarm, correct_reject)

print((pred_a == passed).mean())
show_counts(pred_a, passed)
print((pred_b == passed).mean())
show_counts(pred_b, passed)`}
  out={`0.75
1 2 0 5
0.75
3 0 2 3`}
/>

{/* 説明 */}

8行目の`hit`は、合格と予測して実際に合格だった人数です。これを「当たり」と呼びます。9行目の`miss`は、不合格と予測したのに実際は合格だった人数で、「見逃し」と呼びます。

8〜11行目の`&`は、2つの真偽の配列を同じ位置どうしで比べ、両方が`True`の位置だけを`True`にします（第7章3節）。配列どうしには`and`は使えず、書くと`ValueError`で止まります。

`&`の両側の比べる式は、`(pred == 1)`のように`()`で囲みます。囲まないと、`and`のときと同じく`ValueError`で止まります。

小さな例で確かめます。

<Run
  code={`import numpy as np

pred = np.array([1, 0, 1, 1])
passed = np.array([1, 1, 0, 1])
print((pred == 1) & (passed == 1))
print(np.sum((pred == 1) & (passed == 1)))`}
  out={`[ True False False  True]
2`}
/>

真偽の配列を`np.sum()`に渡すと、`True`を1、`False`を0として足すので、`True`の個数になります。

残りの2つも同じ形の式で数えます。10行目の`false_alarm`は、不合格なのに合格と予測した人数で、「空振り」と呼びます。11行目の`correct_reject`は、不合格を正しく言い当てた人数で、「正しく不合格」と呼びます。

この4つの数を、予測（合格・不合格）と答え（合格・不合格）の2行2列の表に並べたものを、混同行列と呼びます。モデルAの4つの数を並べると、次の表になります。

| | 合格と予測 | 不合格と予測 |
|---|---|---|
| 実際は合格 | 当たり 1人 | 見逃し 2人 |
| 実際は不合格 | 空振り 0人 | 正しく不合格 5人 |

表の「当たり」は、合格と予測して実際も合格だった1マスだけです。正解率で数えた「予測が答えと合っていた人」は、当たりと正しく不合格を足した人数で、モデルAの正解率`0.75`は (1 + 5) ÷ 8 です。

モデルAは見逃しが2人、空振りが0人です。モデルBは見逃しが0人、空振りが2人です。どちらの間違いが困るかは、使う場面によって決まります。
